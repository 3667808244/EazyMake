# EazyMake 1.2.0-pre.2 — README 整理与高级特性触达

> 发布总览见 [`1.2.0.md`](1.2.0.md)。本计划为 1.2.0 系列第二个 pre-release 检查点（对照 1.1.0-pre.1/pre.2 的定位），置于 **dev.10**（工具链/ABI 平台标识符）落地之后、1.2.0 正式发布之前，做**用户触达 + 高级特性曝光 + ABI 警告收口**。

---

## 1 背景

README 目前只体现了 EazyMake 的**易用性**（零配置、一句话构建），高级功能没有体现、也没有快捷的了解渠道：

1. **README 只见入门不见进阶**：语义化版本约束、`ezmk.lock` 确定性构建、多平台多工具链预编译共包、第三方/私有仓库等高级特性散落在 `docs/` 技术文档里，README 只字未提——用户不知道自己"还有这些能力"。
2. **高级特性没有教程**：`tutorial/` 目前只有基础章节（01-install ~ 11-import-cmake），没有针对高级特性的上手教程，用户无法快速上手。
3. **预编译包的跨平台/跨工具链兼容性警告不足**：`package_authoring.md` §3.3 只说明了「操作系统 + 指令集架构」两个维度，没有说明**工具链族 / 工具链版本 / C++ ABI（libstdc++ CXX11、MSVC 工具集）/ MSVC 运行时（/MD vs /MT）**带来的兼容性问题。后果正如 dev.10 背景所述：开发者看到"平台和架构"就以为 GCC 11 的 `.a` 可以放心给 GCC 13 链接，结果链接器报一堆 `std::__cxx11` undefined reference，排查一整天。
4. **dev.10 已落地新能力，需要文档化**：dev.10 把预编译包平台标识符扩展为 `os-arch[-compiler][-abi]`，这是预编译语境下的**最佳实践**，本计划把它写进文档并强化警告。

本计划目标：README 重组 + 高级特性教程 + 预编译包 ABI 警告加强，让「能力可见、上手有路、坑位说透」。

### 3.3 预编译包兼容性警告加强（package_authoring.md §3.3）

现状（`docs/en/package_authoring.md:220`）：

> **⚠️ Not recommended for general use.** Precompiled packages only work on the specific platform and architecture they were built for. …

**加强为四层兼容性维度**，并把命名约定升级到 dev.10：

1. **操作系统 + 指令集架构**（现状已有）：`win-x64` ≠ `linux-x64`。
2. **编译器族**：GCC / Clang / MSVC 产物互不通用（C++ ABI 不同，C 纯 ABI 例外）。
3. **工具链版本 / 标准库 ABI**：
   - libstdc++：`_GLIBCXX_USE_CXX11_ABI`（`abi11` 新 / `abi8` 旧）→ 混用即 `std::__cxx11` undefined reference；
   - MSVC 工具集：`msvc143`（VS2022）≠ `msvc142`（VS2019）；
   - Apple Clang / clang-cl 版本号不对齐的局限。
4. **MSVC 运行时（/MD vs /MT）**：静态库的 CRT 绑定需与消费者一致，文档注明（dev.10 暂不做运行时维度标签，见 [`dev.10`](1.2.0-dev.10.md) §6）。

**并写入 dev.10 的最佳实践**：

> **最佳实践（仅限预编译包语境）**：同一包内用 `os-arch[-compiler][-abi]` 命名并排放多份工具链/ABI 产物，由 `ezmk` 按当前工具链自动选择（见 [dev.10](1.2.0-dev.10.md)）。**源码分发（`src/`）仍远优于预编译**——预编译只能在声明过的平台/工具链/ABI 上工作，源码包处处可编译。

**失败案例**（写入 §3.3 的引用块，直接采用 dev.10 背景的叙事）：

> 文档里确实写了"平台和架构"。但作为一个被 C++ ABI 炸过无数次的开发者，看到"平台和架构"时的本能反应是："哦，就是 Windows 编译的 .a 不能给 Linux 用呗"。然后依然放心地把 GCC 11 编译的 `.a` 丢进仓库，让同事用 GCC 13 去链接——链接器报了一堆 `std::__cxx11` undefined reference，排查一整天。

- **与 1.1.0-pre.1 的 README 精简不冲突**：pre.1 把开发者细节移出 README；本计划只**新增**高级特性索引（保持精简风格——一行链接 + 一句话），不重新引入技术细节。
- **dev.11（代码质量审查）**：dev.11 依赖 dev.10 完成后的代码；pre.2 以文档为主，可与 dev.11 并行推进，两者无代码/文档耦合。
- **发布门槛**：pre.2 为文档化检查点，同样受 1.1.0-pre.3 确立的发布门槛约束（清单收口 + 无破坏性变更 + 全量测试零回归）。
- **语言基准**：全项目用户文档以**中文为基准**（README_ZH / tutorial/zh / docs/zh），英文为同步翻译；本计划所有交付遵循「先中文、后英文」顺序。
- **文档单一事实源**：README 高级特性表、tutorial 12/13/14、package_authoring §3.3 三处涉及同一批特性与命名——以 package_authoring/dev.10 为命名事实源，README/教程只做引用，避免漂移。
