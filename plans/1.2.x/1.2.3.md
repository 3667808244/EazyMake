# EazyMake 1.2.3 — `ezmk example` 命令组 + 内置示例（构建期嵌入资源）

> 1.2.x 稳定线补丁。发布总览见 [`1.2.x/README.md`](README.md)。

---

## 1 背景

用户需要一个「复制即用」的示例获取通道。已评估两条路：仓库 `examples/` 目录（获取成本高、与版本漂移）与 **`ezmk example <name>` 内置命令**（装好即用、离线可用、模板随二进制同版本）——选定后者，并采用**方案B（构建期嵌入资源）**存储示例内容：仓库 `examples/` 源目录为单一事实源，构建期生成 C++ 数据嵌入二进制。

**已拍板的决策**（2026-08-17）：
1. **存储**：方案B——`examples/` 源目录 + `scripts/embed_examples.py` 构建期嵌入（对齐 `embed_locale.py` 与 `embed_logo.py` 机制）；
2. **生成位置**：`./<name>/`（与 `project new` 一致：当前目录下建同名目录）；
3. **with-packages 正常入集并在 CI 完整测试**（GitHub-hosted runner 具备完整出站网络，可 clone 官方仓库 + `pkg install`）；
4. **命令面**：`example` 作为**顶层命令组**（`ezmk example list` / `ezmk example <name>`）。

## 3 详细设计

### 3.1 命令面

```
ezmk example                    # = example list：列出可用示例（名称 + 一句话说明）
ezmk example list               # 显式列出
ezmk example <name> [--output <dir>]   # 生成到 ./<name>/（或 <dir>/<name>/）
```

- **实现**：`Command::Example`（cli.hpp 枚举新增）+ cli.cpp 子命令解析（仿 `project` 组：`parse_options(argc, argv, 3, spec, "ezmk example")`）+ main.cpp 分发到 `example::create_example()`。
- **`<name>` 未知** → fatal（i18n `example_not_found`，列出可用项）；**目标目录已存在** → fatal（同 `project new`）。
- **别名**：不加（`example` 全拼已足够短）；顶层别名表（cli.cpp）不新增。
- **i18n**：新增 `example_list_header` / `example_list_item` / `example_created` / `example_not_found` / `example_exists` 等 key（X-macro 三向一致，`check_i18n.py` 通过）。

### 3.2 方案B 存储（构建期嵌入资源）

```
examples/
├── README.md                    # 示例索引（每项：一句话 + 对应教程 + 运行方式）
├── hello/                       # 可执行：ezmk.toml + src/main.cpp
├── greeter/                     # static 库：ezmk.toml + include/greeter.hpp + src/greeter.cpp
├── with-packages/               # 依赖+版本约束：ezmk.toml([depends] fmt@^10.0) + src/main.cpp
├── with-tests/                  # Catch2 测试：ezmk.toml([test]) + src/main.cpp + test/test_main.cpp
├── with-hooks/                  # 钩子：ezmk.toml([hooks]) + src/main.cpp + script/postbuild.sh
└── cmake-interop/               # CMake 互操作：ezmk.toml + src/main.cpp + CMakeLists.txt(生成后附)
```

- **嵌入管线**：`scripts/embed_examples.py` 扫描 `examples/*/` → 生成 `src/example_data.cpp`（`{name, description, files[{path, content}]}` 表；对齐 `embed_locale.py` 与 `embed_logo.py` 的「构建期读源文件 → 生成 C++ 数据」模式）。
- **build.sh 接入**：在 locale/logo 嵌入之后调用 `embed_examples.py`（python 缺失时生成空表 stub，同现有 fallback 思路）。
- **生成文件**：`src/example_data.cpp` 加入 `.gitignore`（对齐 `src/locale_data.cpp` 的既有处理）。
- **单一事实源**：`examples/` 源文件 = 事实源（可浏览/复制/测试）；嵌入表由构建期生成，集成测试校验「嵌入表文件集合 ≡ 源目录文件集合」（防漂移）。
- **示例构建产物**：根 `.gitignore` 已覆盖 `build/`、`.ezmk/`、`*.o`——示例可在仓库内直接构建不污染 git。

### 3.3 示例内容要点（对应教程）

| 示例 | 关键内容 | 对应教程 |

### 3.4 测试与 CI

- **集成测试**（test_integration.cpp）：
  - `ezmk example` / `example list` → 输出 6 项；
  - `example hello` → 断言 `./hello/{ezmk.toml,src/main.cpp}` 内容与 `examples/hello/` 源文件一致（嵌入表 ≠ 漂移）；
  - `--output` 覆盖、目录已存在 fatal、未知示例名 fatal；
  - 对每个示例：`cd <name> && ezmk build` 通过（with-tests 另跑 `ezmk test`；with-packages 联网 `pkg install`）。
- **CI**（ci.yml）：Linux job 追加「自举验证 6 示例」步骤（`ezmk example <name>` → build/test）——GitHub runner 有完整出站网络，with-packages 正常测试（不打 `[network]` 跳过；可容忍超时标记）。
- **全量回归**：`bash build.sh test-all` 零失败（基线 775/3554）。

## 6 跨版本关注点

- **依赖 1.2.1（模板差异化）**：`greeter` 示例内容应与 1.2.1 的 static 库骨架（`include/<name>.hpp` + `src/<name>.cpp`）一致——1.2.3 在 1.2.1 落地后推进，或实现时对齐目标形态。
- **与 1.2.2（教程分类）**：教程章节尾部加「运行 `ezmk example <name>` 获取完整示例」指引；示例↔教程映射表进 `examples/README.md`。
- **GitHub runner 网络**：with-packages 在 CI 正常测试（runner 出站网络默认开启，2023-05-02 起恢复）。
- **方案B 漂移防护**：嵌入表构建期生成 + 集成测试断言「嵌入表 ≡ 源目录」，杜绝双源漂移。
- **离线可用性**：二进制内嵌示例，用户无网络也能 `ezmk example hello`（with-packages 生成后安装依赖时才需要网络）。
