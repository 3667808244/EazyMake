# EazyMake 1.2.0-dev.5 — catch2 v3 测试主程序兼容

> 本计划并入 1.2.0 正式发布版。修复 `ezmk test` 在 catch2 v3（官方仓库当前版本）下无法链接的问题。

---

## 1 背景

官方仓库（`ezmk-repo`，github/gitee 镜像）的 **catch2 3.6.0 是 v3**。v3 与 v2 的测试主程序机制不同：

- **catch2 v2**：`#define CATCH_CONFIG_MAIN` 后包含 `catch.hpp`，头文件会生成 `main`。
- **catch2 v3**：**已移除 `CATCH_CONFIG_MAIN`**（头文件里完全没有该宏），`main` 由库的 `catch_main.cpp` 提供或必须由消费方显式定义。

`ezmk test`（`src/build.cpp` `run_tests`）生成的 `test_main.cpp` 固定为：

```cpp
#define CATCH_CONFIG_MAIN
#include <catch2/catch_all.hpp>
```

在 v3 下该文件**不产生任何 `main`**，测试链接无入口点（本机表现为 mingw 报 `undefined reference to WinMain`）。这是 `ezmk test` + 官方 catch2 包链路断掉的根本原因——即使 catch2 包内容已修复（lib 有完整实现符号，见下），`ezmk test` 仍无法链接。

> **前置**：catch2 3.6.0 包内容已在 `ezmk-repo` 修复（`3b74cc1`：107 个实现 .cpp 平铺进 `src/`，`libcatch2.a` 含 106 成员 / 24939 实现符号）。本计划只修 EazyMake 侧 CLI 的测试主程序生成。

| # | 目标 | 优先级 |

## 3 详细设计

### 3.1 根因

`src/build.cpp` `run_tests` 的 test_main 生成（~line 1726-1750）：

```cpp
main_content += "#define CATCH_CONFIG_MAIN\n";
if (vendor_hpp exists) {           // v2 单头
    main_content += "#include \"catch2.hpp\"\n";
} else {                            // v3 多头
    main_content += "#include <catch2/catch_all.hpp>\n";
}
```

`CATCH_CONFIG_MAIN` 前缀对 v2/v3 **共用**，但 v3 已无此宏 → v3 分支产物无 `main`。

### 3.2 修改点（`src/build.cpp` `run_tests`）

按 v2/v3 分支分别生成：

```cpp
if (util::file_exists(vendor_hpp)) {
    // catch2 v2 单头：CATCH_CONFIG_MAIN 仍有效（行为不变）
    main_content += "#define CATCH_CONFIG_MAIN\n";
    main_content += "#include \"catch2.hpp\"\n";
} else {
    // catch2 v3 多头：CATCH_CONFIG_MAIN 已移除 → 显式 main 调 Session().run
    main_content += "#include <catch2/catch_session.hpp>\n";
    main_content += "int main(int argc, char* argv[]) {\n";
    main_content += "    return Catch::Session().run(argc, argv);\n";
    main_content += "}\n";
}
```

**已本地验证**：v3 多头路径下显式 `int main` + `Catch::Session().run()` 链接 `libcatch2.a` 成功，运行输出 `All tests passed`。

### 3.3 项目 src/main.cpp 处理（无需改动）

`run_tests` 收集 `project_objs` 时**已排除 `main.o`/`main.obj`**（line 1651-1654，"Exclude main.o (test runner provides its own main)"）。因此测试链接只有一个入口（来自 test_main 或用户测试源），不存在项目 main 与测试 main 重复定义。本计划不动此逻辑。

### 3.4 `has_user_main`（无需改动）

检测用户测试源是否自带 `int main(` / `CATCH_CONFIG_MAIN`（line 1417-1426）。若自带 main 则跳过生成 test_main，行为不变。

|------|------|
