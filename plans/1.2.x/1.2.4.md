# EazyMake 1.2.4 — 仓库文件夹包支持（repo 托管目录形式包）

> 1.2.x 稳定线补丁。发布总览见 [`1.2.x/README.md`](README.md)。

---

## 1 背景

官方仓库（`ezmk-repo`）目前**只能托管归档包**（`packages/*.tar.gz`）：repo 解析 `index.toml` 的 `file` → `archive_path`（[`repo.cpp`](../../src/repo.cpp) :343-345），按名安装固定走 `extract_archive`（[`pkg.cpp`](../../src/pkg.cpp) :1486），**无目录分支**。而 `ezmk pkg install <dir>` 的文件夹安装（dev.7，`pkg.cpp:1388` `if (fs::is_directory(input))` → `install_from_directory`）只作用于**用户直接传目录路径**，不经过仓库解析。

问题：header-only / 源码包想以「目录」形式托管在仓库（免打包、开发中包即拉即用）时，仓库机制不支持。

## 2 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | 按名安装路径支持目录包：repo 解析出的包路径为目录时，走 `install_from_directory`（复用 dev.7） | P0 |
| 2 | `index.toml` 目录包标注：`type = "dir"`（可选字段），sha256 校验语义区分（目录包无归档 hash，跳过） | P0 |
| 3 | 兼容：既有归档包零影响（目录/归档分支互斥） | P0 |
| 4 | 测试：local 仓库目录包端到端 + 归档包回归；文档 + CHANGES.md 1.2.4 | P0 |

## 3 详细设计

### 3.1 安装分支（`src/pkg.cpp`）

按名安装（`search_result.archive_path` 消费点，如 :1436-1440 / :1846 / :1908 三处统一入口）解析出路径后：

```cpp
// 1.2.4: 目录包 —— repo file 指向仓库内目录
if (fs::is_directory(archive_path)) {
    install_from_directory(archive_path, scope, assume_yes, no_lock);
    return;
}
```

- 复用 dev.7 的 `install_from_directory`（目录结构校验 + 编译/安装逻辑不变），**仅把入口从「用户手传目录」扩展到「repo 解析出的目录」**。
- 归档分支（`extract_archive`）不动，互斥。

### 3.2 index.toml 目录包标注（`src/repo.cpp` + 文档）

```toml
[[packages]]
name = "fmt"
version = "11.0.2"
type = "dir"                    # 1.2.4+：目录包（省略 = 归档包，向后兼容）
file = "packages/fmt/"          # 指向仓库内目录（git 仓库即文件夹）
# sha256 省略 —— 目录包无归档 hash
```

- **解析**：`[[packages]]` 增可选 `type` 字段（`"dir"` 或省略）；`type = "dir"` 时 `sha256` 可省略且不参与校验（归档包行为不变）。
- **路径**：`file` 指向仓库根（或 `[platform]` 前缀）下的目录；`find_package_archive` 对 dir 包返回目录路径，`file_exists` 已兼容目录（存在性检查）。
- **版本/约束/依赖解析**：与归档包完全一致，零改动。
- **local 仓库（`type = "local"`）最适用**：就地读目录、改动即时生效；git 仓库的目录包随 git 分发（克隆即得源码）。

### 3.3 边界

- **`type = "dir"` 但 `file` 指向不存在的目录**：按名安装报错（友好提示，同归档包缺失路径）。
- **`type` 省略但 `file` 指向目录**：自动走目录分支（`is_directory` 兜底），sha256 存在则跳过（目录无归档可校验）。
- **目录包不允许 `precompiled` 语义**：`install_from_directory` 本就按源码/header 处理；目录内 `lib/` 预编译产物由包内 `ezmk.toml` 声明（与归档包一致）。

## 5 兼容性

| 变更 | 影响 | 处理 |
|------|------|------|
| 按名安装加目录分支 | 归档包零影响 | `is_directory` 与归档互斥；既有索引不变 |
| `[[packages]].type = "dir"` 可选字段 | 纯新增 | 省略 = 归档包（向后兼容） |
| dir 包 sha256 跳过 | 仅 dir 包 | 归档包 sha256 校验不变 |
| 公共 API | 无破坏性变更 | index 字段纯增量；命令/配置不变 |

## 6 跨版本关注点

- **依赖 dev.7**：复用 `install_from_directory`（`validate_pkg` + `compile_package` 路径），本版只加仓库入口。
- **与 1.2.3（`ezmk example`）无耦合**：示例生成是本地模板，与仓库包机制独立。
- **官方仓库可选演进**：header-only 包可改用目录形式托管（免打包）；是否切换由仓库维护决定，本版只提供能力。
- **后续窗口**：目录包的「内容哈希/增量同步」语义（而非归档 sha256）归 2.0.0 或后续评估；本版以 `is_directory` + 可选 `type` 标注的最小实现为准。
