# EazyMake 1.2.1 — 按项目类型差异化模板生成（.cpp / .h）与默认配置补全

> 1.2.0 正式发布后的**补丁版本**。发布总览见 [`1.2.x/README.md`](README.md)。

---

## 1 背景

`ezmk project new` 目前对 `executable` / `static` / `shared` 三种类型生成**完全相同**的 `src/main.cpp`（Hello world），且从不生成任何 `.h` 头文件（[`src/project.cpp`](../../src/project.cpp) `create_project()`，唯一硬编码模板）。问题：

1. **库项目语义误导**：`static` / `shared` 库带着一个永远不会被链接使用的 `main.cpp`，用户建库后还得自己写 `include/<name>.hpp` + `src/<name>.cpp` 骨架。
2. **类型区分度为零**：三种类型唯一的差异是 `ezmk.toml` 的 `type` 字段——`--type` 参数对生成物没有任何影响，与用户直觉不符。
3. **没有头文件示范**：新项目没有「公共头文件放 `include/`、实现放 `src/`」的惯例示范，与 `[compile].include_dirs = ["include"]` 的默认配置脱节。
4. **默认配置无 `[test]` 节**：`write_default_config()` 生成的 ezmk.toml 不含 `[test]`（1.1.0-dev.6 起的测试能力），用户想跑测试得自行查文档手写配置——发现成本高。

## 2 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | `executable`：保持 `src/main.cpp`（Hello world）不变，不生成头文件 | P0 |
| 2 | `static` / `shared`：生成**库骨架** `include/<name>.hpp`（公开 API 示例）+ `src/<name>.cpp`（实现），**不生成 main.cpp** | P0 |
| 3 | `utils`：保持现状（无 C++ 代码，`utils/` 目录放 Lua 脚本） | P0 |
| 4 | 项目名净化规则：头文件名保留原名，C++ namespace 将 `-`/`.`/空格 → `_` | P1 |
| 5 | 测试：集成断言各类型生成文件集合 + 净化 + 新项目可编译；全量零回归 | P0 |
| 6 | 默认配置模板（`write_default_config()`）追加**注释掉的 `[test]` 示例节**（降低发现成本，TOML 解析零影响） | P1 |
| 7 | 文档：cli.md（模板说明）、教程 02（如涉及）、CHANGES.md 1.2.1 条目 | P1 |

## 3 详细设计

### 3.1 各类型生成物（`create_project()` 按 `project_type` 分支）

| 类型 | `src/main.cpp` | `include/<name>.hpp` | `src/<name>.cpp` | `utils/` |
|------|:---:|:---:|:---:|:---:|
| `executable` | ✅（现状 Hello world） | — | — | — |
| `static` | — | ✅ 库骨架 | ✅ 实现 | — |
| `shared` | — | ✅ 库骨架 | ✅ 实现 | — |
| `utils` | — | — | — | ✅（现状） |

> `static` 与 `shared` 生成物**完全相同**，仅 `ezmk.toml` 的 `type` 字段不同（库类型区分在配置层，模板骨架无需区分）。

### 3.2 模板内容

**`include/<name>.hpp`**（static/shared）：

```cpp
#pragma once

// <name> — 示例公共 API。
// 替换为你的库接口：头文件放 include/，实现放 src/。

namespace <ns> {

// 示例函数：返回一条问候消息。
const char* greeting();

} // namespace <ns>
```

**`src/<name>.cpp`**（static/shared）：

```cpp
#include "<name>.hpp"

namespace <ns> {

const char* greeting() {
    return "Hello from <name>!";
}

} // namespace <ns>
```

### 3.3 项目名净化规则

- **头文件/实现文件名**：保留原始项目名（`my-lib` → `include/my-lib.hpp` + `src/my-lib.cpp`）——文件系统允许连字符，无需净化。
- **C++ namespace**：将 `-`、`.`、空格替换为 `_`（`my-lib` → `namespace my_lib`），与既有宏名转换规则（config_file.md §`want` 宏转换）同思路；以字母开头的前置校验沿用 `project new` 现有的项目名合法性检查。
- **头文件保护**：用 `#pragma once`，规避 guard 宏名净化问题（与仓库内 `include/ezmk/*.gen.h` 等一致）。
- **转义**：项目名/内容写入文件时沿用 1.1.2 C5 的 TOML/内容转义经验（本项目名仅用于文件名与 namespace，无注入面，但 namespace 净化先于拼接）。

### 3.4 实施要点

- `create_project()` 中把硬编码 main.cpp 字符串抽为按类型分支：`executable` 走原路径；`static`/`shared` 走新库骨架；`utils` 不变。
- `write_default_config()`：`type` 字段逻辑不动；**追加注释掉的 `[test]` 示例节**（见 §3.5）。
- 新增内部 helper：`sanitize_namespace(name)`（`-`/`.`/空格 → `_`）。

### 3.5 默认模板的 `[test]` 注释示例节（`write_default_config()`）

在 `[depends]` 之后追加（纯 TOML 注释，解析零影响；字段与 `TestConfig` 实现一致，含 1.2.0-dev.12 新字段）：

```toml
# [test]                     # 启用项目测试：取消注释后运行 `ezmk test`
# framework = "catch2"       # "catch2" | "ezmk"（内置框架）
# dirs = ["test"]
# default_profile = "debug"  # 1.2.0-dev.12+：测试默认 profile
# include_dirs = ["test/helpers"]   # 测试专属 -I（1.2.0-dev.12+）
# link_targets = ["pthread"]        # 测试专属 -l（1.2.0-dev.12+）
```

> 刻意**不**展示已弃用的 `[test].flags`（dev.12 弃用、2.0.0 移除）——注释示例只教现代用法。

## 5 兼容性

| 变更 | 影响 | 处理 |
|------|------|------|
| static/shared 新项目不再生成 `src/main.cpp` | 仅影响**新建**项目；旧项目零变化 | 库项目本就不该有 main；README/教程同步说明 |
| executable 生成物不变 | 无 | — |
| 新增 `include/<name>.hpp` + `src/<name>.cpp` | 纯新增生成物 | 与 `include_dirs = ["include"]` 默认配置衔接 |
| 默认模板追加注释 `[test]` 节 | TOML 注释，解析零影响；仅新建项目可见 | 旧项目零变化；`test_config` 断言同步 |
| 公共 API | 无破坏性变更 | `create_project()` 签名不变，仅模板内容分支；`project new` CLI 不变 |

## 6 跨版本关注点

- **1.2.1 为 1.2.0 稳定线补丁**：独立推进，不触碰 1.2.0 已发布 API；发布门槛沿用（实现完整 + API 兼容 + 全量零回归）。
- **与 dev.3 模板 profile 无冲突**：profile 节不动；本次 `ezmk.toml` 模板仅追加注释 `[test]` 节。
- **与 1.2.3（`ezmk example`）联动**：默认模板的注释 `[test]` 节给入口，1.2.3 `with-tests` 示例给完整形态；注释字段与 `TestConfig` 实现（含 dev.12 新字段）严格一致。
- **净化规则与既有转换对齐**：namespace 净化与 `want` 宏名转换（config_file.md）同规则；`#pragma once` 规避 guard 净化。
- **库模板的编译验证**：`static`/`shared` 新项目必须 `build` 通过（库编译 + 归档），集成测试覆盖。
- **后续窗口**：如需更多模板（header-only 项目类型、C 语言模板等）归 2.0.0 或后续补丁评估，本版只做最小差异化。
