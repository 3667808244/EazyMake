# EazyMake 1.2.5 — 测试缓存签名修复（01807bb）+ 默认包格式改为源码包

> 1.2.x 稳定线补丁。发布总览见 [`1.2.x/README.md`](README.md)。

---

## 1 背景

两项动因合并为一次补丁发布：

1. **未发布的修复（commit `01807bb`，2026-08-19 已合入 main，未打 tag）**：
   - `ezmk test` 的测试源缓存**从未做编译选项签名校验**——`record.compile_options_signature` 在测试路径（Catch2 与 ezmk 框架两处）永不写入 → 每次运行都全量重编译测试源（"0 cached, 2 compiled"）。修复新增 `validate_test_cache_signature()` 两条路径统一设置，签名变化时 `record.files.clear()`——第二次 `ezmk test` 即缓存命中（"2 cached, 0 compiled"）。
   - `scripts/embed_examples.py` 未剪枝仓库内构建残留（`build/` / `.ezmk/` / `.git` 与二进制扩展名被 `os.walk` 扫入嵌入表 → UnicodeDecodeError）；`test/test_example.cpp` 的 `list_files` 同步对齐。
   - 同批 main 上未发布的祖先修复随 1.2.5 一并携带：`d7b032d`（CI 双失败修复：.gitattributes eol=lf + embed 字节精确输出 + bootstrap repo add）、`2e3bcb6`（pkg `expected_sha256` string_view 悬垂 UB 修复）。
2. **默认包格式改为源码包**：`ezmk project pack` 目前**只**产出预编译包（`include/` + `lib/` + 自动追加 `precompiled = true`，仅 static 项目、需先构建、产物平台/工具链/ABI 绑定）——与包生态既定哲学相悖：`package_authoring` 明确「**源码包在任何平台都能编译**，预编译是**用可移植性换安装速度**的显式选择，优先源码包」。本版把默认改为**源码包**（平台无关、消费者侧编译），旧预编译行为收敛为显式 `--precompiled`。

## 3 详细设计

### 3.1 修复合入（`01807bb`，随发布携带，无新实现）

- ① `validate_test_cache_signature()`（[`src/build.cpp`](../../src/build.cpp)）：测试路径（Catch2 ≈:1832、ezmk 框架 ≈:2036）与构建路径（≈:892）一致地设置 `record.compile_options_signature`；签名变化 → `record.files.clear()`。
- ② [`scripts/embed_examples.py`](../../scripts/embed_examples.py)：剪枝 `build/` / `.ezmk/` / `.git` 目录 + 跳过二进制扩展名；[`test/test_example.cpp`](../../test/test_example.cpp) `list_files` 对齐。
- **回归锚点**：连续两次 `ezmk test`，第二次输出 "N cached, 0 compiled"；构建期 `example_data.cpp` 嵌入无 UnicodeDecodeError。

### 3.2 `ezmk project pack` 默认源码包（[`src/build.cpp`](../../src/build.cpp) `pack_project`）

| 维度 | 默认（源码包） | `--precompiled`（旧行为） |
|------|----------------|---------------------------|
| 归档内容 | `src/`（按 `[compile].src_dirs`，默认 `["src"]`）+ `include/` + `ezmk.toml`（**原样**，不追加标记） | `include/` + `lib/lib<name>.a`（MSVC 为 `<name>.lib`）+ `ezmk.toml` 追加 `precompiled = true` |
| 项目类型 | **任意类型**（包安装侧本就按静态库编译，`[project].type` 不触发 main 校验——与 `package_authoring` §2.4 语义一致） | 仅 `static`（现有校验保留） |
| 先构建 | **不需要**（无产物参与打包） | 需要（产物缺失时自动 `build_project`） |
| 平台 | **平台无关**（消费者侧编译到本机工具链/ABI） | 平台/工具链/ABI 绑定（打包机产物） |
| 归档名 | `<name>-<version>.tar.gz`（不变） | 同（两种格式同名；一次 pack 仅产一种格式；同时发布两格式用不同 `--output` 目录） |
| SHA-256 | 照常输出（内容 hash，随平台无关） | 照常输出 |

- `--precompiled` 新增到 `cli::ProjectPackOptions`（与 `--output` 并列）；help 文本同步（`i18n_keys.def` + 两份 JSON）。
- 源码包打包 `src/` 复用 `collect_sources` 的 `src_dirs` 语义（与 dev.9 包构建一致）；**无 `src/` 但有 `include/`**（header-only 风格）也可打包——安装侧按既有 header_only/空源规则处理，与 `pkg install <dir>` 一致。
- **不引入新包格式**：源码归档包 = 安装侧早已支持的源码包（`validate_pkg` + `compile_package`，`precompiled` 缺省 false）；本版只改 `project pack` 的**默认产物**。
- 打包前剪枝构建残留（`build/` / `.ezmk/` / `.git`），避免产物/缓存混入源码包（复用 3.1 ② 的剪枝思路）。

### 3.3 边界

- 既有已发布预编译归档 / 仓库索引：零影响（`--precompiled` 产物与旧默认逐字节等价；index 字段不变）。
- 与 1.2.4 目录包（`type = "dir"`）互补：**源码归档包**用于远程/非 git 分发（repo `file` 指向 tar.gz）；**目录包**用于 git 托管免打包。二者均为源码形态，本版不改安装侧。
- 源码包发布到 repo 的 index 条目：无 `precompiled` 相关语义（平台无关），`platform` 字段可省略。

## 5 兼容性

| 变更 | 影响 | 处理 |
|------|------|------|
| pack 默认产出源码包 | **行为变更**（旧默认 = 预编译包） | `--precompiled` 完全保留旧行为（逐字节等价）；视为「默认值调整 + 显式兼容」，非 API 破坏；CHANGES.md 明确记录 |

| `01807bb` 修复 | 纯修复 | test 缓存行为改善（二次命中），无 API 影响 |
| 公共 API | 无破坏性变更 | 新 flag `--precompiled` 纯新增；既有 flag（`--output` 等）不变；命令/配置零改动 |

## 6 跨版本关注点

- **与 1.3.0 解耦**：1.2.5 是 1.2.x 稳定线补丁，可先于 1.3.0 发布；`plan.md` 执行计划不变（仍指向 1.3.0），本版文档独立在 1.2.x 系列。

- **回归基线**：当前全量 793 用例 / 3755 断言（1.2.4 后），新增测试不得引入回归。
- **后续窗口**：源码包与预编译包「同包发布 / 按平台自动二选一」、pack 内容 hash（替代/补充 sha256）归 2.0.0 或后续评估；本版以默认切换 + `--precompiled` 的最小实现为准。
