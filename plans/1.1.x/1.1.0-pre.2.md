## 1 背景

`1.1.0-pre.1` 引入了顶层命令别名（`ezmk build` / `ezmk run` / …）、`--help` 输出重组、README 精简和 API 冻结承诺。`1.1.0-dev.7` 完成了包处理改善（硬依赖前置检查 + 自动安装 + want 交互式询问）。在这两个版本之后，需要做一次全面的文档审计：

1. **顶层别名未反映到文档**：`docs/en/cli.md`、`docs/zh/cli.md`、所有 tutorial 文件仍只使用 `ezmk project build` 旧写法，未提及新的顶层别名。此外，`README.md` 和 `README_ZH.md` 遗漏了 `ezmk pack` 顶层别名（仅以 `ezmk project pack` 形式出现在 "Project" 子部分）
2. **`config_file.md`（en + zh）遗漏配置节**：`[install]`（1.1.0 新增）和 `[test]`（1.1.0-dev.6 新增）在 CHANGES.md 的 API 稳定性承诺中列为稳定 API，但在配置参考文档中完全未记录
3. **pre.1 遗留项未完成**：zsh 补全（`res/ezmk.zsh`）、CI 自动构建（`.github/workflows/release.yml`）、Homebrew formula / winget manifest、`docs/zh/technical.md` 中文版
4. **`plans/README.md` 未更新**：仍显示 dev.7 为"当前执行"，未反映 pre.1 和 pre.2 的进展；此外 `plans/1.1.x/1.1.0.md`（最终 1.1.0 合并计划）不存在
5. **`include/ezmk/version.hpp` 版本号**：fallback 值仍为 `1.0.0`，与实际版本 `1.1.0-dev.7` 不符
6. **`CHANGES.md` 需验证**：检查是否涵盖了 dev.7 和 pre.1 的变更
7. **i18n 完整性**：验证 `i18n_keys.def` ↔ `en.json` ↔ `zh.json` 三者一致
8. **`docs/zh/` 中文文档一致性**：验证与 `docs/en/` 英文文档是否同步

```markdown
## Top-level aliases (1.1.0+)

For convenience, the most-used `project` subcommands are also available as
top-level commands:

| Alias | Full form |
|-------|-----------|
| `ezmk build` | `ezmk project build` |
| `ezmk run` | `ezmk project run` |
| `ezmk clean` | `ezmk project clean` |
| `ezmk watch` | `ezmk project watch` |
| `ezmk install` | `ezmk project install` |
| `ezmk test` | `ezmk project test` |
| `ezmk pack` | `ezmk project pack` |

Both forms are equivalent — all flags and arguments work the same way.
The short forms are recommended for daily use; the full `project <action>` forms
are kept for scripting and muscle memory.
```

### 阶段二：`config_file.md` 补全（P0）

**文件**：`docs/en/config_file.md` + `docs/zh/config_file.md`

#### 3.2.1 `[install]` 配置节

`1.1.0` 新增的安装配置节，在 CHANGES.md API 稳定性承诺中列为稳定 API，但配置参考文档中完全缺失。需新增：

```toml
[install]
prefix = "~/.local"        # 安装根目录（支持 ~ 展开）
bindir = "bin"             # 可执行文件子目录（相对于 prefix）
libdir = "lib"             # 静态/动态库子目录
includedir = "include"     # 头文件子目录
sharedir = "share"         # 数据文件子目录
```

对应 CLI 命令：`ezmk project install` / `ezmk install`。

#### 3.2.2 `[test]` 配置节

`1.1.0-dev.6` 新增的测试配置节，同样在 API 稳定性承诺中位列稳定 API。需新增：

```toml
[test]
dirs = ["test"]            # 测试源文件目录（string[]，默认 ["test"]）
framework = "catch2"       # 测试框架："catch2" | "ezmk"（大小写不敏感）
flags = []                 # 额外测试编译标志（string[]，默认 []）
```

对应 CLI 命令：`ezmk project test` / `ezmk test`。

#### 3.2.3 更新内容

以 `[hooks]` 节之后、`[utils]` 节之前的位置插入 `[install]` 和 `[test]` 文档，保持与现有配置节一致的格式（TOML 示例 + 字段说明表 + 备注）。中英文同步。

## 7 风险与注意事项

- **Tutorial 全面更新量大**：涉及 en + zh 共 12+ 个文件，建议按章节分批更新，每个文件改动不多（主要是命令替换）
- **zsh 补全的正确性验证**：需在 MSYS2 或 Linux 环境实际加载补全文件测试；Windows 原生 PowerShell 无法验证 zsh 补全
