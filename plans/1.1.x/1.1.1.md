# EazyMake 1.1.1 — 拦截 `ezmk utils cc` + 构建后自动生成 compile_commands

---

## 1 背景

`ezmk utils cc`（Lua 工具，`ezmk-official-utils/utils/cc.lua`）生成的 `compile_commands.json` 与 `ezmk build` 真实命令存在系统性 drift：不含 `@link:` 解析目录、依赖包 `extra_includes`、`-stdlib`、`-fPIC`、确定性标志、宏 `-D`、`--profile`、MSVC 翻译等（详见原 `1.2.0-dev.1` 分析，该计划核心已移入本版）。

1.1.1 是 **1.1.x 稳定线的补丁发布**，做两件事——**不改命令名、不新增命令、不弃用**：

1. **拦截 `ezmk utils cc`**：修复既有命令的输出正确性。在 CLI 分发处拦截 `utils cc`，改由内置 C++ 逻辑（复用真实命令构造）服务。
2. **`[compile].compile_commands` 自动生成**：新增配置项，`ezmk build` 成功后自动生成 compile_commands.json（对标 CMake `CMAKE_EXPORT_COMPILE_COMMANDS`）。

> **范围边界**：本版做拦截 + 自动生成。`ezmk project cc` 新命令、`ezmk utils cc` 弃用，推迟到 1.2.0（见 [`plans/1.2.0/1.2.0.md`](../1.2.0/1.2.0.md) 与 [`plans/1.2.0/1.2.0-dev.1.md`](../1.2.0/1.2.0-dev.1.md)）。
>
> **发布口径**：本版对 `ezmk-official-utils` 的 `cc` 工具**不声明废弃**。对外（CHANGES.md）仅表述为「**优化 compile_commands.json 生成算法**」+ 新增 `[compile].compile_commands` 配置项；「拦截」是内部实现细节，不对外宣布。`cc` 工具的弃用声明在 **1.2.0**。

## 3 详细设计

### 3.1 命令构造重构（核心）

`compile_one_source()`（`src/cache.cpp:310`）内联拼 shell 命令，同时处理 GCC/Clang 与 MSVC 两套。提取为两个公开函数（`include/ezmk/cache.hpp`）：

```cpp
// 构造单文件的真实编译参数（未转义；构建与 compile-db 共用）
std::vector<std::string> build_compile_args(const CompileInput& in,
                                            const fs::path& src,
                                            const fs::path& obj);

// 参数向量 → shell 转义命令串（构建路径专用，compile_one_source 内部调用）
std::string join_shell_args(const std::vector<std::string>& args);
```

- `build_compile_args()` 完整包含：真实编译器（`detected_compiler` 优先）、`-std=`、stdlib 标志、确定性标志、`-fPIC`、`[compile].flags`（MSVC 经 `translate_compile_flags` + `msvc_flags`）、`-I`（默认 `include/` + `include_dirs` 解析 `@link:` + 依赖包 `extra_includes`）、宏 `-D`（`generate_ezmk_macros()` + `[compile].macros`）、`-MMD -MF <dep>`、`-c <src> -o <obj>`。
- **验收**：`compile_one_source()` 经重构后输出命令与重构前逐字节一致（`bash build.sh test` 零回归）。

### 3.2 compile_db 模块

新建 `src/compile_db.cpp` + `include/ezmk/compile_db.hpp`：`generate_compile_db(project_root, config, profile, output_path)`。

- 复用 `build::prepare_build_state()`（或等价 include 收集）得到 `CompileInput`，遍历 `sources` → `build_compile_args()`。
- **最小规范化**：剔除 `-MMD`/`-MF <path>`/`-frandom-seed=<x>`/`/showIncludes`（clangd 不需要）；保留编译器、`-std=`、stdlib、宏、includes、flags、`-c <src>`、`-o <obj>`。
- `file` 用相对项目根 `rel_src`；`directory` 用项目根绝对路径；条目按 `rel_src` 字典序排序；temp → rename 原子写。
- 无源文件 → warning + 成功返回。

```json
[
  {
    "directory": "E:/proj",
    "arguments": ["g++", "-std=c++17", "-DEZMK=1", "-Iinclude", "-c", "src/main.cpp", "-o", "build/src/main.o"],
    "file": "src/main.cpp"
  }
]
```

### 3.3 拦截 `ezmk utils cc`

`src/main.cpp` 的 `Command::Utils` 分发处（当前：`find_utils_script()` → `lua::run_script()`），在查找 Lua 脚本**之前**拦截：

```
if (args.utils_name == "cc") {
    // 1.1.1：cc 工具内建拦截，改由 C++ 生成器服务
    return run_builtin_cc(args.utils_args);   // 解析 -o/--output、-h/--help → generate_compile_db()
}
```

- **兼容行为**：默认输出 `<proj_root>/compile_commands.json`；`-o <path>` 相对项目根解析；`-h/--help` 打印帮助（复用原工具文案）；`--profile <name>` 透传（若传入）。
- **不**调用 `find_utils_script("cc")`，`cc.lua` 不再执行（包内文件保留，1.2.0 再处理弃用）。
- 拦截仅针对工具名 `cc`，其他 utils 工具查找链不变。

### 3.4 `[compile].compile_commands` 自动生成

**配置**：`config::CompileSection` 新增 `bool compile_commands = false`，`src/config.cpp` 解析 `[compile].compile_commands`。

```toml
[compile]
compile_commands = true   # ezmk build 成功后自动生成 compile_commands.json
```

**构建集成**（`src/build.cpp`）：

- `ezmk build` 链接成功后，若 `compile.compile_commands` 为 true（或 `--compile-commands` flag 透传），调用 `compile_db::generate_compile_db()`。
- **用构建期 `CompileInput`**：含 `--profile` 应用后的标志、依赖包 include、`@link:` 解析结果——输出与本次构建**逐条一致**（这是比独立命令更精准的地方）。
- 失败不阻塞构建（warning 级）；`--compile-commands` flag 允许临时开启而不改配置。

> **为什么自动生成用构建期状态**：独立 `generate_compile_db()` 需重建 `prepare_build_state()`；而构建已完成解析，直接复用本次 `CompileInput` 保证零 drift，且无额外探测开销。

## 6 跨版本关注点

- **1.2.0 承接**：`ezmk project cc` 新命令在 1.2.0 添加，直接复用本版 `build_compile_args()` + `compile_db`；本版拦截逻辑迁到新命令后，`ezmk utils cc` 转弃用提示（1.2.0）。
- **自动生成与命令的同一实现**：本版自动生成与拦截共用 `generate_compile_db()`；1.2.0 的 `project cc` 命令也复用同一函数——三个入口（拦截/自动生成/命令）输出永远一致。
- **单一事实源持续收益**：重构收敛后，任何新增编译标志自动进入 compile_commands.json。
- **`--profile` 一致性**：拦截与自动生成路径的 profile 应用须与 `build.cpp` 一致，避免"构建用 profile、索引不用"。
- **确定性交互**：`-ffile-prefix-map` 保留，`-frandom-seed` 剔除——决策在代码注释记录。
