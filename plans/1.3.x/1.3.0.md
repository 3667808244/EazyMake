# EazyMake 1.3.0 — Workspace（工作区）功能版本

> 1.2.x 收官后的**首个功能 minor**。发布总览见 [`1.3.x/README.md`](README.md)。
> 正式版按 **dev → pre** 两阶段推进：dev 落地功能，pre 做文档/门槛收口，最后聚合发布。

---

## 1 背景

EazyMake 目前只有**单项目模型**：`ezmk build` 从当前目录向上找 `ezmk.toml`，一次处理一个项目。多个独立项目（monorepo 多产物、一批示例/工具、CI 多组件）只能逐个 `cd` 或外部脚本循环，没有统一管理面。`@link:` 是源码级共享（跨目录编译进多个项目），但每次改共享源码，所有消费者各自重编一份——重复劳动。

需要一个**多项目组织层**：工作区 = 一个目录下多个独立项目（成员）的集合，统一、可并行的批量管理。成员间可声明**单向非循环依赖**（最常见 monorepo 形态：共享基础库 + 多个可执行文件），构建时**拓扑排序 + 产物复用**：改库 `.cpp` → 库重编一次、消费者只重链接（消灭 @link 的重复编译）；改库 `.h` → 消费者重编（C++ 编译模型固有，任何工具无法消除）。

**定位**：这是「批量命令 + 并行调度 + 最小依赖图（单向、无环、无版本）」，**不是**完整构建系统——环 / 版本约束 / 平台矩阵 / 可编程构建图仍归 non-goals（见 [`docs/non-goals.md`](../../docs/zh/non-goals.md)「多项目工作区」条款的更新）。

## 3 详细设计

### 3.1 配置文件 `ezmk-workspace.toml`（独立于 `ezmk.toml`）

```toml
[workspace]
name = "my-workspace"
members = ["libs/strutil", "apps/tool-a", "apps/tool-b"]

[workspace.options]
default_jobs = 0          # 0 = 自动（hardware_concurrency）；默认
stop_on_error = false     # 默认继续并汇总；true = 首个失败即停
```

- 文件放 **workspace 根**；成员路径**相对根**，仅允许子目录（`../` 逃逸 → 校验错误）
- 根目录可有自己的 `ezmk.toml`（根自身可作为成员）或仅作纯容器
- 新解析器（复用 toml11）；`[workspace]` 的 `name` 可选、`members` 必填非空；`[workspace.options]` 可选
- **定位**：`locate_workspace_root()` 从 cwd 向上最多 5 层找 `ezmk-workspace.toml`（与 `locate_project_root` 对称，互不干扰）

### 3.2 成员依赖声明（成员自己的 `ezmk.toml`）

```toml
# apps/tool-a/ezmk.toml
[depends]
lib = ["fmt"]                     # 外部包（现状，不变）
workspace = ["strutil"]           # 1.3.0：兄弟成员（命名空间区别于外部包）
```

- 依赖是**项目的属性**，跟随成员走：成员搬到别处/独立出去，声明不用改
- `workspace` 值 = 成员相对路径的**末段**（`strutil`）或完整相对路径（`libs/strutil`），二者皆可
- **约束**：
  - **单向无环**：A→B 且 B→A 或自环 → 配置校验期报错（fail-fast，同路径逃逸/依赖互引哲学）
  - **被依赖成员必须 `static`**（产物 `build/lib<name>.a`）；`executable`/`shared` 不能被依赖（shared 运行时依赖归延后）
  - 依赖方可为 `executable`/`static`（`shared` 依赖兄弟成员暂不支持，延后）
  - **无版本**：开发中源目录即改即用；版本/快照语义继续走包模型（与 1.2.4 目录包互补）

### 3.3 命令面：顶层 `ezmk workspace` 组

```
ezmk workspace list                        # 成员列表：路径 + 类型 + 依赖 + 状态
ezmk workspace build  [build-opts] [-j N] [--stop-on-error] [--member <name>...]
ezmk workspace test   [test-opts]  [-j N] [--stop-on-error] [--member <name>...]
ezmk workspace clean                       # 批量清理（全部成员）
```

- `build-opts` 完全复用单项目 build 选项（`--profile` / `--disable-cache` / `-j` 等），逐成员透传
- `--member <name>`：只对指定成员执行（**含其依赖闭包**：依赖成员按拓扑先构建）；名称 = 成员路径末段或完整相对路径
- 顶层 `ezmk build` 在纯容器根 → 提示用 `ezmk workspace build`；有 `ezmk.toml` → 正常单项目行为
- 成员目录内直接 `ezmk build`：若该成员声明了 `[depends] workspace`，**自动解析兄弟产物**（见 3.5），无需在 workspace 根
- 无别名；未知子命令/未知成员 → fatal
- **i18n**：新增 `workspace_*` key 组（X-macro 三向一致）

### 3.4 构建语义：拓扑 + 层内并行

```
ezmk workspace build
[workspace] Building 3 members (-j 2)...
  ✓ libs/strutil     (2.1s)   ← 第 0 层（无依赖）
  ✓ apps/tool-a      (0.8s)   ← 第 1 层（依赖 strutil），与 tool-b 并行
  ✓ apps/tool-b      (0.7s)
[workspace] 3 succeeded, 0 failed
```

- **Kahn 拓扑分层**：依赖成员先构建；同层成员并行（`-j` 限并发，复用 `util::ThreadPool`）
- 无依赖成员 = 第 0 层（平行批量退化为特例，`1.3.0-dev.2` 的并行调度不变）
- 环在**配置期**拒绝（`workspace list`/任何执行前 fail-fast），构建期不可能出现环
- 执行模型为**子进程**（每成员独立 `<ezmk> build/test/clean` 进程，cwd 为成员目录）——cwd/Lua 状态/缓存天然隔离，复用全部单项目逻辑

### 3.5 兄弟产物注入（成员内 `ezmk build` / workspace build 通用）

当成员声明 `workspace = ["strutil"]` 时，构建自动注入：

```
-I <workspace>/libs/strutil/include
-L <workspace>/libs/strutil/build  -lstrutil
```

- **约定布局**：被依赖成员固定产出 `include/`（公共头）与 `build/lib<name>.a`（静态库）；消费者 `#include <strutil/strutil.hpp>` 开箱即用，零手写路径
- 产物注入在构建前**解析**（依赖成员必须先构建完成；其 `build/lib<name>.a` 存在才注入链接）——由 workspace 构建的拓扑保证；成员内独立 `ezmk build` 时若兄弟产物缺失 → 提示「先 `ezmk workspace build` 或构建依赖成员」

### 3.6 增量语义

- **改库 `.cpp`** → 库重编一次（`build/lib<name>.a` 更新）→ 消费者 `.o` 缓存命中、**仅重链接**（链接无缓存，天然正确）
- **改库 `.h`** → 消费者编译时经 `-MMD` depfile 记录兄弟头文件 → 缓存自动失效重编（复用 `cache.cpp` 的 `parse_depfile_and_hash`，零新语义）
- 每个成员独立 `.ezmk/`、`build/`、`ezmk.lock`、测试缓存（含已修复的签名校验）——增量天然按成员隔离

### 3.7 成员校验（`list` 与任何执行前）

1. 路径在根内（无 `..` 逃逸、无绝对路径、无盘符、无 UNC；符号链接解析真实路径）
2. 成员目录存在且含 `ezmk.toml`（缺失 → 标记 `invalid` 并跳过，不阻断其他成员）
3. 无嵌套 workspace（成员内不得再有 `ezmk-workspace.toml`）
4. **成员依赖**：`[depends] workspace` 引用的名字必须解析到已列成员（未知 → 报错）；环（含自环）→ 报错；被依赖成员类型非 `static` → 报错

## 5 兼容性

| 变更 | 影响 | 处理 |
|------|------|------|
| 新增 `ezmk workspace` 命令组 | 纯新增 | 与既有命令不冲突；无别名 |
| 新增 `ezmk-workspace.toml` | 纯新增文件 | 与 `ezmk.toml` 独立解析；定位互不干扰 |
| `[depends] workspace = [...]` 新字段 | 纯新增 | 未声明时零影响；单项目（非成员）声明了但找不到 workspace → 报错提示 |
| 成员内 `ezmk build` 自动解析兄弟产物 | 仅成员生效 | 非成员项目行为不变 |
| 公共 API | 无破坏性变更 | 新命令/新文件/新字段纯增量；单项目路径零改动 |

## 6 跨版本关注点

- **与 2.0.0 解耦**：workspace 纯增量，不依赖任何 deprecation 到期；2.0.0 保持破坏性变更窗口。
- **non-goals 立场更新**：允许**单向非循环成员依赖**这一最小图；完整构建图（环 / 版本 / 平台矩阵 / 可编程图）仍拒绝——见 `docs/non-goals.md`「多项目工作区」条款（pre.1 落地，中文基准先行同步英文）。
- **与包模型互补**：成员依赖 = 开发中源码即改即用；包（目录包/归档包）= 分发与快照隔离。二者并存。
- **并行模型**：层内并行复用线程池；输出加成员前缀防交错；`--stop-on-error` 语义扩展为「本层失败即停，后续层跳过」。
- **回归基线**：当前全量 793 用例 / 3755 断言（1.2.4 后），新增功能不得引入回归。
- **后续窗口**：shared 运行时依赖 / 成员级过滤（按标签）归 2.0.0 或后续评估。
