# EazyMake 1.3.0 — Workspace（工作区）功能版本

> 1.2.x 收官后的**首个功能 minor**。发布总览见 [`1.3.x/README.md`](README.md)。
> 正式版按 **dev → pre** 两阶段推进：dev 落地功能，pre 做文档/门槛收口，最后聚合发布。

---

## 1 背景

EazyMake 目前只有**单项目模型**：`ezmk build` 从当前目录向上找 `ezmk.toml`，一次处理一个项目。多个独立项目（monorepo 多产物、一批示例/工具、CI 多组件）只能逐个 `cd` 或外部脚本循环，没有统一管理面。`@link:` 是源码级共享（跨目录编译进多个项目），但仍是单项目构建。

需要一个**多项目组织层**：工作区 = 一个目录下**若干编译期互不依赖的独立项目集合**，统一、可并行的批量管理。成员不构成编译依赖图（无 `add_subdirectory` 式构建图），因此可跨成员并行、缓存/产物完全独立——定位为「批量命令 + 并行调度」。

## 3 详细设计

### 3.1 配置文件 `ezmk-workspace.toml`（独立于 `ezmk.toml`）

```toml
[workspace]
name = "my-workspace"
members = ["apps/tool-a", "apps/tool-b", "libs/strutil", "tests/e2e"]

[workspace.options]
default_jobs = 0          # 0 = 自动（hardware_concurrency）；默认
stop_on_error = false     # 默认继续并汇总；true = 首个失败即停
```

- 文件放 **workspace 根**；成员路径**相对根**，仅允许子目录（`../` 逃逸 → 校验错误）
- 根目录可有自己的 `ezmk.toml`（根自身作为成员之一）或仅作纯容器
- 新解析器（复用 toml11），`[workspace]` 的 `name` 可选、`members` 必填非空；`[workspace.options]` 可选（缺省：`default_jobs=0`、`stop_on_error=false`）
- **定位**：`locate_workspace_root()` 从 cwd 向上最多 5 层找 `ezmk-workspace.toml`（与 `locate_project_root` 对称，互不干扰）

### 3.2 命令面：顶层 `ezmk workspace` 组

```
ezmk workspace list                        # 成员列表：路径 + 类型 + ezmk.toml 是否存在
ezmk workspace build  [build-opts] [-j N] [--stop-on-error] [--member <name>...]
ezmk workspace test   [test-opts]  [-j N] [--stop-on-error] [--member <name>...]
ezmk workspace clean                       # 批量清理（全部成员）
```

- `build-opts` 完全复用单项目 build 选项（`--profile` / `--disable-cache` / `-j` 等），逐成员透传
- `--member <name>`：只对指定成员执行（名称 = 成员路径末段或完整相对路径）；可多次
- **顶层 `ezmk build` 在 workspace 根**：仅存在 `ezmk-workspace.toml` 而无 `ezmk.toml` → 提示「工作区根，请用 `ezmk workspace build`」；有 `ezmk.toml` → 正常单项目行为（不隐式降级）
- 无别名；未知子命令/未知成员 → fatal
- **i18n**：新增 `workspace_*` key 组（X-macro 三向一致，`check_i18n.py` 通过）

### 3.3 执行模型

- **并行调度**：按 `-j`（默认 `default_jobs`）限制并发成员数；每个成员在自己的 cwd 跑完整管线；成员内 `-j` 并行不变
- **结果汇总**：

```
[workspace] Building 3 members (-j 2)...
  ✓ apps/tool-a      (2.1s)
  ✓ libs/strutil     (1.8s)
  ✗ apps/tool-b      (0.4s) — 3 error(s)
[workspace] 2 succeeded, 1 failed
```

- 默认**继续执行**并汇总；`--stop-on-error` 首个失败即停（剩余成员跳过并标注）
- 每个成员输出前缀 `[member] `，避免并行日志交错
- 任一失败 → 最终非零退出码

### 3.4 成员校验（`list` 与任何执行前）

1. 路径在根内（无 `..` 逃逸、无绝对路径、无盘符、无 UNC；符号链接解析真实路径）
2. 成员目录存在且含 `ezmk.toml`（缺失 → 标记 `invalid` 并跳过，不阻断其他成员）
3. 无嵌套 workspace（成员内不得再有 `ezmk-workspace.toml`）
4. **成员间无编译期依赖**：`[depends]` 引用其他成员名 → 校验错误（「可并行」的保证）

### 3.5 缓存与产物

每个成员独立 `.ezmk/`、`build/`、`ezmk.lock`、测试缓存（含已修复的签名校验）——增量缓存天然按成员隔离。

## 5 兼容性

| 变更 | 影响 | 处理 |
|------|------|------|
| 新增 `ezmk workspace` 命令组 | 纯新增 | 与既有命令不冲突；无别名 |
| 新增 `ezmk-workspace.toml` | 纯新增文件 | 与 `ezmk.toml` 独立解析；根定位互不干扰 |
| 顶层 `ezmk build` 在 workspace 根 | 仅纯容器根提示 | 有 `ezmk.toml` 时行为不变；无则提示用 workspace 命令 |
| 公共 API | 无破坏性变更 | 新命令/新文件纯增量；单项目路径零改动 |

## 6 跨版本关注点

- **与 2.0.0 解耦**：workspace 纯增量，不依赖任何 deprecation 到期；2.0.0 保持破坏性变更窗口（`[test].flags` / `ezmk utils cc` 移除等）。
- **并行模型**：跨成员并行复用线程池思路，成员内 `-j` 并行不变；输出加成员前缀防交错。
- **安全**：路径逃逸与依赖互引在配置校验期拒绝（前者路径安全，后者是可并行保证）。
- **回归基线**：当前全量 793 用例 / 3755 断言（1.2.4 后），新增功能不得引入回归。
- **后续窗口**：成员级过滤/`cc` 批量生成/嵌套依赖图（成员间真实依赖）归 2.0.0 或后续评估。
