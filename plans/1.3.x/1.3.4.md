# EazyMake 1.3.4 — watch 重建后自动运行（`ezmk watch --run`）

> 1.3.0 正式发布后的**补丁版本**（与 1.3.1 语言区间、1.3.2 测试报告、1.3.3 简写相互独立，可并行）。发布总览见 [`1.3.x/README.md`](README.md)。

---

## 1 背景

`ezmk watch`（[`src/main.cpp`](../../src/main.cpp) `:299-403`）是**无限重建循环**：文件变更 → 增量/全量重建，但**从不运行产物**。用户想要"改代码自动重跑"目前没有内置形态——只能手动 `ezmk run`，或外部循环（`while true; do ezmk run; ...`）这类脆弱的壳脚本。

基础设施恰好已经具备，改动极小：

1. **`build_project()` 返回可执行文件路径**——`project run` 正是这么用的（`main.cpp:198`：`auto exe = build_project(...)` → 拼 `"<exe>" <args>` → 阻塞 `run_command`）。watch 的变更回调（`main.cpp:346-376`）现在把返回值丢弃，`--run` 只需接住它。
2. **`util::run_command` 是阻塞的**——而 watch 的重建发生在 **watcher 线程**上（`main.cpp:392-394`：后台线程跑 `watcher.run()`，回调在线程内执行）。阻塞运行 = **程序运行期间天然暂停变更检测，程序退出后 watch 自动恢复**——免费拿到的最简语义，不需要任何进程管理/杀进程逻辑。
3. **`-r` 短 flag 未被占用**（全部 `OptionSpec` 无 `'r'`）。

## 2 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | `ezmk watch --run` / `-r`：每次**成功**重建后阻塞运行产物；程序退出后 watch 继续监听 | P0 |
| 2 | **默认行为不变**：无 `--run` 时与现状完全一致 | P0 |
| 3 | 仅 `executable` 项目：`static`/`shared`/`utils` + `--run` → 启动时 fatal（配置期拒绝） | P0 |
| 4 | 构建失败 → 不运行（现有 catch 分支），继续 watch | P0 |
| 5 | 程序非零退出 → 警告，**不退出 watch**（watch 是持续循环，不是一次性 run） | P0 |
| 6 | 与 `--no-build-on-start` 正交（首次运行发生在第一次变更后） | P1 |
| 7 | 文档：cli.md（en/zh）+ CHANGES.md 1.3.4 条目；集成测试 | P1 |

## 3 详细设计

### 3.1 flag 与执行语义

- **flag**：`cli.cpp:256` 的 watch spec 追加 `{'r', "run", false}`；`CliArgs` 新增 `watch_run` 布尔；`reject_positionals` 不变（**不做** `--` 参数透传，见 §6 后续窗口）。
- **执行点**：watch 回调（`main.cpp:346-376`）中 `auto exe = ezmk::build::build_project(...)`；`if (args.watch_run && !exe.empty())` → 阻塞运行。**只在成功分支**（try 内）运行，catch 分支（`:358-361`/`:372-375`）不运行——构建失败绝不得运行旧产物（坑 4）。
- **执行方式复用 `project run`**（`main.cpp:202-211`）：`"<exe>"` → `util::run_command` → stdout/stderr 回显 → 非零退出码 → **警告不退出**（区别于 run 的退出码转发）。运行前打印现有 `running` i18n key（带 `{exe}` 参数，`locale/en.json` 已有）。
- **类型门禁**：watch 启动时（`main.cpp:311` 前）检查 `cfg.project.type != "executable"` && `watch_run` → fatal（新 key `cli_err_run_needs_executable`）。
- **I/O 行为与 `project run` 一致**（捕获 + 回显）：交互式/长驻程序的行为与 `ezmk run` 相同——文档明示。

### 3.2 生命周期（决策记录）

| 决策 | 选择 | 理由 |
|------|------|------|
| 运行时机 | 每次成功重建后 | 简单可预测；"缓存命中也要跑"（看到最新结果） |
| 生命周期 | **阻塞运行**；程序自行退出 → watch 恢复 | 最简；watcher 线程阻塞 = 运行期间暂停检测，免费的正确性 |
| 程序非零退出 | 警告，不退出 watch | watch 是循环，非一次性 run |
| Ctrl+C | 子进程与 ezmk 同前台进程组 → 一起终止 | 用户意图"全停"；文档写明 |
| **拒绝：kill 旧进程再重启** | 不实现 | 自动杀用户进程（服务器/GUI/未保存状态）危险；信号/进程组/子进程树复杂，违反"小而直" |
| **拒绝：非阻塞 detached 启动** | 不实现 | 不管理生命周期 → 堆积进程 |
| **拒绝：仅缓存未命中时运行** | 不实现 | UX 怪异（改头文件触发重编却不运行，或相反） |

### 3.3 已知坑位与对策

| # | 坑 | 优先级 | 对策 | 落点 |
|---|-----|--------|------|------|
| 1 | 程序长驻不退出（服务器/GUI）→ watch 暂停 | 高 | 文档写明：程序运行期间不检测变更，退出后恢复；用户自行 Ctrl+C | §3.2 |
| 2 | Ctrl+C 同进程组一起终止 | 中 | 文档写明（用户意图全停）；SIGINT 处理（`main.cpp:305-309`）不受影响 | §3.2 |
| 3 | 非 `executable` + `--run` | 高 | 启动时 fatal（配置期拒绝） | §3.1 |
| 4 | 构建失败运行旧产物 | 高 | 只在 try 成功分支运行；catch 不运行 | §3.1 |
| 5 | `ezmk.toml` 变更路径（`:351-363`）也要运行 | 中 | 两条回调路径（config 变更 / 源变更）统一接 `--run` 逻辑（共享 helper） | §3.1 |

### 3.4 测试

- **集成测试**（`test/test_integration.cpp` 或 `test/test_file_watcher.cpp` 扩展）：`executable` 项目（main 打印唯一标记）→ `ezmk watch --run`（后台进程）→ 修改源文件 → 轮询断言标记输出出现（沿用 file_watcher 测试的 poll 模式）；
- 构建失败不运行：改出编译错误 → 断言无运行输出、watch 存活；
- 非 `executable` + `--run` → 启动 fatal；
- 无 `--run` → 行为与现状一致（回归断言：改源 → 只有构建输出，无程序输出）。
