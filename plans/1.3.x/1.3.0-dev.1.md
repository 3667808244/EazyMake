# EazyMake 1.3.0-dev.1 — workspace 配置与定位

> 1.3.0 第一个开发子版本。总览见 [`1.3.x/README.md`](README.md)，正式版设计见 [`1.3.0.md`](1.3.0.md)。

## 1 背景

工作区功能的第一步：**配置文件解析与根定位**。定义 `ezmk-workspace.toml`（独立于 `ezmk.toml`），提供 `locate_workspace_root()` 从任意子目录定位 workspace 根，并在配置期完成成员校验（路径逃逸 / 存在性 / 嵌套 / 依赖互引）——为 dev.2 的命令执行提供可信的成员清单。

## 2 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | `ezmk-workspace.toml` 解析：`[workspace]`（`name` 可选、`members` 必填非空）+ `[workspace.options]`（`default_jobs=0`、`stop_on_error=false`） | P0 |
| 2 | `locate_workspace_root()`：从 cwd 向上最多 5 层找 `ezmk-workspace.toml`（与 `locate_project_root` 对称） | P0 |
| 3 | 成员校验：路径逃逸拒绝（`../` / 绝对 / 盘符 / 符号链接出根）、成员存在 + 含 `ezmk.toml`、无嵌套 workspace、成员间 `[depends]` 互引拒绝 | P0 |
| 4 | 单元测试：解析（members/options/缺省/非法格式）+ 定位 + 校验各拒绝分支 | P0 |

## 3 详细设计

### 3.1 数据结构（`include/ezmk/workspace.hpp`）

```cpp
namespace ezmk::workspace {

struct Options {
    int default_jobs = 0;        // 0 = auto (hardware_concurrency)
    bool stop_on_error = false;
};

struct Member {
    std::string name;            // 相对 workspace 根的路径（如 "apps/tool-a"）
    fs::path path;               // 解析后的绝对路径
    bool valid = false;          // 校验通过（存在 + ezmk.toml + 无嵌套）
    std::string error;           // invalid 原因（校验期填充）
};

struct Workspace {
    std::string name;            // 可为空
    Options options;
    std::vector<Member> members;
    fs::path root;               // workspace 根（绝对路径）
};

// 从给定目录向上（最多 5 层）找 ezmk-workspace.toml；找不到返回空。
std::optional<Workspace> load_from(const fs::path& start_dir);

// 校验单个成员（存在性/ezmk.toml/嵌套/路径安全）；失败抛 std::runtime_error。
void validate_member(const Workspace& ws, Member& m);

// 成员间依赖互引校验（读各成员 ezmk.toml 的 [depends]）；失败抛 std::runtime_error。
void validate_no_inter_member_deps(const Workspace& ws);

} // namespace ezmk::workspace
```

### 3.2 `ezmk-workspace.toml` 解析

- 复用 toml11（`include/vendor/toml11`），独立于 `config.cpp` 的项目解析（互不耦合）
- `[workspace]`：`name`（string，可选）、`members`（string 数组，必填非空）
- `[workspace.options]`：`default_jobs`（int ≥ 0，缺省 0）、`stop_on_error`（bool，缺省 false）
- 非法格式（缺 members / 空 members / 非字符串数组 / 负 jobs / 未知节）→ 明确报错（含文件路径与字段名）

### 3.3 `locate_workspace_root()`

- 从 `start_dir` 起，检查 `ezmk-workspace.toml` 存在；否则逐级 `parent_path()`，最多 5 层
- 与 `util::locate_project_root`（找 `ezmk.toml`）**完全独立**：一个目录可同时是项目根（`ezmk.toml`）与 workspace 根（`ezmk-workspace.toml`）
- 返回绝对路径根

### 3.4 成员校验

| 检查 | 规则 | 失败处理 |
|------|------|----------|
| 路径安全 | 相对路径、无 `..` 逃逸、无绝对/盘符/UNC；`fs::weakly_canonical` 解析后仍在根内 | 配置解析即报错（`runtime_error`） |
| 存在性 | 成员目录存在且含 `ezmk.toml` | 标记 `valid=false` + `error`（执行时跳过，不阻断） |
| 嵌套 | 成员内不得含 `ezmk-workspace.toml` | 标记 invalid（明确报错） |
| 依赖互引 | 读各成员 `[depends] lib/want`，若引用其他成员名 → 拒绝 | 配置校验报错（可并行保证） |

- 路径逃逸与依赖互引属于**配置期硬校验**（`load_from` 抛错）；存在性/嵌套标记 `valid=false`（`list` 展示、执行跳过）

### 3.5 与既有代码的边界

- **零改动**：`config.cpp` / `util.cpp`（`locate_project_root` 不动）/ 单项目命令路径
- 新增文件：`include/ezmk/workspace.hpp` + `src/workspace.cpp`
- `build.sh` 的 `TEST_SRC` / `SRC` 自动包含 `src/workspace.cpp`（`src/*.cpp` glob）

## 6 跨版本关注点

- **dev.2 依赖本版**：命令执行消费 `Workspace` 结构与校验结果。
- **安全**：路径逃逸与符号链接出根在配置期拒绝（复用以 1.1.2 路径校验为蓝本的 `weakly_canonical` 思路）。
- **依赖互引检测**：成员 `[depends]` 引用其他成员名即拒绝——与包解析（`pkg::package_available`）正交，只做名称比对。
