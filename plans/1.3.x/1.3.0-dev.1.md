# EazyMake 1.3.0-dev.1 — workspace 配置与定位

> 1.3.0 第一个开发子版本。总览见 [`1.3.x/README.md`](README.md)，正式版设计见 [`1.3.0.md`](1.3.0.md)。

---

## 1 背景

工作区功能的第一步：**配置文件解析与根定位**。定义 `ezmk-workspace.toml`（独立于 `ezmk.toml`），提供 `locate_workspace_root()` 从任意子目录定位 workspace 根，并在配置期完成**成员校验**（路径逃逸 / 存在性 / 嵌套）与**成员依赖校验**（`[depends] workspace` 解析、环检测、被依赖类型约束）——为 dev.2 的拓扑构建与并行执行提供可信的成员+依赖清单。

## 2 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | `ezmk-workspace.toml` 解析：`[workspace]`（`name` 可选、`members` 必填非空）+ `[workspace.options]`（`default_jobs=0`、`stop_on_error=false`） | P0 |
| 2 | `locate_workspace_root()`：从 cwd 向上最多 5 层找 `ezmk-workspace.toml`（与 `locate_project_root` 对称） | P0 |
| 3 | 成员校验：路径逃逸拒绝（`../` / 绝对 / 盘符 / 符号链接出根）、成员存在 + 含 `ezmk.toml`、无嵌套 workspace | P0 |
| 4 | **成员依赖**：`[depends] workspace = [...]` 解析（值 = 成员末段或完整相对路径）；未知引用 → 报错；**环（含自环）→ 配置期报错**；被依赖成员非 `static` → 报错 | P0 |
| 5 | 单元测试：解析（members/options/缺省/非法）+ 定位 + 校验各拒绝分支 + 依赖/环/类型 | P0 |

## 3 详细设计

### 3.1 数据结构（`include/ezmk/workspace.hpp`）

```cpp
namespace ezmk::workspace {

struct Options {
    int default_jobs = 0;        // 0 = auto (hardware_concurrency)
    bool stop_on_error = false;
};

struct Member {
    std::string name;            // 相对 workspace 根的路径（如 "apps/tool-a"）
    std::string basename;        // 末段（如 "tool-a"），供 `workspace = [...]` 引用
    fs::path path;               // 解析后的绝对路径
    std::string type;            // 成员 ezmk.toml 的 [project].type（缺失则 ""）
    std::vector<std::string> ws_deps;  // [depends] workspace 引用（成员末段/相对路径）
    bool valid = false;          // 校验通过（存在 + ezmk.toml + 无嵌套）
    std::string error;           // invalid 原因
};

struct Workspace {
    std::string name;
    Options options;
    std::vector<Member> members;
    fs::path root;
};

std::optional<Workspace> load_from(const fs::path& start_dir);
void validate_member(const Workspace& ws, Member& m);           // 路径/存在性/嵌套
void validate_ws_deps(const Workspace& ws);                     // 依赖解析 + 环 + 类型

} // namespace ezmk::workspace
```

### 3.2 `ezmk-workspace.toml` 解析

- 复用 toml11，独立于 `config.cpp` 的项目解析（互不耦合）
- `[workspace]`：`name`（string，可选）、`members`（string 数组，必填非空）
- `[workspace.options]`：`default_jobs`（int ≥ 0，缺省 0）、`stop_on_error`（bool，缺省 false）
- 非法格式（缺 members / 空 members / 非字符串数组 / 负 jobs / 未知节）→ 明确报错（含文件路径与字段名）

### 3.3 `locate_workspace_root()`

- 从 `start_dir` 起检查 `ezmk-workspace.toml`，否则逐级 `parent_path()`，最多 5 层
- 与 `util::locate_project_root`（找 `ezmk.toml`）**完全独立**：一个目录可同时是项目根与 workspace 根

### 3.4 成员校验

| 检查 | 规则 | 失败处理 |
|------|------|----------|
| 路径安全 | 相对路径、无 `..` 逃逸、无绝对/盘符/UNC；`weakly_canonical` 解析后仍在根内 | 配置解析即报错（`runtime_error`） |
| 存在性 | 成员目录存在且含 `ezmk.toml` | 标记 `valid=false` + `error`（执行时跳过，不阻断） |
| 嵌套 | 成员内不得含 `ezmk-workspace.toml` | 标记 invalid（明确报错） |

### 3.5 成员依赖校验（`validate_ws_deps`）

1. 读每个成员 `ezmk.toml` 的 `[depends] workspace`（数组字段；复用 `config::parse_config` 的 `depends` 解析后取 `workspace` 键——需在 `Config` 结构新增可选 `workspace` 向量）
2. **引用解析**：每个值按「成员完整相对路径或末段」匹配已列成员；未匹配 → `runtime_error`（含成员名与引用值）
3. **环检测**：以成员为节点、`ws_deps` 为边做 DFS 环检测（或 Kahn 计数）；发现环（含自环）→ `runtime_error`（打印环路径，如 `tool-a → strutil → tool-a`）
4. **类型约束**：被依赖成员的 `[project].type` 必须为 `static`（产物 `lib<name>.a`）；`executable`/`shared` 被依赖 → `runtime_error`
5. 依赖成员自身 `valid=false`（缺失 ezmk.toml）→ 引用它的成员也标记 invalid

> 环与类型在**配置期** fail-fast（同路径逃逸哲学）：`workspace list` / 任何执行前调用 `validate_ws_deps`，构建期不可能出现环。

### 3.6 与既有代码的边界

- **零改动**：`config.cpp` / `util.cpp`（`locate_project_root` 不动）/ 单项目命令路径
- **新增**：`include/ezmk/workspace.hpp` + `src/workspace.cpp`
- **config.hpp 微扩**：`DependsSection` 加可选 `std::vector<std::string> workspace;`（解析 `[depends] workspace`；未声明时为空，既有行为零影响）——成员内 `ezmk build` 读取兄弟依赖需要它

## 6 跨版本关注点

- **dev.2 依赖本版**：命令执行消费 `Workspace` 结构与校验结果；拓扑排序消费 `ws_deps`。
- **环检测算法**：DFS 三色标记（未访问/访问中/完成）——`runtime_error` 携带环路径便于用户定位。
- **依赖命名**：值支持成员末段与完整相对路径；歧义（两成员同名末段）→ 报错要求用完整路径。
