# EazyMake 1.3.2 — 单元测试机器可读报告（`ezmk test --report`）

> 1.3.0 正式发布后的**补丁版本**（与 1.3.1 语言区间相互独立、可并行）。发布总览见 [`1.3.x/README.md`](README.md)。

---

## 1 背景

`ezmk test`（[`src/build.cpp`](../../src/build.cpp) `run_tests()` `:1813-2315`）目前只输出**控制台摘要文本**（`cases: N | passed: M | failed: K` + Catch2 摘要行解析），CI 无法直接消费。现状下唯一机器可读路径是绕过 ezmk 直接跑测试二进制的 Catch2 reporter 参数——与 `ezmk test` 的「先增量构建再消费」管线（1.3.0-dev.5）脱节：不自动构建、不注入依赖包 include / 宏 / `-stdlib` 等。

1.3.0-dev.5 确立了"消费命令总是先增量构建"，报告出口应当挂在 `ezmk test` 之后，而不是让用户在 CI 里手工拼命令。同时两个测试框架不对称：**Catch2**（vendor v3）自带 `-r junit/xml/json` reporter（`catch2_impl.cpp:3282`），**EZMK 内置框架**（`build.cpp:2201-2315`，逐文件编译+链接+运行）没有任何 reporter 概念——报告出口必须两路对称。

**定位**：本版只做**发射**（机器可读报告写文件，交给已有仪表盘/CI 渲染），**不做**任何 UI/历史/图表——后者是 non-goals「原生单元测试仪表盘」条款拒绝的形态 A/B（见 [`docs/zh/non-goals.md`](../../docs/zh/non-goals.md)）；本版是替代方案里的**形态 C**。与 1.2.0-dev.11 删除的 `parse_catch2_xml`（摄入/解析）方向相反，不冲突。

## 3 详细设计

### 3.1 CLI 与输出路径

```
ezmk test --report junit[:<path>]
```

- 格式：`junit`（主格式，GitHub Actions / GitLab / Jenkins 原生摄入）；`<path>` 可选，缺省 `<proj_root>/.ezmk/test-results/junit.xml`（项目级、可 gitignore，不污染 `build/`）。
- **Catch2 路径额外允许任意 Catch2 reporter 名**（`json`、`xml`、`sonarqube`…）：透传 `-r <fmt>::out=<file>`（vendor 自带，零成本）；EZMK 框架仅支持 `junit`（`json` 等报"not supported"提示用 Catch2 框架）——文档写明差异，避免"换框架丢格式"的隐形陷阱（坑 3）。
- 仅 CLI flag，**不加 `[test]` 配置字段**（本版最小面；CI 命令里写 flag 即可）。
- 失败门禁不变：报告是附加产物，`ezmk test` 退出码语义（`test_failed` fatal）不动。

### 3.2 Catch2 路径（≈10 行）

- `test_cmd`（`build.cpp:2091-2096`，现有 `"<runner>" "<filter>"`）追加 `-r junit::out="<file>"`（路径经 `escape_shell_arg`）。
- **控制台 reporter 保持默认**（不写 stdout）→ 现有摘要解析（`:2099-2172`）与退出码门禁零回归。
- `--filter` 与 `--report` 可组合；报告只含过滤后用例（Catch2 语义，文档注明）。

### 3.3 EZMK 框架路径（≈50-80 行）

- 循环（`build.cpp:2212-2296`）已有每测试文件的：文件名、耗时（`elapsed`）、PASS/FAIL/TIMEOUT（`passed`/`failed`/`timed_out` 计数）、编译失败/链接失败分支。
- 汇总后生成 JUnit XML：
  - `<testsuites>` → 每个测试文件一个 `<testsuite name="<fname>" tests time="...">`；
  - 失败/超时用例加 `<failure message="...">`（含 stdout/stderr 摘要，**截断**防超长）；
  - 编译/链接失败 → 该文件标记 `<error>`（与 `<failure>` 语义区分）。
- **XML 转义**（`& < > " '`）：输出内容可能含用户打印文本（stdout/stderr），必须全量转义（对齐 1.1.2 C5 转义经验；坑 2）。
- 写文件：temp → rename 原子写（对齐 cache/record.json 惯例）。

### 3.4 workspace 透传（P1）

- `ezmk workspace test`（1.3.0）成员子进程模型天然透传 test-opts；`--report` 跟随透传，每成员写自己的 `.ezmk/test-results/junit.xml`。
- 成员失败汇总语义不变（报告是附加产物，不改变成员退出码/汇总逻辑）。

### 3.5 已知坑位与对策

| # | 坑 | 优先级 | 对策 | 落点 |
|---|-----|--------|------|------|
| 1 | `-r junit` 打到 stdout → 盖掉现有摘要文本解析 | 高 | 必须 `out=<file>` 写文件；单测断言 stdout 摘要仍在 | §3.2 |
| 2 | EZMK 输出含 `&`/`<`/`>` 等 → XML 非法 | 高 | 全量 XML 转义（含 stdout/stderr 截断内容） | §3.3 |
| 3 | 两框架不对称（EZMK 无 reporter）→ 换框架丢报告 | 高 | EZMK 最小发射器必须一起交付；`json` 等格式在 EZMK 下显式提示用 Catch2 | §3.1 |
| 4 | 报告路径/内容含空格引号 → shell 注入面 | 中 | 路径 `escape_shell_arg`；内容仅转义不执行（无 shell 面） | §3.2/§3.3 |
| 5 | 超长失败输出撑爆 XML | 中 | stdout/stderr 摘要截断（如 4KB/条） | §3.3 |

## 6 跨版本关注点

- **与 1.3.1 相互独立**：1.3.1（语言区间）/ 1.3.2（测试报告）均为 1.3.x 稳定线补丁，代码路径不相交，可并行推进；发布顺序按各自完成度。
- **与 non-goals「原生单元测试仪表盘」条款互补**：条款拒绝形态 A/B（TUI/Web 仪表盘），替代方案点名本版形态 C（`ezmk test --report junit`）——文档与实现互相引用，用户不会为一个永远不会来的特性等待。
- **与 1.2.0-dev.11 删 `parse_catch2_xml` 的关系**：本版是**发射**（外部消费），删除的是**摄入**（内部解析）——方向相反，不冲突；EazyMake 依然不解析报告。
- **CI 步骤**：ubuntu job 追加 `ezmk test --report junit` + 文件存在/含 `<testsuite>` 断言（对齐 dev.3 的 workspace 冒烟步骤惯例）。
- **回归基线**：全量 863 用例 / 5007 断言（1.3.0-dev.5 后基线），新增功能不得引入回归。
- **i18n**：新增 key（如 `cli_err_invalid_report`）三向一致（`.def` + en/zh JSON + 重新生成 `locale_data.cpp`），`check_i18n.py` 通过。
- **后续窗口**：`[test]` 配置字段（声明式报告路径）、EZMK 侧 JSON 格式、耗时历史/对比——归 1.4.0 或后续评估；形态 A/B 明确 non-goal。
