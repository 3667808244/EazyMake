# EazyMake 1.3.3 — workspace 双字母命令简写

> 1.3.0 正式发布后的**补丁版本**（与 1.3.1 语言区间、1.3.2 测试报告相互独立，可并行）。发布总览见 [`1.3.x/README.md`](README.md)。

---

## 1 背景

0.2.6 起 `kAliases` 表（[`src/cli.cpp`](../../src/cli.cpp) `:967-992`）为 **project / pkg / repo** 提供双字母简写（`pb` / `ki` / `ra`…），单字母 `u` / `h` / `v` 覆盖 utils / help / version。1.3.0 新增 **`workspace` 命令组**（`list` / `build` / `test` / `clean`，`cli.cpp:791-808`）却**没有**对应简写——与其他命令组不一致：想打 `ezmk workspace build` 只能全拼，或绕道 `ezmk build -w`（`-w` 重定向 flag 挂在 project 命令上，`cli.cpp:107/243/312/477`），需要先记住"project 命令 + `-w`"这个间接形态。

1.2.3 的 `example` 命令组同样无简写——**不在本版范围**（见 §6）。

## 2 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | `wl` / `wb` / `wt` / `wc` → `workspace list / build / test / clean`（`kAliases` 加 4 行） | P0 |
| 2 | 无冲突：`kAliases` 现有键无任何 `w*` 占用；与 `pw`（project watch）首字母不同、与 `-w` flag 语义正交 | P0 |
| 3 | 单测（`test/test_cli.cpp`）：展开断言 + **命令位置限定**（`ezmk workspace wb` 仍报未知子命令）+ `--verbose` 展开记录 | P0 |
| 4 | 文档：cli.md（en/zh）简写说明 + CHANGES.md 1.3.3 条目 | P1 |
| 5 | 刻意不做：`completions/_ezmk` 加简写（与 p/k/r 一致的既有设计决定）；`w` **单字母**（workspace 有子命令，单字母歧义，与 `u`/`h`/`v` 的"组即命令"模式不同）；**`example` 组简写（明确不做**——低频/一次性命令，`e`/`ex` 形态易与 shell 常见命令混淆，见 §3.5） | P0 |

## 3 详细设计

### 3.1 简写命名

沿用「组首字母 + 子命令首字母」规则（p/k/r 同款）：

| 简写 | 展开 |
|------|------|
| `wl` | `workspace list` |
| `wb` | `workspace build` |
| `wt` | `workspace test` |
| `wc` | `workspace clean` |

**冲突核查**（`kAliases` 全表 `cli.cpp:967-992`）：无任何 `w*` 键；`wt` 与 `pt`（project test）组字母不同不冲突；`-w` 是 project `build/test/clean` 的**参数位 flag**（重定向到 workspace 命令组），与命令位置的 `w*` 简写正交——`ezmk wb` 展开为 `ezmk workspace build` 后即进入 workspace 解析器，不再需要（也不接受）`-w`。

### 3.2 实现

- `src/cli.cpp` `kAliases`（`:979-991` 区域）追加 4 行：`{"wl", {"workspace", "list"}}` 等；
- 展开逻辑（`:994-1009`）**零改动**——泛化处理 `second` 为子命令；下游 `Command::Workspace*` 分发（`:1074-1076`）与 `shorthand_expansion` 展示（`--verbose` 输出 `wb → workspace build`）自动生效。

### 3.3 测试（`test/test_cli.cpp`）

- 4 个展开断言：`wl`/`wb`/`wt`/`wc` → `Command::WorkspaceList/Build/Test/Clean`；
- 命令位置限定：`ezmk workspace wb` → 未知子命令错误（沿用 1.3.0 的 `cli_err_unknown_subcommand` 路径，`cli.cpp:822` 附近）；
- `--verbose` 展开记录含 `wb → workspace build`；
- 回归：既有 p/k/r/u/h/v 简写断言不变（确认无键冲突）。

### 3.4 文档与 i18n

- `docs/en/cli.md` / `docs/zh/cli.md`：命令简写说明补 workspace 4 个（现状只描述 p/k/r 简写）；
- CHANGES.md 1.3.3 条目；
- **无新 i18n key**（全部复用既有错误消息）——`.def`/JSON/`locale_data.cpp` 零改动。

### 3.5 决策记录：`example` 组明确不做简写

`example`（1.2.3）命令组**不引入**任何单/双字母简写，且**不留后续评估**——这是定死的边界：

- **低频/一次性**：`example list` + 按名拉取示例模板，是"用过即走"的命令；简写服务的是高频操作（build/test/install/watch…）；
- **形态易混淆**：`e` / `ex` 与 shell 常见命令（`exit`、可执行文件扩展名）易误触/误读，占用键位收益为负；
- **与 `u`/`h`/`v` 模式不同**：单字母简写只给"组即命令"的顶层命令（utils/help/version），不扩展到命令组。

## 5 兼容性

| 变更 | 影响 | 处理 |
|------|------|------|
| `wl`/`wb`/`wt`/`wc` 新简写 | 纯新增 | `kAliases` 无 `w*` 键，零冲突 |
| `ezmk workspace wb`（组内位置） | 行为不变 | 仍报未知子命令（简写只在命令位置生效） |
| `-w` flag | 不受影响 | 参数位 flag 与命令位置简写正交 |
| `completions/_ezmk` | 不加 | 与既有简写设计决定一致（刻意不补全简写） |
| 公共 API | 无破坏性变更 | 纯增量 |

## 6 跨版本关注点

- **与 1.3.1 / 1.3.2 相互独立**：三个补丁代码路径不相交（config/pkg/cache vs test 报告 vs cli 别名），可并行推进；发布顺序按各自完成度。
- **`example` 组简写明确不做**（§3.5 决策记录）：低频一次性命令 + `e`/`ex` 形态易混淆，不占用键位、不留后续评估。
- **`w` 单字母不引入**：workspace 有 4 个子命令，单字母无法表达（区别于 `u`/`h`/`v` 的"组即命令"模式）；用户可打 `ezmk w` + 补全/`--help` 查看子命令。
- **回归基线**：全量 863 用例 / 5007 断言（1.3.0-dev.5 后基线）。
- **i18n**：无新 key，三向一致性零风险。
- **后续窗口**：`-w` 与 `w*` 简写组合的文档示例、`example` 组简写——归 1.4.0 或后续评估。
