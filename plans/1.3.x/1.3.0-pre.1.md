## 3 详细设计

### 3.1 `docs/cli.md` workspace 命令组节（zh/en，中文基准先行）

`docs/zh/cli.md` 新增 `## Workspace（工作区）` 节，随后同步 `docs/en/cli.md`。结构：

| 小节 | 内容 |
|------|------|
| 命令表 | `ezmk workspace list` / `build` / `test` / `clean`（顶层完整形式）+ 各自参数与默认值 |
| `-w` / `--workspace` 重定向 | `ezmk build -w` ≡ `ezmk workspace build`；**非**「项目 + workspace 叠加」（坑 4 锁定，配 help 文本一致） |
| `--member <name>` | 目标成员 + **依赖闭包**（坑 2 锁定）；只构建单成员 → `cd <member> && ezmk build`（注入已存在产物、不触发闭包构建） |
| `--stop-on-error` | 失败后**停派发**（本层未启动 + 后续层 skipped）、在跑成员自然结束不 kill；`clean` 不支持（坑 3 锁定） |
| `-j` / `--jobs` | 优先级：显式 `-j` > `[workspace.options].default_jobs` > 硬件并发 |
| 兄弟产物注入 | 成员 `[depends] workspace` → 自发现注入 `-I <ws>/<m>/include` + `-L <ws>/<m>/build -l<m>`；**零环境变量**（坑 1 锁定）；成员 `ezmk.toml` 零改动 |
| 纯容器根 | 有 `ezmk-workspace.toml` 无 `ezmk.toml` 的目录 `ezmk build` → 提示 `ezmk workspace build` |

### 3.2 `docs/cli.md` `EZMK_LANG` 变体说明更新（zh/en）

现状（`docs/zh/cli.md:346`）：`界面语言（zh / en），覆盖系统检测`。

更新为：

| 值 | 效果 |
|----|------|
| `en` / `zh`（基础语言） | 行为与 1.2.x 完全一致 |
| `zh-TW`（变体标签） | 命中 `locale/zh-TW.json` 繁体文案；未转写的键**继承 `zh`** |
| `zh-CN` / `zh_CN` / `zh_CN.UTF-8` | 归一化 → 命中 `zh`（简体） |
| 未设置 | 系统检测（Windows `GetUserDefaultLocaleName` / POSIX `$LANG`）同样走标签归一化，`zh-TW` 系统自动繁体 |

回退链：**变体 → 基础语言 → 英文兜底**，任一环节缺失静默降级，永不出现 `{???}`。

### 3.3 README 命令速览补 workspace（zh/en）

`README_ZH.md`「命令速览」节追加：

```
ezmk workspace list                  # 列出工作区成员
ezmk workspace build [-j N] [--stop-on-error] [--member <name>]  # 拓扑构建全部成员
ezmk workspace test  [-j N] [--stop-on-error] [--member <name>]  # 运行成员测试
ezmk workspace clean [--member <name>]                           # 清理成员缓存
```

（build/test/clean 附 `-w` 重定向；`README.md` 同步。）

### 3.4 教程新章：workspace 实战（zh/en）

`tutorial/zh/dev/05-workspace.md`（开发体验组追加，编号接续 04）+ `tutorial/en/dev/05-workspace.md`：

- 场景：共享基础库 `strutil` + 两个可执行文件 `tool-a` / `tool-b`（monorepo 最常见形态）
- 步骤：写 `ezmk-workspace.toml` → 成员声明 `[depends] workspace = ["strutil"]` → `workspace build -j` → 改库 `.cpp` 只重链 / 改库 `.h` 触发重编 → `workspace test` / `clean` → `--member` / `-w` / `--stop-on-error` 快速演示
- 易错点：`--member` 会带依赖闭包；`-w` 是重定向；兄弟产物缺失时先 `workspace build`
- 更新 `tutorial/zh|en/README.md` 索引（开发体验组 +1）

## 6 跨版本关注点

- **发布门槛**（⛔ 见 [`1.1.0-pre.3.md`](../1.1.x/1.1.0-pre.3.md)）：① 计划清单全部完成或明确收口 ② 公共 API 无破坏性变更 ③ 全量测试零回归（基线 863 / 5007，dev.5 后）——门槛未满足即停止，禁止带着未收口项进入正式发布。
- **语言基准**：全项目用户文档以**中文为基准**（docs/zh / README_ZH / tutorial/zh），英文为同步翻译；本计划所有交付遵循「先中文、后英文」。
- **坑位文档化是核心交付**：`--member` 闭包（坑 2）、`-w` 重定向（坑 4）、`--stop-on-error` 停派发（坑 3）、零环境变量注入与响应文件（坑 1）——四个最容易误解的语义必须在 cli.md 与教程里说透，防止用户误用。
- **与 dev.1 ~ dev.5 联动**：文档描述的是已实现且回归锁定的行为（workspace 命令组 / 注入 / i18n 变体 / 消费命令总是构建）；若核对发现文档与实现不符，先修实现还是修文档按「实现为准」裁定（实现已过全量回归）。
- **发布流水线**（winget/Homebrew/pacman）与 AUR 不在 pre.1 范围：需真实 Release 验证的项明确收口到**正式发布阶段**（workflow §3）；若 pre.1 收口后仍有多项未决，追加 pre.2 检查点（机制同 1.2.0）。
- **正式发布依赖本版**：1.3.0 聚合发布（版本置 1.3.0 + tag + Release + 三渠道分发）以 pre.1 全绿收口为前提。
