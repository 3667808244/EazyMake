## 3 详细设计

### 3.1 集成测试（`test/test_integration.cpp`，tag `[workspace][1.3.0]`）

**测试夹具**：临时目录构造 3 成员 workspace——
```
ws/
  ezmk-workspace.toml        # members = ["apps/tool-a", "apps/tool-b", "libs/strutil"]
  apps/tool-a/ezmk.toml + src/main.cpp   # executable，printf "tool-a"
  apps/tool-b/ezmk.toml + src/main.cpp   # executable
  libs/strutil/ezmk.toml + include/strutil.hpp + src/strutil.cpp  # static
```

**用例清单**：

| # | 用例 | 断言 |
|---|------|------|
| 1 | `ezmk workspace list` | 输出 3 成员 + 状态 ✓；退出码 0 |
| 2 | `ezmk workspace build -j 2` | 3 成员全部成功；各自 `build/` 产物落位（exe / libstrutil.a）；汇总 "3 succeeded"；退出码 0 |
| 3 | **增量隔离** | 改 `tool-a/src/main.cpp` → `workspace build`：仅 tool-a 重编（输出含 tool-a 编译、不含 tool-b/strutil 编译）；3 次全成功 |
| 4 | `ezmk workspace test` | 成员带 `[test]`（ezmk 框架，零依赖）→ 测试通过；无测试成员跳过（不报错） |
| 5 | `ezmk workspace clean` | 各成员 `build/` 移除；退出码 0 |
| 6 | **失败汇总** | 让 tool-b 源码故意编译失败 → `workspace build`：tool-b 失败、其余继续完成；汇总 "2 succeeded, 1 failed"；退出码非零 |
| 7 | `--stop-on-error` | 同上 + flag：tool-b 失败后剩余成员标记 skipped（汇总含 skipped）；退出码非零 |
| 8 | `--member` 子集 | `workspace build --member tool-a`：只构建 tool-a；`--member apps/tool-a` 等价；未知成员 → fatal |
| 9 | **路径逃逸拒绝** | `members = ["../outside"]` → 配置加载 fatal（含路径信息） |
| 10 | **依赖互引拒绝** | tool-a 的 `[depends] lib = ["strutil"]` → 配置加载 fatal（提示成员间依赖不被允许） |
| 11 | **嵌套拒绝** | libs/strutil 内含 `ezmk-workspace.toml` → 该成员 invalid；执行跳过 + list 标记 |
| 12 | **成员缺失 ezmk.toml** | members 含不存在目录 → invalid 标记 + 跳过，不阻断其他成员 |
| 13 | **顶层提示** | 纯容器根（仅 workspace 文件）`ezmk build` → fatal 提示用 `ezmk workspace build`；有 `ezmk.toml` 时行为不变 |

### 3.3 CI（`.github/workflows/ci.yml`）

ubuntu job 追加「workspace 冒烟」步骤（在示例自举验证后）：

```yaml
- name: Workspace smoke (1.3.0)
  run: |
    set -euo pipefail
    EZMK="$GITHUB_WORKSPACE/build/ezmk"
    cd "$RUNNER_TEMP"
    mkdir -p ws/apps/a ws/apps/b ws/libs/l
    printf '[workspace]\nmembers = ["apps/a", "apps/b", "libs/l"]\n' > ws/ezmk-workspace.toml
    # ... 写 3 个最小项目（ezmk.toml + src/main.cpp / 库）
    cd ws && "$EZMK" workspace list && "$EZMK" workspace build -j 3 && "$EZMK" workspace clean
```

> runner 干净环境，无仓库依赖（workspace 成员为本地最小项目）；`build` 用系统 g++。

## 6 跨版本关注点

- **pre.1 依赖本版**：文档与发布收口基于全绿基线。
- **测试的确定性**：并行测试避免依赖完成顺序——断言用「集合包含」而非顺序；`-j` 相关用例断言「并发发生」用耗时（串行 > 并行）但留宽松阈值避免 flaky。
- **失败注入**：编译失败用例用语法错误源码（确定失败），不用随机/环境依赖手段。
