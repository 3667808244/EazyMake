## 3 详细设计

### 3.1 集成测试（`test/test_integration.cpp`，tag `[workspace][1.3.0]`）

**测试夹具**：临时目录构造 3 成员 workspace，其中 tool-a / tool-b 依赖静态库 strutil：

```
ws/
  ezmk-workspace.toml        # members = ["apps/tool-a", "apps/tool-b", "libs/strutil"]
  apps/tool-a/ezmk.toml + src/main.cpp   # executable + [test]（ezmk 框架）；[depends] workspace = ["strutil"]
  apps/tool-b/ezmk.toml + src/main.cpp   # executable；[depends] workspace = ["strutil"]
  libs/strutil/ezmk.toml + include/strutil.hpp + src/strutil.cpp  # type = "static"
```

**用例清单**：

| # | 用例 | 断言 |
|---|------|------|
| 1 | `ezmk workspace list` | 输出 3 成员 + 状态 ✓ + ws_deps；退出码 0 |
| 2 | `ezmk workspace build -j 2` | 3 成员全部成功；各自 `build/` 产物落位（exe / libstrutil.a）；汇总 "3 succeeded"；退出码 0 |
| 3 | **依赖构建顺序** | strutil 的编译输出先于 tool-a/tool-b（捕获子进程输出顺序断言）；仅 tool-a 依赖时只 tool-a 依赖 strutil |
| 4 | **跨成员增量①：库 .cpp 变** | 改 `strutil/src/strutil.cpp` → `workspace build`：strutil 重编 + tool-a/tool-b **重新链接**（输出含 strutil 编译与两 exe 链接，不含两 app 的编译）；3 次全成功 |
| 5 | **跨成员增量②：库 .h 变** | 改 `strutil/include/strutil.hpp` → `workspace build`：strutil 重编 + tool-a/tool-b **重新编译**（依赖者 depfile 含注入 `-I` 的库头） |
| 6 | `ezmk workspace test` | tool-a 带 `[test]`（ezmk 框架，零依赖）→ 测试通过；tool-b/strutil 无测试跳过（不报错）；退出码 0 |
| 7 | `ezmk workspace clean` | 各成员 `build/` 移除；退出码 0 |
| 8 | **失败汇总** | 让 tool-b 源码故意编译失败 → `workspace build`：tool-b 失败、strutil 与 tool-a 继续完成；汇总 "2 succeeded, 1 failed"；退出码非零 |
| 9 | `--stop-on-error` | 同上 + flag：tool-b 失败后依赖它的成员/后续层标记 skipped（汇总含 skipped）；退出码非零 |
| 10 | `--member` 子集（含闭包） | `workspace build --member tool-a`：构建 tool-a **及其依赖 strutil**（strutil 先构建）；`--member apps/tool-a` 等价；未知成员 → fatal |
| 11 | **路径逃逸拒绝** | `members = ["../outside"]` → 配置加载 fatal（含路径信息） |
| 12 | **环拒绝** | tool-a `[depends] workspace = ["strutil"]` 且 strutil `[depends] workspace = ["tool-a"]` → 配置加载 fatal（含环路径） |
| 13 | **非 static 被依赖拒绝** | tool-a 依赖 type=executable 的 tool-b → 配置加载 fatal（提示被依赖须为 static） |
| 14 | **嵌套拒绝** | libs/strutil 内含 `ezmk-workspace.toml` → 该成员 invalid；执行跳过 + list 标记 |
| 15 | **成员缺失 ezmk.toml** | members 含不存在目录 → invalid 标记 + 跳过，不阻断其他成员 |
| 16 | **顶层提示** | 纯容器根（仅 workspace 文件）`ezmk build` → fatal 提示用 `ezmk workspace build`；有 `ezmk.toml` 时行为不变 |

### 3.3 CI（`.github/workflows/ci.yml`）

ubuntu job 追加「workspace 冒烟」步骤（在示例自举验证后）：

```yaml
- name: Workspace smoke (1.3.0)
  run: |
    set -euo pipefail
    EZMK="$GITHUB_WORKSPACE/build/ezmk"
    cd "$RUNNER_TEMP"
    mkdir -p ws/apps/a ws/apps/b ws/libs/l
    printf '[workspace]\nmembers = ["apps/a", "apps/b", "libs/l"]\n' > ws/ezmk-workspace.toml
    # libs/l: type=static + include/l.hpp + src/l.cpp
    # apps/a, apps/b: [depends] workspace = ["l"] + src/main.cpp 调用 l.hpp
    cd ws && "$EZMK" workspace list && "$EZMK" workspace build -j 3 \
      && "$EZMK" workspace build -j 3   # 二次构建验证增量：0 重编
    test -f apps/a/build/a.exe -o -f apps/a/build/a   # 产物落位（win/linux 二选一）
    "$EZMK" workspace clean
```

> runner 干净环境，无仓库依赖（workspace 成员为本地最小项目）；`build` 用系统 g++。二次构建验证跨成员增量（库与依赖者均不重编）。

## 6 跨版本关注点

- **pre.1 依赖本版**：文档与发布收口基于全绿基线。
- **测试的确定性**：并行测试避免依赖完成顺序——断言用「集合包含」而非顺序；依赖顺序用例用**捕获输出时间戳**而非 sleep；`-j` 相关用例断言「并发发生」用耗时（串行 > 并行）但留宽松阈值避免 flaky。
- **失败注入**：编译失败用例用语法错误源码（确定失败），不用随机/环境依赖手段。
- **跨成员增量是 1.3.0 的核心卖点**：用例 4/5 必须覆盖「库产物/头文件变化 → 依赖者自动重链/重编」，防止回归到「需要手动 clean」。
