# 1.3.x — 功能版本系列（Workspace 工作区）

> 1.3.x 系列 = **1.3.0 功能版本**（dev.1 ~ dev.3 + pre.1，规划中）+ 后续补丁（如有）。
>
> 本目录为 1.3.x 全部文档的**平铺结构**（无子文件夹）：`1.3.0-dev.N.md` 为开发子版本，`1.3.0-pre.N.md` 为发布前收口，`1.3.0.md` 为正式版聚合。

## 定位

1.3.0 是 1.2.x 收官后的**首个功能 minor**（延续 1.0.0 → 1.1.0 → 1.2.0 的节奏）：新增 **Workspace（工作区）** 功能——一个目录下**若干编译期互不依赖的独立项目集合**，提供统一、可并行的批量管理（build / test / clean / cc）。**纯增量：新命令组 + 新配置文件 `ezmk-workspace.toml`，公共 API 零破坏**（破坏性变更仍仅归 2.0.0）。

## 版本规划（dev / pre 拆分）

> 1.3.0 正式版按 dev → pre 两个阶段推进：dev 落地功能，pre 做文档/门槛收口，最后聚合发布。

### 依赖关系

```
1.2.4 (已发布) ──→ 1.3.0-dev.1 (配置/定位) ──→ 1.3.0-dev.2 (命令/并行)
                      └──────────────┬──────────→ 1.3.0-dev.3 (测试/CI)
                                     └──────────→ 1.3.0-pre.1 (文档收口) ──→ 1.3.0 (发布)
```

- dev.1 → dev.2 顺序依赖（命令消费配置解析与定位）。
- dev.2 → dev.3 顺序依赖（集成测试覆盖命令行为）。
- pre.1 依赖全部 dev 完成。
- 与 **2.0.0 解耦**：workspace 纯增量，不依赖任何 deprecation 到期；2.0.0 保持破坏性变更窗口定位。

## 跨版本关注点

- **纯增量兼容**：新命令组 + 新配置文件，不触碰单项目路径（`project`/`pkg`/`repo`/`example` 全部不变）；既有 `ezmk.toml` 零影响。
- **回归基线**：当前全量测试 793 用例 / 3755 断言（1.2.4 后），新增功能不得引入回归。
- **并行模型**：跨成员并行复用线程池思路，成员内 `-j` 并行不变；输出加成员前缀防交错。
- **安全**：成员路径逃逸（`../` / 绝对 / 盘符 / 符号链接出根）与「成员间 `[depends]` 互引」在配置校验期拒绝——前者是路径安全，后者是「编译期无依赖 = 可并行」的保证。
- **i18n**：新增 `workspace_*` key（X-macro 三向一致，`check_i18n.py` 通过）。
