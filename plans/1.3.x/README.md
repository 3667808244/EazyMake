# 1.3.x — 功能版本系列（Workspace 工作区）

> 1.3.x 系列 = **1.3.0 功能版本**（dev.1 ~ dev.5 + pre.1，已发布 ✅）+ **1.3.1 补丁**（区间语言标准与包/消费者标准兼容校验，✅ 已完成 2026-08-24）+ **1.3.2 补丁**（单元测试机器可读报告，规划中）+ **1.3.3 补丁**（workspace 双字母命令简写，规划中）+ **1.3.4 补丁**（watch 重建后自动运行，规划中）+ **1.3.5 补丁**（pack 多格式输出，规划中）。
>
> 本目录为 1.3.x 全部文档的**平铺结构**（无子文件夹）：`1.3.0-dev.N.md` 为开发子版本，`1.3.0-pre.N.md` 为发布前收口，`1.3.0.md` 为正式版聚合，`1.3.1.md` ~ `1.3.5.md` 为补丁。

## 定位

1.3.0 是 1.2.x 收官后的**首个功能 minor**（延续 1.0.0 → 1.1.0 → 1.2.0 的节奏）：新增 **Workspace（工作区）** 功能——一个目录下若干独立项目（成员）的集合，提供统一、可并行的批量管理（build / test / clean）。成员间可声明**单向非循环依赖**（最常见 monorepo 形态：共享基础库 + 多个可执行文件），构建时**拓扑排序 + 产物复用**（改库 `.cpp` → 消费者只重链接，消灭重复编译）。**纯增量：新命令组 + 新配置文件 `ezmk-workspace.toml` + `[depends] workspace` 新字段，公共 API 零破坏**（破坏性变更仍仅归 2.0.0）。同系列附带 **i18n 语言变体**（dev.4，`zh-TW` 繁体等，继承式变体文件）与**消费命令总是自动构建**（dev.5，`test`/`pack --precompiled` 消除陈旧产物陷阱）。

## 跨版本关注点

- **纯增量兼容**：新命令组 + 新配置文件 + `[depends] workspace` 新字段，不触碰单项目路径（`project`/`pkg`/`repo`/`example` 全部不变）；既有 `ezmk.toml` 零影响。
- **回归基线**：当前全量测试 822 用例 / 3922 断言（1.3.0-dev.1 后），新增功能不得引入回归。
- **并行模型**：跨成员并行按**拓扑层**（依赖层先构建，同层并行，复用线程池思路）；成员内 `-j` 并行不变；输出加成员前缀防交错；`--stop-on-error` = 失败后停派发（后续层 skipped）、不 kill 在跑成员。
- **注入与命令行长度**：兄弟产物注入走**成员自发现**（零环境变量，长度与规模无关）；编译/链接命令 >16K 走 GCC 响应文件兜底——大型项目不炸（坑 1）。
- **依赖约束**：成员依赖仅允许**单向非循环**——环（含自环）与「被依赖成员非 static」在配置校验期 fail-fast；完整构建图（版本 / 平台矩阵 / 可编程图）仍归 non-goals。
- **安全**：成员路径逃逸（`../` / 绝对 / 盘符 / 符号链接出根）在配置校验期拒绝。
- **i18n**：新增 `workspace_*` key（X-macro 三向一致，`check_i18n.py` 通过）；**语言变体**（dev.4）——BCP 47 标签归一化 + 继承式变体文件 + 回退链（变体 → 基础 → 英文），新键在变体文件未转写时自动回退，永不出现 `{???}`。
- **消费命令一致性**（dev.5）：所有消费构建产物的命令统一「先增量构建再消费」——`run`/`install`/`watch`/`test`/`pack --precompiled`；`pack` 源码包与 `cc`/`export`/`import`/`clean` 不消费产物，维持现状。增量缓存保证新鲜产物时开销趋近于零。

## 1.3.1 — 补丁（区间语言标准 + 包/消费者标准兼容校验）

1.3.1 为 **1.3.x 稳定线的补丁发布**：`[project].language` 支持区间语法（`">=C++11"` 单边下界、`"C++11..C++17"` 双边区间），让库作者能声明"最低兼容标准"（如 C++11 基础接口 + C++17 拓展接口，头文件 `#if __cplusplus` 条件编译）；安装期新增**标准兼容校验**（包 min > 消费者 min → 警告，防预编译库 ABI 断裂）；顺带修复 CMake 导出的裸数字提取 bug（`"CPP11..C++17"` → `CXX_STANDARD 1117`）。**语义 = 元数据 + 校验（A）**：编译仍用单一精确标准（取 min），编译协商与工具链能力表（语义 B/C）**预留 1.4.0**。纯增量，公共 API 无破坏性变更。

## 1.3.4 — 补丁（watch 重建后自动运行）

1.3.4 为 **1.3.x 稳定线的补丁发布**：`ezmk watch --run` / `-r` —— 每次**成功**重建后阻塞运行产物，程序退出后 watch 继续监听（"改代码自动重跑"）。复用 `build_project()` 返回的 exe 路径（`project run` 同款）与阻塞 `run_command`：watcher 线程阻塞 = 程序运行期间天然暂停变更检测，无需进程管理。仅 `executable` 项目（其余类型 + `--run` → 启动 fatal）；构建失败不运行；程序非零退出 → 警告不退出 watch；**无 `--run` 时默认行为完全不变**。拒绝形态（kill-重启 / detached 启动 / 缓存命中才运行）为定死边界。与 1.3.1 / 1.3.2 / 1.3.3 相互独立，可并行。

## 1.3.5 — 补丁（pack 多格式输出）

1.3.5 为 **1.3.x 稳定线的补丁发布**：`ezmk project pack --format zip|tar.gz`（缺省 tar.gz，默认行为不变）——`extract_archive` 早已支持 zip（miniz vendored），消费 zip 可用而产出 zip 是缺口；zip 与 tar.gz **逐文件等价**（同一 stage 流程，仅归档器不同），`pkg install` 端到端闭环。附带 `.sha256` 边车（两种格式统一，P1）。**明确不做**：`.deb` / `.rpm` 等包管理器格式（fpm 配方覆盖）、发布自动化。与 1.3.1 ~ 1.3.4 相互独立，可并行。
