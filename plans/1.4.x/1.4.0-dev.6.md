# EazyMake 1.4.0-dev.6 — 代码质量审计（全量）

> 1.4.0 第六个开发子版本。总览见 [`1.4.x/README.md`](README.md)。

---

## 1 背景

dev.5 收口后对**当前使用的全部代码**做了一次系统审计（8 路并行审查覆盖 ~19k 行核心代码 + include + test），发现并修复了一批**正确性缺陷（P0）与健壮性问题（P1）**。这些缺陷多为历史遗留（1.1.0 确定性构建、1.2.x 测试/包路径、1.4.0-dev.2 MSVC 能力表等后来新增代码），且多数**静默出错**（缓存永久失效、非英文系统探测失败、锁文件被静默改写）——无报错、无回归测试锁定，是最危险的一类。

## 2 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | `-Wall -Wextra` 严格编译零警告 | P0 |
| 2 | 修复全部 P0 正确性缺陷（8 项：缓存签名/路径穿越/锁版本/命令注入/本地化解析/括号注释/Lua 根路径） | P0 |
| 3 | 修复高价值 P1 健壮性问题（句柄泄漏/崩溃路径/写失败静默/配置类型误判等） | P1 |
| 4 | 修复测试套件 P0（4 个恒真/无断言测试）+ dev.5 新测试的脆弱点（进程泄漏/空转断言/假优先级） | P0/P1 |
| 5 | 全量零回归 + 记录未修 P2 延后项 | P0 |

## 3 详细设计

### 3.1 审计方法

- 8 路并行子代理审查：build/cache · pkg/repo/lockfile · cli/config/toolchain · util/file_watcher/crypto · export/import/compile_db · workspace · i18n/lua/main · test 套件
- 关键结论**实证复核**（非仅代码阅读）：MSVC cl 横幅本地化（zh-CN 实机验证）、vswhere BuildTools 探测、CMake 括号注释语义、`fs::relative` 跨盘符行为、Catch2 SECTION 重跑语义
- 结论按 P0（正确性）/ P1（健壮性）/ P2（风格/死代码）分级，修复 P0/P1，P2 记录延后

## 5 兼容性

| 变更 | 影响 | 处理 |
|------|------|------|
| 确定性构建缓存签名含 lock 哈希 | 行为修复 | 缓存键变化 → deterministic 项目首次构建重编一次后恢复正常增量；非确定性无影响 |
| `--locked` 锁版本 + 不重写 lockfile | 行为收紧 | 与文档契约一致；锁文件无该包记录/版本不可得 → 新错误信息 |
| repo 名安全校验 | 行为收紧 | 恶意/非法 repo 名被拒；Windows 本地路径名提取修复配套 |
| config 非数组字段报错 | 行为收紧 | 此前静默空值 → 显式报错（`flags = "-Wall"` 这类拼写错误不再无声失效） |
| MSVC 版本解析语言无关 | 行为修复 | 非英文系统行为对齐英文系统；英文系统结果不变 |
| 公共 API | **无破坏性变更** | 纯修复 + 新 i18n 键（`lock_locked_pkg_not_in_lockfile` / `lock_locked_version_unavailable` / `config_err_array_field_type`） |

## 6 跨版本关注点

- **未修 P2 延后项**（记录在案，随 1.4.0 后续 dev/pre 或 1.5.x）：
  - 跨盘符 `fs::relative` 空路径 → cache 键碰撞 + 对象覆盖（Windows 绝对 src_dirs 指向其他盘符）
  - 测试链接缺依赖包归档/链接参数（`run_tests` 未复用 `prepare_build_state` 的 pkg_archives 等）
  - `ezmk test --profile` 未转发内层 `build_project`
  - `extract_zip` 无解压总大小上限（zip-bomb 防护不一致）
  - `extract_targz` 不校验 gzip footer CRC32/ISIZE
  - watcher 事件风暴（ERROR_NOTIFY_ENUM_DIR）退出 + 关闭期 OVERLAPPED 竞态
  - `lua_to_json` 循环表无界递归 → C 栈溢出崩溃
  - export C 侧 `std_capability_note` 用 C++ 能力表比较
  - import `add_library` 无类型形态误判 + 内联源文件不收集
  - export 生成 CMake 字面路径/名称不引号化（含空格路径）
  - `load_msvc_env` 死代码、`FlagMapEntry::is_prefix` 未用、多组重复逻辑/死 i18n 键
  - Lua API 参数错误硬编码英文（`lua_api_*` 死键）
  - `lua_setupvalue` 返回值忽略、`g_current_script_pkg_root` 运行后不恢复
  - watch 回调不做文件类型过滤（README/docs 变更触发整库重建）、`main.cpp:399` 同名 ezmk.toml 误判
  - `project.cpp` 脚手架写失败静默吞掉
- **回归基线**：全量 968 用例 / 5612 断言（dev.6 后实测），新增功能不得引入回归。
- **与 2.0.0 解耦**：本版纯修复，公共 API 无破坏性变更。
