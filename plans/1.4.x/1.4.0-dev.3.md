# EazyMake 1.4.0-dev.3 — 编译协商（语义 B）

> 1.4.0 第三个开发子版本。总览见 [`1.4.x/README.md`](README.md)。

---

## 1 背景

1.3.1 定死语义 A：**包按自己的 `language` 独立编译**（min），消费者按其 `language` 编译——两者从不协商。预编译库的 ABI 断裂风险（`std::__cxx11`）靠 1.3.1 的 warn 缓解，但源码包与消费者标准不一致时（包 C++11、消费者 C++17），包仍按 C++11 编译——**浪费**（消费者已具备更高标准）且**不能**利用更高标准。本版实现**语义 B：编译协商**——包按 `max(包min, 消费者标准)` 重编，前提是能力表（dev.2）确认该标准被编译器支持。

## 2 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | `compile_package()` 接受"协商标准"：包按 `max(包min, 消费者min)` 编译（cap 到 `max_supported_std`） | P0 |
| 2 | 消费者标准传入路径：`compile_package` 调用点（`pkg.cpp:754` 等）从 `consumer_std_min()` 取协商标准 | P0 |
| 3 | 协商标准 < 包 max（双边区间上界）时不触发（包声明 `C++11..C++17`、协商到 C++17 时用 C++17） | P0 |
| 4 | 缓存语义：协商标准变化 → `compile_options_signature` 变（std_flag 已参与签名，天然失效） | P0 |
| 5 | 1.3.1 的 warn 校验与协商**共存**：协商后仍校验（协商值 ≥ 包 min，通常不再 warn；包 min > 消费者能力时才 warn/fatal） | P1 |
| 6 | 测试：协商后按 max 编译（断言 `-std=`）+ 能力 cap + 缓存失效 + warn 共存 | P0 |

## 3 详细设计

### 3.1 协商公式

```
effective_pkg_std = min( max(包min, 消费者min), max_supported_std(family, version) )
```

- 无消费者项目（全局/用户级安装）→ 包按自身 min（现状）
- 消费者标准超包区间上界：**不协商超过 max**（上界是元数据承诺，超上界行为未验证——1.3.1 语义 A 保留：编译仍取"协商后的有效值"，但 ≤ 包 max）
- 协商结果低于包 min（消费者能力不足）→ 不协商，按包 min（1.3.1 warn 继续）

### 3.2 实现（`src/pkg.cpp`）

- `compile_package()` 内：`std::string effective = negotiated_std(cfg.project.language, consumer_min, tc)`（新 helper，dev.2 能力表支撑）
- 用 effective 构造编译输入（替换 `cfg.project.language` 解析出的 `LanguageInfo` 的 `std_flag`/`min_ver`）
- `check_std_compat()` 保留在协商前（1.3.1 语义），协商后不再重复 warn（协商值 ≥ 包 min）

### 3.3 缓存与共享语义（坑）

- `compile_options_signature` 已含 `std_flag` → 协商值变化自动失效 ✓（1.3.1 设计预留）
- **共享缓存注意**：同一包在不同消费者下编译产物不同（协商值不同）→ 包缓存 `.pkg_cache.json` 的签名已区分，但**安装目录共享**（同一 scope 下多次安装覆盖）——文档注明"同一 scope 内协商值一致才复用缓存"
- 预编译包不参与协商（无编译；ABI 由发布方决定）——1.3.1 的 precompiled warn 逻辑不变

### 3.4 已知坑位与对策

| # | 坑 | 优先级 | 对策 | 落点 |
|---|-----|--------|------|------|
| 1 | 协商值超包 max（上界语义被破坏） | 高 | 协商 cap 到包 max；文档明确上界为承诺边界 | §3.1 |
| 2 | 协商破坏"包独立编译"可复现性 | 高 | 缓存签名区分 + 文档注明；`--locked`/确定性构建下协商值固定（消费者标准确定） | §3.3 |
| 3 | 能力表误判导致协商失败 | 中 | dev.2 保守默认 + cap；协商失败回退包 min + warn | §3.1 |
| 4 | 消费者标准非法 | 低 | `consumer_std_min()` 现有容错（nullopt → 不协商） | §3.2 |

## 5 兼容性

| 变更 | 影响 | 处理 |
|------|------|------|
| 包编译标准从 min → max(包min, 消费者min) | 行为增强 | 仅消费者标准更高时改变；单消费者/无消费者不变 |
| 协商值参与缓存签名 | 自动失效 | 既有签名机制，零代码改动 |
| 预编译包 | 不参与 | 无编译，逻辑不变 |
| 公共 API | 无破坏性变更 | 纯增量（内部协商） |

## 6 跨版本关注点

- **依赖 dev.2**：协商需能力表 cap；dev.2 未完成时协商退化为"取 max 不 cap"（文档注明顺序）。
- **1.3.1 语义 A 为基线**：本版扩展而非替换；区间上界/元数据语义不变。
- **后续窗口**：语义 C（"支持多高用多高"自动协商到能力上限）、`[test]` 场景协商（测试编译用消费者标准）——1.4.0 后续或 1.5.x。
