# EazyMake 1.4.0-dev.5 — 功能收口（1.3.x 延后项）

> 1.4.0 第五个开发子版本。总览见 [`1.4.x/README.md`](README.md)。

---

## 1 背景

1.3.x 各补丁把一批"小而独立"的功能项明确延后到 1.4.0。本版集中收口（每项独立、风险低、互不依赖）：

| 来源 | 延后项 |
|------|--------|
| 1.3.4 | `watch --run` 的 `--` 参数透传 |
| 1.3.0 | `workspace watch` 命令组（`-w` 目前只重定向 build/test/clean） |
| 1.3.5 | `--format tgz` 别名（tar.gz 的简写） |
| 1.3.5 | sha256 边车纳入 `pkg install --sha256` 自动校验（与 index.toml 联动） |

## 2 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | `ezmk watch --run -- <args>`：透传参数给被运行产物（复用 `run_executable` 的 args 通道） | P0 |
| 2 | `ezmk workspace watch [--member ...]`：成员级 watch（复用 workspace 定位 + watch 语义；`-w` 重定向扩展到 watch） | P0 |
| 3 | `--format tgz` 别名 = `tar.gz`（大小写不敏感，归一化） | P0 |
| 4 | `pkg install <pkg>.tar.gz` 时自动读取同目录 `.sha256` 边车校验（无 `--sha256` 时）；index.toml `sha256` 字段联动（已有） | P0 |
| 5 | 测试：四类各独立用例 + 全量回归 | P0 |

## 3 详细设计

### 3.1 `watch --run -- <args>`（`src/main.cpp`）

- watch spec 现 `reject_positionals`；改为允许 `--` 后透传（对齐 `project run` 的 `program_args` 通道）
- `run_watched_exe` → `run_executable(exe, watch_program_args, true)`（1.3.6 已建通道，仅接线）

### 3.2 `workspace watch`（`src/workspace_build.cpp` + `src/cli.cpp`）

- `kAliases` 加 `ww`（可选，workspace 简写族一致）；`workspace_cmd_spec` 已含 watch 所需 flag（`-j`/`--member`）
- 语义：**成员级 watch**——每个成员跑 `ezmk watch`（子进程，复用 `run_member` 的 cwd 模型）；成员聚合输出带前缀（复用 `print_prefixed`）；`--stop-on-error` 语义沿用
- `-w` 重定向扩展到 `watch`（`ezmk watch -w` ≡ `ezmk workspace watch`）
- 边界：成员 watch 无 `--run` 透传（`workspace watch --run` 转发成员 `--run`；`--` 透传归成员级）

### 3.3 `--format tgz`（`src/cli.cpp`）

- 合法值集合：`tar.gz` / `tgz` / `zip`；`tgz` 归一化为 `tar.gz`（归档名仍 `name-version.tar.gz`）

### 3.4 sha256 边车自动校验（`src/pkg.cpp`）

- `install_package` 的本地归档路径：若 `expected_sha256` 为空且 `<archive>.sha256` 存在 → 读取并校验（格式 `<hash>  <filename>`，1.3.5 产出）
- 边车缺失/格式非法 → 现状（跳过校验，`pkg_sha256_skipped_dir` 类提示可复用）；不阻断
- URL 安装仍走显式 `--sha256`（不信任 URL 伴生边车）

### 3.5 已知坑位与对策

| # | 坑 | 优先级 | 对策 | 落点 |
|---|-----|--------|------|------|
| 1 | workspace watch 多成员并发冲突（共享 build 目录） | 高 | 成员互不依赖才并行（复用拓扑层）；同层依赖 watch 串行；文档注明 | §3.2 |
| 2 | `--` 透传与 watch flag 解析冲突 | 中 | `--` 终止符语义既有（`parse_options` 支持）；单测锁定 | §3.1 |
| 3 | 边车自动校验与显式 `--sha256` 冲突 | 低 | 显式优先；边车仅空 `--sha256` 时启用 | §3.4 |

## 5 兼容性

| 变更 | 影响 | 处理 |
|------|------|------|
| watch `--` 透传 | 纯新增 | 无 `--` 时不变 |
| `workspace watch` | 纯新增命令 | `-w` 重定向扩展（watch 此前无 `-w`） |
| `tgz` 别名 | 纯新增 | `tar.gz` 行为不变 |
| 边车自动校验 | 行为增强 | 仅边车存在且无显式 `--sha256` 时启用；失败不阻断 |
| 公共 API | 无破坏性变更 | 纯增量 |

## 6 跨版本关注点

- **独立于 dev.1~dev.4**：无能力表/协商依赖；可并行推进。
- **1.3.6 重构收益**：`run_executable`（1.3.6）为 watch 透传提供现成通道；`run_member` 为 workspace watch 提供成员子进程模型。
- **后续窗口**：`workspace watch --run` 的 `--` 成员级透传、watch 的 profile 热切换——1.4.0 后续或 1.5.x。
