# EazyMake 1.4.0-dev.4 — CMake 互操作补全

> 1.4.0 第四个开发子版本。总览见 [`1.4.x/README.md`](README.md)。

---

## 1 背景

CMake 互操作有两处 1.3.x 明确预留的缺口：

1. **导入（`src/import.cpp:446-447`）**：轻量解析器对 CMake `LANGUAGES CXX` 硬编码 `C++17`，**不读 `CXX_STANDARD`**（"至少 N"语义）——导入的项目语言标准丢失。
2. **导出**：`export cmake` 的 `CXX_STANDARD` 直接映射 ezmk min（1.3.1 修复后），但**未与能力表联动**（导出的标准可能超出目标工具链能力——不常见但语义上不完整）。

本版补全：导入读 `CXX_STANDARD` 并映射为 ezmk **区间**（`">=N"` 形式，语义 A 兼容）；导出在能力表就绪后确认/校正映射。

## 2 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | `import` 解析 `CXX_STANDARD N`（及 `C_STANDARD`）→ `[project].language = ">=CPP<N>"`（区间形式，语义 A） | P0 |
| 2 | `CXX_STANDARD_REQUIRED OFF` / `CXX_EXTENSIONS ON` → 保持精确值而非区间（扩展语义不同）或注释注明 | P1 |
| 3 | 缺省回退不变：无 `CXX_STANDARD` → 现状 `C++17`（文档注明"CMake 缺省下 ezmk 取 C++17"） | P0 |
| 4 | 导出：能力表（dev.2）就绪后，`CXX_STANDARD` 映射确认不超能力（超 → 注释警告而非静默） | P1 |
| 5 | 测试：导入含/不含 `CXX_STANDARD` 两态 + 区间断言；导出能力警告 | P0 |

## 3 详细设计

### 3.1 导入（`src/import.cpp`）

- 现有轻量解析器扫描 `set_target_properties(... CXX_STANDARD N ...)` / `target_compile_features(... cxx_std_N)` → 提取 N
- 映射：`language = ">=CPP<N>"`（C 项目 `">=C<N>"`）——与 1.3.1 区间语法对齐，语义 A（编译取 min=N）
- `CXX_STANDARD_REQUIRED OFF`：CMake 语义为"达不到就警告继续"——ezmk 区间语义天然类似（不 fail），映射为 `>=` 即可；`CXX_EXTENSIONS ON` → `GNU` 前缀（`>=GNUCPP<N>`）或注释
- 无 `CXX_STANDARD` → 现状 `C++17` 回退（保留）

### 3.2 导出能力确认（`src/export.cpp`）

- 1.3.1 后导出 `CXX_STANDARD <min>`；本版在能力表就绪后：若 `<min>` > `max_supported_std(family, version)` → 生成注释 `# CXX_STANDARD <min> exceeds the target toolchain capability (<max>)`（不静默改值——CMake 项目可自行决定）

### 3.3 已知坑位与对策

| # | 坑 | 优先级 | 对策 | 落点 |
|---|-----|--------|------|------|
| 1 | 轻量解析器漏 `CXX_STANDARD` 变体（property 简写/`target_compile_features`） | 中 | 双路径扫描；漏 → 回退 `C++17`（现状）不报错 | §3.1 |
| 2 | 导入区间与既有精确值项目混用 | 低 | 纯新增映射；精确值写法不变 | §3.1 |
| 3 | 能力确认误报（目标工具链未知） | 中 | 未知 → 不警告（保守） | §3.2 |
