# EazyMake 1.4.1 — pkg install 支持 git 仓库 URL

> 1.4.0 正式发布后的**补丁版本**（1.4.x 系列补丁的延续，对照 1.3.1~1.3.6 的单主题补丁惯例）。主题来自 1.4.0 发布后收集到的用户需求：**`ezmk pkg install` 目前无法直接安装 git 仓库 URL**（`git@github.com:user/repo.git` / `https://github.com/user/repo.git`），本版把「git 仓库作为包来源」落地为完整链路：识别 → 克隆 → ref 定位 → 安装 → lockfile 记录。发布总览见 [`1.4.x/README.md`](README.md)。
>
> **范围边界**：只做 git URL 安装支持（单主题补丁）。子模块递归、仓库子目录选择、`pkg update` 的 git 语义升级、`git://` 之外的额外协议均**明确不做**（见 §3.8）。**公共 API 无破坏性变更**。
>
> **⛔ 发布门槛**：① 计划清单全部完成或明确收口；② 公共 API 无破坏性变更；③ 全量测试零回归（基线 **1003 用例 / 5835 断言**，1.4.0 发布态）。
>
> **版本决策**：dev 阶段二进制版本号**保持 1.4.0**（1.2.x/1.3.x 补丁系列先例均不提前 bump），1.4.1 正式发布 commit 按 workflow §3 置正式版本号。

## 1 背景

`pkg install` 目前支持 4 种来源（`docs/pkg.md`「Package Sources」）：

| 来源 | 形式 | 现状 |
|------|------|------|
| 名称（仓库） | `ezmk pkg install fmt` | ✅ |
| 本地归档 | `./foo-0.1.0.zip` / `.tar.gz` | ✅ |
| 本地目录 | `./mylib`（1.2.0-dev.7+） | ✅ |
| 归档 URL | `https://.../foo-0.1.0.zip` | ✅ |
| **git 仓库 URL** | `git@github.com:user/repo.git` / `...repo.git` | ❌ |

git URL 缺失的根因（`src/pkg.cpp` 安装源检测，1611-1623 行）：只区分「目录 / 归档 URL / 本地文件 / 名称搜索」——`git@github.com:user/repo.git` 不含 `://`，被 `is_url` 启发式（含 `.` 与 `/` 且非本地文件）误判为 URL 并补 `https://` 前缀，克隆/下载必然失败；`https://github.com/user/repo.git` 虽命中 URL 分支，但下载下来的是 git 仓库而非归档，解压失败。`pkg install` 侧完全没有 git 分支。

**已有可复用基础设施**：`util::git_available()` / `util::git_clone(url, dest, branch)` / `util::git_pull()` / `util::git_last_commit_time()`（`util.cpp` Git helpers）；`repo.cpp` 有私有的 `is_git_url()` 启发式（`git@` 前缀、URL 含点）；`install_from_directory()`（`pkg.cpp:1519`）已实现目录安装全链路（校验 → 钩子 → 依赖 → 编译 → 拷贝 → postinstall → lockfile），git 克隆后可直接复用。缺口仅是：**来源判定 + 克隆落地 + ref 定位 + lockfile 记录**。

## 2 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | `pkg install` 识别 git 仓库 URL（SSH `git@` / `git://` / `file://` / `https(s)` `.git`）并克隆安装，复用 `install_from_directory` 全链路 | P0 |
| 2 | ref 定位：URL 片段 `#<ref>` + `--branch <ref>`（分支/标签/commit SHA），分支/标签浅克隆、commit 全量克隆 | P0 |

| 4 | 完整性语义：git 源以 commit SHA 为指纹（无 sha256）；显式 `--sha256` → 提示跳过；`git://` 明文协议 → 警告 + 确认 | P1 |
| 5 | 文档三向（docs/en|zh pkg.md/cli.md、README、skill）+ i18n 三向（新 key + `check_i18n.py`） | P0 |

| 7 | **明确不做**：子模块递归、仓库子目录选择、`pkg update` 的 git 版本语义、git 源自动升级（见 §3.8） | P0 |

## 3 详细设计

### 3.1 来源检测顺序与 git 判定（目标 1）

`pkg.cpp` `install()` 的检测顺序调整为：

```
0. 本地目录（现有）              → install_from_directory
1. git 仓库 URL（新增）          → clone → install_from_directory
2. 归档 URL / 本地归档（现有）    → 下载/校验/解压
3. 仓库名称搜索（现有）
```

**git 判定 `is_git_install_source(s)`**（新增，`pkg.cpp` 或 `util`）：

| 形式 | 例子 | 判定 |
|------|------|------|
| SSH scp 风格 | `git@github.com:user/repo.git` | `git@` 前缀 → git |
| 显式协议 | `git://host/repo.git`、`file:///tmp/repo.git` | `git://` / `file://` 前缀 → git |
| `://` URL 且剥 `#ref` 后以 `.git` 结尾 | `https://github.com/user/repo.git[#v1.0.0]` | → git |
| 无协议、剥 `#ref` 后以 `.git` 结尾 | `github.com/user/repo.git` | → git（补 `https://` **之前**判定） |

**不误判**：`foo.zip` / `foo.tar.gz` / `https://host/pkg.tar.gz` 不含 `.git` 后缀 → 走归档 URL 分支，行为不变。判定在现有 `is_url` 启发式**之前**执行，命中即短路进 git 分支。

**与 `repo.cpp` 的关系**：`repo.cpp:162` 已有私有 `is_git_url()`（`git@` 前缀 / 任意 `://` / 含点含斜杠启发式 + 本地路径排除）——宽松规则对 `repo add` 合适（参数本应是仓库 URL），但直接用于 `pkg install` 会把 `https://host/foo.zip` 误判为 git。因此**提取为 `util::is_git_url(std::string_view)`**（**保留 repo 的宽松语义**：`git@` / 任意 `://` / 含点含斜杠 + 本地路径排除，repo.cpp 改调 util 后行为零变化，用 repo add 回归测试锁定）；`pkg.cpp` 的 `is_git_install_source` 取 **严格子集** = util 判定 **且**（`git@` 前缀 / `git://`·`file://` 协议 / 剥 `#ref` 后以 `.git` 结尾），归档 URL 不命中。

### 3.2 克隆与安装流程（目标 1/2）

- **克隆位置**：临时目录（沿用归档 URL 的 temp 策略），克隆目录名带 PID+计数器防碰撞（与解压 staging 一致）；安装完成后清理。
- **安装**：`install_from_directory(clone_dir, scope, assume_yes, no_lock)` —— 校验 / 安装钩子 / 依赖解析 / 编译 / 拷贝 / postinstall / lockfile 全链路与目录安装完全一致，无新代码路径。
- **git 不可用**：`!util::git_available()` → fatal「git 未安装，请安装并加入 PATH」（复用 repo.cpp 既有文案语义）。
- **ref 解析优先级**：显式 `--branch <ref>` > URL 片段 `#<ref>` > 默认分支。`#` 片段取最后一个 `#` 之后全部字符（URL 中 `#` 本就是 fragment 分隔，git clone 不接受 fragment，克隆前剥离）。
- **浅克隆策略**（`util::git_clone` 扩展 `bool shallow` 参数，默认 false 保持 repo.cpp 现有调用行为不变）：
  - 分支/标签：`git clone --branch <ref> --depth 1`（最快路径，`--depth 1` 对 `--branch` 标签/分支均安全）；
  - commit SHA：**全量克隆**（浅克隆下 SHA 可能不可达）→ `git checkout <sha>`（detached HEAD）；
  - ref 为空（默认分支）：`git clone --depth 1`（默认分支 HEAD）。
- **新 helper `util::git_head_commit(repo_dir)`**：`git rev-parse HEAD`，供 lockfile 记录与 `--locked` 校验复用。

### 3.3 lockfile 与 `--locked`（目标 3）

- `config::LockfilePackage`（`include/ezmk/config.hpp:148-156`）新增**可选**字段 `std::string commit;`：
  - 写入：git 源 `source = "git"`、`source_url = <克隆 URL>`、`commit = <rev-parse HEAD>`；sha256 留空；
  - 解析：缺省空串 → 旧 lockfile（无此字段）正常解析，**向后兼容，lockfile version 保持 1**；
  - 序列化：`lockfile.cpp` save/load 同步（`commit = "..."`，仅在非空时写出，保持旧文件输出稳定）。
- **`--locked` 模式**（`pkg.cpp` 1566-1588 现有逻辑扩展）：
  - lockfile 中该包 `source == "git"` → 按 `source_url` + `commit` 克隆安装；克隆后 `git_head_commit(clone_dir) != lockfile.commit` → fatal（`lock_commit_mismatch`：分支/标签被 force-push 或已漂移，拒绝安装）；
  - `--locked` 下 lockfile 不重写（现有约束保持）；
  - 非 `--locked` 的 git 安装：重新解析 ref（分支/标签可能前移），写入新 commit —— 与现有"默认装最新"语义一致。
- **sha256 语义**：git 源无归档 → 不校验 sha256；显式 `--sha256` → 提示跳过（复用 `pkg_sha256_skipped_dir` 文案模式）；边车（`.sha256`）对 git 源不读取。

### 3.4 CLI 与 i18n（目标 4/5）

- CLI：`pkg install` 参数即 git URL（位置参数，无新子命令）；新增可选 flag `--branch <ref>`（与 `git_clone` 的 branch 参数同名，语义一致）。`pkg list` / `pkg info` 无改动（lockfile 记录自动反映）。
- 新 i18n key（预估 5 个，三向 + zh-TW 回退，`check_i18n.py` 通过）：
  - `pkg_git_cloning`（克隆中，含 url/ref 占位）
  - `pkg_git_not_available`（git 未安装）
  - `pkg_git_sha256_skipped`（`--sha256` 对 git 源跳过）
  - `pkg_git_plain_confirm`（`git://` 明文协议警告 + 确认，参照 `url_http_confirm`）
  - `lock_commit_mismatch`（`--locked` 下 commit 不一致）

### 3.5 安全

| 面 | 处理 |
|----|------|
| 全局安装 | 沿用 `global_confirm`（`install_from_directory` 已内置），git 源不例外 |
| 明文传输 | `git://` → 警告 + 确认（参照 `url_integrity_confirm` 的 `http://` 模式）；SSH `git@` / `https` 无明文问题 |
| 包内容 | 无解压 → 解压路径安全校验（1.1.2 `safe_extract_path`）不适用；包合法性校验（ezmk.toml / 依赖）走目录安装既有路径 |
| 命令注入 | 克隆命令全部参数经 `escape_shell_arg`（沿用 `util::git_clone` 既有防护）；ref 同样转义 |
| 钩子脚本 | 沿用安装钩子既有确认/沙箱机制（Lua 沙箱 / shell 审查），git 源不改变 |

### 3.6 测试

- **单元**：`is_git_install_source` 判定表（`git@` / `git://` / `file://` / `.git` / `.git#ref` 命中；`.zip` / `.tar.gz` / `foo.zip#x` / 无协议非 git 不误判）；`#ref` 剥离与 `--branch` 优先级。
- **集成**（离线可用，不依赖网络）：临时目录 `git init` + 提交 + tag 构造本地 git 仓库 fixture：
  - `file://` URL 端到端安装（识别 → 克隆 → 安装 → 出现在 `pkg list` / `ezmk.lock` 的 `source="git"` + `commit`）；
  - `#tag` / `#<sha>` / `--branch` 三形态安装，lockfile commit 与 `rev-parse HEAD` 一致；
  - `--locked`：commit 匹配成功 / 篡改 lockfile commit 后失败（`lock_commit_mismatch`）；
  - `--sha256` 显式给出 → 跳过提示；
  - `git://` 明文 → 确认提示（`-y` 跳过）。
- **回归**：全量 `bash build.sh test-all` 零失败（基线 1003/5835）；新增用例不得引入回归。

### 3.7 已知坑位与对策

| # | 坑 | 优先级 | 对策 | 落点 |
|---|-----|--------|------|------|
| 1 | git 判定误伤归档 URL（如 `foo.git.zip`） | 高 | 判定只认「剥 `#ref` 后**以 `.git` 结尾**」+ `git@`/`git://`/`file://` 前缀；判定表单测锁定 | §3.1 |
| 2 | `git_clone` 签名变更影响 repo.cpp 现有调用 | 中 | 新参数带默认值（`shallow=false`），repo 行为零变化；`-Wall` 全量编译 + 调用点复核 | §3.2 |
| 3 | commit SHA 浅克隆不可达 | 高 | SHA 强制全量克隆；`--depth 1` 仅用于分支/标签/默认分支 | §3.2 |
| 4 | lockfile 格式变更破坏旧文件解析 | 高 | `commit` 可选字段、空串缺省；非空才写出；旧 lockfile 兼容单测 | §3.3 |
| 5 | `--locked` 下 tag 被 force-push 后克隆到漂移 commit | 中 | 克隆后 `rev-parse HEAD` 与 lockfile commit 比对，不一致 fatal | §3.3 |
| 6 | `#` 片段与真实 URL fragment 混淆 | 低 | git 源才解析 `#`；归档 URL 分支不解析（保持现状） | §3.2 |
| 7 | 集成测试依赖本机 git | 低 | fixture 全本地（`git init`）；git 缺失时测试 skip（沿用既有跳过惯例） | §3.6 |

### 3.8 明确不做（收口后续版本）

- 子模块递归（`--recurse-submodules`）：仓库含子模块时按普通文件缺失处理，报错即可；
- 仓库子目录选择（clone 后从 `packages/<name>/` 子目录安装）：本版要求 **git 仓库根即包根**（ezmk.toml 在根）；
- `pkg update` 对 git 源的版本语义：git 源无语义版本可解析——update 输出提示「请用 `pkg install <git-url>` 重新安装」，不做自动刷新逻辑；
- `git+https://` 等额外 scheme 别名；
- 依赖声明 `[depends]` 中的 git URL（`[depends].lib` 仍只支持包名，git URL 仅作为 `pkg install` 的安装参数）。
