# EazyMake 1.4.0-dev.2 — 工具链能力表 + 标准校验严格化

> 1.4.0 第二个开发子版本。总览见 [`1.4.x/README.md`](README.md)。

---

## 1 背景

1.3.1 落地了**区间语言标准**（语义 A：编译取 min）与安装期**标准兼容校验**（warn 不 fail）。两个遗留点在本版收口：

1. **工具链能力表**：目前不知道"当前编译器最高支持哪个 `-std=`"（`ver_map` 是配置侧白名单，与真实编译器能力无关）。语义 C（"编译器支持多高用多高"，CMake `CXX_STANDARD` 式）与 dev.3 的编译协商都需要它——先建 `max_supported_std(family, version)`。
2. **校验严格化开关**：1.3.1 的兼容校验是"信息性不 fail"（坑 4：严格 fail 破坏现有包生态）。本版给可配置开关（`[pkg] strict_std_check = true` 或 `--strict`），默认仍 warn。

## 2 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | `toolchain::max_supported_std(family, version)`：给定工具链（gcc/clang/msvc + 版本）返回最高可用 `-std=` 规范值（如 gcc 13 → `CPP17`/`C17`） | P0 |
| 2 | 能力表来源：MSVC 走 `_MSC_VER` 分段（已有先例 `toolchain.cpp:504-506`）；GCC/Clang 走版本号分段表（可含实测校验脚本） | P0 |
| 3 | 校验严格化开关：标准兼容校验 warn → error 可配（`ezmk.toml [pkg] strict_std_check` 或 CLI `--strict`）；默认不变（warn） | P0 |
| 4 | 严格化错误沿用 1.3.1 的 `pkg_warn_std_mismatch*` 语义（改 fatal 措辞）；i18n 新 key 三向一致 | P1 |
| 5 | 测试：能力表分段断言（各 family 关键版本）+ 严格化开/关两态 + 默认回归 | P0 |

## 3 详细设计

### 3.1 能力表（`src/toolchain.cpp`）

```cpp
// 返回该工具链实际支持的最高标准（规范形 "CPP20"/"C17"；未知 → 保守下限）。
std::string max_supported_std(CompilerFamily family, const std::string& version);
```

- **GCC**：版本→标准映射表（如 gcc 11 → C++20/C17；gcc 8 → C++17/C17；gcc 5 → C++14/C11；gcc 4.8 → C++11/C11……），版本号取 `major[.minor]` 比较
- **Clang**：`__cplusplus` 能力与版本近似（clang 16 → C++23 支持实验性，保守 C++20……）
- **MSVC**：复用 `_MSC_VER` 分段（1910=VS2017→C++17、1920=VS2019→C++20、1930=VS2022→C++20/23 视配置）
- 未知版本 → 保守下限（C++11/C11），文档注明
- 表以注释标注来源与实测日期；可选 `scripts/check_max_std.py` 在 CI 对常见版本实测核对

### 3.2 校验严格化（`src/pkg.cpp`）

- 配置：`[pkg] strict_std_check = false`（默认）——`config.hpp` 新字段；CLI 不新增全局 flag（1.4.0 最小面，配置字段即可）
- 行为：`check_std_compat()` 命中不匹配时，strict → `util::fatal`（措辞引用 `pkg_warn_std_mismatch*` 语义 + "strict check enabled"），非 strict → 现状 warn
- i18n：新增 `pkg_fatal_std_mismatch`（严格化错误），`pkg_warn_std_mismatch*` 保留

### 3.3 已知坑位与对策

| # | 坑 | 优先级 | 对策 | 落点 |
|---|-----|--------|------|------|
| 1 | 能力表与真实编译器漂移 | 高 | 分段表注释来源/日期 + CI 实测脚本（可选）；保守默认 | §3.1 |
| 2 | 严格化误伤合法项目（包声明过高） | 中 | 默认 off；文档明示"仅 CI/严格要求时开启" | §3.2 |
| 3 | `_MSC_VER` 分段过时 | 中 | 对照 VS 版本表注释；未知 → 保守 | §3.1 |

## 6 跨版本关注点

- **dev.3 前置**：编译协商（语义 B）按 `max(包min, 消费者标准)` 重编——消费者标准可能超包声明，需能力表确认"协商后的标准是否被编译器支持"。
- **1.3.1 语义 A 不变**：本版不改变"编译取 min"；能力表只做元数据与协商的支撑。
- **语义 C（"支持多高用多高"）**：本版建表，是否启用 C 语义归 dev.3/后续评估（非本版承诺）。
- **后续窗口**：`[compile].language` 的 `max_supported_std` 校验（配置期拒绝超能力标准）——dev.4 或后续。
