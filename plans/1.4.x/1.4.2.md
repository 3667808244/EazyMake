## 1 背景

1.4.0-dev.6 已完成**第一轮**全量审计并修复 8 项 P0/P1。本版（第二轮）审计在 v1.4.1 上重新展开，发现的问题集中在**子系统接口层**与**跨平台路径/编码**，而非各模块内部逻辑：

- **崩溃/挂起**：Lua 报错对象处理 UB（`error()`/`error({})` 可打崩 ezmk）；`workspace watch` 在线程池上派发长驻 watcher 导致成员饿死、退出需多次 Ctrl+C；文件监视器 worker 死亡后主循环无感知 → watch 假死。
- **缓存正确性**：MSVC `/showIncludes` 依赖注解写到 **stdout** 却被从 **stderr** 解析（+ 前缀硬编码英文）→ 头文件改动永不触发重编，链接陈旧对象；`--locked` 把「编译产物哈希」当「下载归档哈希」校验 → 编译型包 `--locked` 重装必失败。
- **默认值/契约**：`[test].framework` 缺省小写 `"catch2"` 与分发处大写比较不一致 → 省略该键的 `ezmk test` 必然报 "unknown test framework"；CMake 导入器 `add_library` 丢弃源码参数、未知条件分支的 `else` 被错误采纳；`--disable-cache` 仍写缓存。
- **跨平台**：Windows 全链路窄 API/代码页问题（`CreateProcessA`/`GetModuleFileNameA`/miniz 窄名/`file_watcher` 逐字节 char↔wchar_t）——非 ASCII（中文）路径在三处乱码或失败；POSIX shell 转义被用于 Windows `CreateProcess` 命令行；MSVC 标准映射输出无效开关（`/std:c++98`、`/std:c++11`）。
- **信任边界**：repo `index.toml` 的 `file`/`[platform]` 前缀未约束在 repo 目录内且 `repo update` 后不复查；`repo remove/update/info` 不校验名字；preinstall shell 钩子 cwd 在全新安装时尚不存在。
- **watcher/workspace 文件层**：`replace_members_in_text` 按首个含 `]` 的行截断多行数组；`scan_dir` 对自指符号链接无限递归；workspace 成员校验顺序相关（同一配置因 members 顺序不同而「内部错误」或静默跳过）。

逐条修复项与方案见 §2/§3，执行阶段见 §4。

## 3 详细设计

### 3.1 Lua 运行时健壮性（F-01 / F-18 / F-19）

**F-01 — `lua_tostring` NULL → UB**。`src/lua_api.cpp` 全部 pcall/loadfile 报错路径（1106/1124/1150/1183/1294/1306/1327/1456/1464/1491）均为 `std::string err = lua_tostring(L, -1);`。`error()`（nil）、`error({...})` 等非字符串错误对象时 `lua_tostring` 返回 NULL，`std::string(NULL)` 触发 UB（SIGSEGV），任何构建/安装钩子或第三方工具脚本可打崩 ezmk。
方案：全部改为 `luaL_tolstring(L, -1, nullptr)`（永不返回 NULL；自动转换数字），或 `const char* s = lua_tostring(L,-1); std::string err = s ? s : "unknown Lua error";`。luaL_tolstring 会 push 结果——注意随后 `lua_pop(L, n)` 的次数按 tolstring 后栈形态调整（tolstring 把原值原位替换为字符串，栈深不变，pop 次数不变）。
测试：Lua 单测新增 `error()`/`error({code=1})`/`assert(false, {})` 三形态 → ezmk 进程不崩、输出 "Lua error"。

**F-18 — 权限一致性**。
- `ezmk.file_exists`（518-523）与 `ezmk.list_sources`（465-490）绕过 `check_read_permission`（同脚本 `file_read` 却被拒）——脚本上下文（声明了 `[utils.permissions]`）时经 `check_read_permission`；deny 时 `file_exists` 返回 false/nil、`list_sources` 返回空（不弹 ask）。
- `run_script`（1056-1063）仅在 `ezmk` 全局为 nil 时重注册——对齐 `run_lua_script_with_ctx`（1259-1268）：按 `g_project_root != 定位到的项目根` 决定重注册。
测试：权限单测（deny 列表内路径 file_exists=false；list_sources 不含 deny 项）。

**F-19 — 执行预算**。沙箱脚本无 `lua_sethook`、`ezmk.run` 无超时、`json_encode` 递归无深度上限。
方案：`run_lua_script_with_ctx`/`run_script` 执行 chunk 前 `lua_sethook`（`LUA_MASKCOUNT`，约 1e8 条指令，钩子内 `luaL_error`）并在 run(ctx) 调用后移除钩子；`ezmk.run`/`run_capture` 传 `timeout_sec`（如 300s 默认）给 `run_command`；`lua_to_json` 对象/数组递归带深度上限（如 200）超限报 Lua 错误。注意钩子只装到**本次脚本执行**，不得泄漏到下一个脚本（restore 钩子）。
测试：死循环脚本超时报错不挂起；深嵌套表 json_encode 报错不崩。

### 3.2 workspace watch 与文件监视（F-02 / F-05 / F-31 / F-32 / F-36）

**F-02 — run_watch 线程模型**。`workspace_build.cpp:451-482` 把全部成员 watcher 投进固定大小 `ThreadPool`，任务在 `run_command` 内阻塞整个 watch 会话 → 队尾成员永不启动；Ctrl+C 后线程拉取新任务又拉起新 watch，需多次 Ctrl+C。
方案：`run_watch` 改为**每选中成员一个 `std::thread`**（不设池）；层序仅用于启动次序（依赖成员先启动，避免其初始构建与依赖方读产物竞态——沿用现有层序 dispatch，启动后即并发）。退出：各成员子进程收 SIGINT 自行退出 → `run_command` 返回 → join。`--stop-on-error` 语义保持（失败后不再启动后续，已有逻辑保留）。
测试：集成——成员数 > jobs 的 workspace（如 3 成员 + `-j1`）三成员均进入 watch（`EZMK_TEST_BIN` 子进程）；一次 SIGINT 全部退出、退出码 0；`--stop-on-error` 下失败成员场景。

**F-05 — worker 死亡感知**。三平台 worker（file_watcher.cpp 200-211/303-307/371-374）对硬错误 `break` 退出，run() 主循环只轮询 `stop_requested_` → 假死。
方案：`FileWatcher` 增加 `std::atomic<bool> worker_error_` + 错误消息（mutex 保护或原子字符串指针）；worker 退出时置位；run() 主循环在 `stop_requested_` 之外检查 `worker_error_`，置位则 `warn` 明确信息、清理平台状态、返回（非静默）。watch 调用方（main.cpp ProjectWatch / workspace watch 成员）正常走 watcher 返回路径提示用户。
测试：单元——模拟 IOCP 错误后 run() 返回且带错误（Windows 本机）；删除被监视目录后进程不假死、输出告警。

**F-31 — 目录删除后恢复监视**。Windows 重挂失败即弃守（243-252）；Linux `IN_IGNORED`（len==0）跳过但 `wd_to_path_` 残留且 inotify wd 复用会错配旧路径（312）；macOS 目录 rename/delete 后 fd 指向陈旧 vnode。
方案：三平台统一——目录消失后从注册表移除并**周期重试补挂**（run() 主循环低频率探测缺失目录，如每 2s；Windows 重开句柄 + 重挂 ReadDirectoryChangesW、Linux 重新 inotify_add_watch 并在 `IN_IGNORED`/`IN_DELETE_SELF` 时清理 wd 映射、macOS 重开 fd + EV_SET）；补挂成功前不再报错刷屏（每次仅一次警告）。
测试：集成（Windows 为主，Linux 视环境）：删除并重建 src 子目录 → 恢复后可再次触发重建。

**F-32 — 存在性过滤与输出忽略**。`flush_pending`（66-89）注释声称有存在性过滤但未实现；无路径/扩展忽略机制 → 构建自身产物事件可能自触发（`src_dirs=["."]` 等配置）。
方案：(a) flush 前 `fs::exists` 过滤（删除事件不再触发重建，与注释一致）；(b) `add_ignore_prefix`/`add_ignore_suffix` API（或 `FileWatcher` 构造参数）——main.cpp 的 ProjectWatch 注册忽略 `build/`、`.ezmk/` 前缀与 `.o/.d/.tmp` 后缀；(c) 各平台事件侧同样过滤（减少 pending 噪音）。Linux/macOS 真递归不在本版（§3.9）。
测试：单元——删除文件事件不回调；`.ezmk/`/`build/` 内事件不进入 pending；集成——`src_dirs=["."]` 配置下 watch 重建不自我循环（限时断言无第二次重建）。

**F-36 — macOS kevent 固定 32 槽**。`changes[32]`/`events[32]`（362-363/520-535）超 32 目录栈溢出/事件截断。
方案：按 `dirs_.size()` 动态分配（`std::vector<struct kevent>`），注册与轮询同尺寸；超上限拒绝或扩容。测试：macOS 环境 >32 目录注册不崩（或 Linux CI 借构）。

### 3.3 构建缓存正确性（F-03 / F-04 / F-09 / F-10 / F-11 / F-12）

**F-03 — MSVC 依赖注解流错误**。`cache.cpp:598-607` `parse_compile_dependencies` 从 `res.err` 调 `parse_show_includes`；MSVC 的 "Note: including file:" 写 **stdout**（clang-cl 为对齐也写 stdout）→ MSVC 记录 dependencies 恒空 → 头文件改动不失效。
方案：MSVC 分支改解析 `res.out`；`toolchain::parse_show_includes` 前缀本地化无关化（MSVC `/showIncludes` 输出跟随 UI 语言，zh-CN 为「注意: 包含文件:」）——本版采用：**前缀匹配放宽为同时接受已知 en/zh 前缀 + 兜底按「`:` 后存在盘符/绝对/相对路径」解析**，并用 MSVC 本地化样本回归测试锁定。
测试：构造含 "Note: including file:" 的 stdout 与 stderr 样本（en/zh-CN 两种），断言解析正确、缓存记录含依赖、改头文件触发重编。

**F-04 — `--locked` 哈希双语义**。写锁 `maybe_write_lockfile`（pkg.cpp:1547-1552）记录**编译产物** `.a/.lib` 哈希（供 `lockfile::verify`）；`--locked` 安装（1910-1913）却把该值当**下载归档**期望哈希，`sha256_file(archive_path)` 必不等 → 编译型包 `--locked` 必 fatal。
方案：`LockedPackage` 增/改字段区分：`archive_sha256`（安装源归档哈希，来自 index/`--sha256`/下载校验，重装时校验归档）与 `lib_sha256`（产物哈希，仅 `lockfile::verify` 用）；`--locked` 重装时：有 `archive_sha256` 则校验下载归档，无（git/目录源）则按 commit/存在性校验。lockfile 版本仍 1、旧字段兼容（缺省空）。同步修正 URL/本地归档安装时 lockfile 记录 source/source_url/archive hash（F-04 附带，当前完全缺失导致跨机 `--locked` 不可能）。
测试：编译型包归档安装 → `--locked` 重装成功；篡改归档 → mismatch fatal；`lockfile::verify` 仍用产物哈希（改动产物后 build 报 integrity fail）；旧 lockfile 解析兼容。

**F-09 — `--disable-cache` 语义**。`cache.cpp:658` 只跳读；804-816 拷贝与 record 合并照常。
方案：`disable_cache` 时跳过 cache_obj 拷贝、跳过 record 条目合并与 `save_record`（或保存空记录并 clear files）——与用户「逃离坏增量状态」意图一致。测试：`--disable-cache` 构建后 .ezmk/cache/obj 无新增、record.files 为空；随后普通构建全量重编。

**F-10 — C++20 designated initializers**。`build.cpp:2569-2583` `.field = ...` 聚合在 `-std=c++17` 下仅靠 GCC 扩展（每次编译 -Wc++20-extensions）。
方案：改为逐成员赋值或普通聚合（TestRunContext 12 字段顺序一致即可）；不升构建标准（保持 C++17 兼容面）。测试：`-Wall -Wextra -Wpedantic -Wshadow` 全量编译零告警（构建脚本加告警门禁可选）。
