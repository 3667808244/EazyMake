### 1.1 为什么这几项值得单独一个补丁版

1. **`install.ps1 -DryRun` 是"文档承诺的用法直接报错"**：README 与脚本自身的 comment-based help 都写明 `.\install.ps1 -DryRun` 可预览，实际一跑就在 `Join-Path` 上抛错中止（根因见 §3.1）。这是**用户可见的缺陷**，优先级高于其它卫生项。
2. **测试代码告警会持续污染"零告警"口径**：1.4.2/1.4.3 的门槛写的是"首方代码零告警"，但 `src/` + `include/ezmk/` 零告警之外，`test/` 还有 7 条（`-Wall -Wextra -Wpedantic -Wshadow -Wformat=2` 下）。清掉后门槛才真正覆盖首方全部代码。
3. **僵尸 job 让发布流水线"看起来没跑完"**：每次 `gh release create` 后 Release run 都因 `macos-13` 拿不到 runner 而长期 `queued`，24h 后被取消（v1.4.2 实测 `cancelled 24h0m6s`；v1.4.3 同样）——发布者与自动化（如 `gh run watch --exit-status`）都会被这条假信号干扰。
4. **过期 TODO 会误导后来者**：注释承诺"归 1.2.0"，而 1.2.0 已发布多版；这类"挂版本的承诺"是文档腐化的典型。
5. **`.gitignore` 的过期条目会掩盖真实状态**：`plan.md` 与 `include/ezmk/version.hpp` 都已被正式跟踪（ignore 对 tracked 文件无效），却仍留在忽略列表里；`stdout_in_linux_vm.txt` 早已不存在。

## 3 详细设计

### 3.1 `install.ps1 -DryRun` 修复（M-01）

**根因（读码定位）**：`Main` 在 dry-run 下把临时目录留空——

```powershell
# install.ps1:520-524（现状）
$tempDir = ""
if (-not (Test-DryRun)) {
    $tempDir = Join-Path ([System.IO.Path]::GetTempPath()) "ezmk-install.$pid"
    New-Item -ItemType Directory -Path $tempDir -Force | Out-Null
}
```

随后 `Invoke-Download -DestDir $tempDir`（`:528`）→ `Invoke-BinaryDownload` 第一行就 `Join-Path $DestDir $BinName`（`:197`）→ `$DestDir` 为空串 → **`ParameterArgumentValidationErrorEmptyStringNotAllowed`**；脚本顶部 `$ErrorActionPreference = "Stop"`，于是 dry-run 在打印任何 `[DRY RUN] Would …` 之前就中止（实测：`-DryRun` 与 `-Version v1.4.3 -DryRun` 两种用法都失败，退出码 1）。

**次要缺陷（预览不完整）**：三处"文件不存在 → 警告并跳过"的早退发生在 `Test-DryRun` 判断**之前**（dry-run 下目标二进制必然不存在）：

| 位置 | 现状行为 | dry-run 下应当 |
|------|----------|----------------|
| `Register-OfficialRepo:378-381` | `ezmk.exe not found … skipping repo registration` | 打印 `Would run: … repo add/update …` |
| `Preinstall-OfficialUtils:415-418` | `ezmk.exe not found … skipping utils pre-install` | 打印 `Would run: … pkg install -g ezmk-official-utils -y` |
| `Confirm-Installation:442-445` | `Cannot verify — ezmk.exe not found` | 打印 `Would run: … version` |

**修复方案**：

1. `$tempDir` 改为**两种模式都计算展示路径**，仅非 dry-run 时创建目录：
   ```powershell
   $tempDir = Join-Path ([System.IO.Path]::GetTempPath()) "ezmk-install.$pid"
   if (-not (Test-DryRun)) { New-Item -ItemType Directory -Path $tempDir -Force | Out-Null }
   ```
   `Remove-TempFiles` 已有 `if ($TempDir -and (Test-Path $TempDir))` 守卫（`:489`），dry-run 下不会误删。
2. 上述三处把 `Test-DryRun` 分支**提到** `Test-Path $ezmkBin` 早退之前（预览优先，且不改变非 dry-run 行为）。
3. 防御性加固：`Invoke-BinaryDownload` 开头补一条空 `DestDir` 断言（`Write-Die`），避免同类回归再次以晦涩的 `Join-Path` 报错出现。

**行为契约（本版验收口径）**：

| 用法 | 期望 |
|------|------|
| `.\install.ps1 -DryRun` | 退出码 **0**；打印 `DRY RUN MODE` + 版本解析 + 两个 `Would download to: <temp>\…` + `Would install: … -> <InstallDir>\bin\…`（两个）+ PATH/repo/utils/version 的 `Would …`；**不创建任何文件/目录、不写 PATH、不联网** |
| `.\install.ps1 -Version v1.4.4 -DryRun` | 同上；版本解析不联网（现状已满足：`Resolve-Version:156-159`） |
| 非 dry-run 真实安装 | **行为零变化**（路径、顺序、提示文案一致） |

> **不引入网络**：`-DryRun` 全程只用 `[System.IO.Path]::GetTempPath()` 计算展示路径，CI 可在无网/限网环境跑冒烟。

### 3.2 测试代码 7 条编译告警清零（M-02）

`CXXFLAGS='-std=c++17 -Wall -Wextra -Wpedantic -Wshadow -Wformat=2' bash build.sh test` 下 `test/` 的全部告警（gcc 16.2.0 实测）：

| # | 位置 | 告警 | 修法 |
|---|------|------|------|
| 1 | `test/test_build.cpp:73` | `-Wmissing-field-initializers`（`cli::BuildOptions::profile` 未初始化） | 补齐聚合初始化项。**必须 C++17 合法**——1.4.2 F-10 刚把 C++20 designated initializers 从测试里拿掉，**不得再用 `.field =` 形式**；用位置初始化或先声明再赋值 |
| 2 | `test/test_cache.cpp:711` | `-Wcomment`（`//` 注释以反斜杠结尾导致续行） | 去掉行尾反斜杠 / 改写为多行 `//` 注释 |
| 3–6 | `test/test_integration.cpp:2399 / 2404 / 2419 / 2475` | `-Wrange-loop-construct`（`const std::string&` 绑定由 `const char* const` 构造的临时量，逐元素构造 `std::string`） | 循环变量改 `std::string_view`（C++17 可用）或 `const char*`；4 处同构，一并处理 |
| 7 | `test/test_lua.cpp:53` | `-Wunused-function`（`lua_dostring_safe` 已无调用点） | 删除该函数；若判断仍有诊断价值则加 `[[maybe_unused]]` 并注明理由 |

**约束**：只改测试代码的表达形式，**不得改变测试语义与断言数**（基线 1099 用例 / 6348 断言保持）。另注：`test/test_workspace.cpp:301` 是 Catch2 运行期 `WARN(...)` 输出（非编译告警），本版**不改**（它是刻意保留的诊断信息）。

### 3.4 过期 TODO 与"挂版本承诺"（M-04）

- `src/cli.cpp:1144-1146` 现状注释承诺"完整防御（检测截断/显式拒绝）归 1.2.0（TODO）"。事实：`argv` 由操作系统保证以 NUL 结尾、**不可能含嵌入 NUL**，所以"检测截断"本身没有可防御对象；改为**不挂版本的已知限制**：
  > `// 依赖 C 字符串语义：std::string(argv[i]) 在首个 NUL 处截断。OS 不会传入含嵌入 NUL 的 argv，故此处无需额外防御（不是待办项）。`
- 顺带扫一遍首方代码里的同类"版本承诺"（`归 1.`、`将在 1.`、`TODO(1.`、`待 1.` 等模式），凡指向**已发布版本**的，一并改成不挂版本的事实陈述或指向 `plans/2.0.0/REMOVALS.md`（若确属 2.0.0）。
- **不改**：指向具体历史版本的**事实性**注释（如 `// 1.2.0-dev.11: …` 记录实现时间）——那是变更溯源，不是承诺。

### 3.5 `release.yml` 的 `macos-x64` job（M-05）

现状：`macos-x64`（`:114-141`）声明 `runs-on: macos-13`，但该 runner 在 free tier 长期不分配 → job 永远排队 → **整个 run 长期 `queued`**（Release 资产其实已由其它 4 个 job 上传完毕），24h 后整轮被取消。

**方案（保留定义、默认跳过）**：

```yaml
  macos-x64:
    needs: version
    # Intel macOS (x64)：macos-13 runner 在 free tier 长期不分配，job 一旦进入
    # 队列就会把整轮 Release 拖成 queued（v1.2.x~v1.4.3 均如此，24h 后被取消）。
    # 默认跳过：需要出包时把仓库变量 ENABLE_MACOS_X64 设为 true（Settings →
    # Secrets and variables → Actions → Variables），或临时改本条件。
    if: vars.ENABLE_MACOS_X64 == 'true'
    runs-on: macos-13
```

- 未设置该变量 → `vars.ENABLE_MACOS_X64` 为空串 → 条件为假 → job **skipped**（不是 queued）→ run 正常结束。
- 资产产出行为不变：默认无 `ezmk-macos-x64.tar.gz`（与 1.2.x~1.4.3 一致）。
- **文档/skill 同步**：`.claude/skills/ezmk-publish/SKILL.md`（§2.3 "Intel x64 一直没有 Release 资产"与 §4 坑位表）与 `publish/homebrew/ezmk.rb` 头部注释（Inte Mac 说明）补一句"需要时用 `ENABLE_MACOS_X64` 打开"；`docs/{en,zh}/faq.md` / `technical.md` 若提到 Intel Mac 无资产，保持口径一致。

### 3.8 明确不做（本版收口）

- **`locale/zh-TW.json` 补齐 32 个未译键**：变体继承是既定设计（缺键回落基础语言），补齐需大量译写与校对，且不属"遗留清理"；留作后续可选演进（若要收口，应在专门的语言变体计划里做，并同步 `check_i18n.py` 的口径说明）。
- **`[install].sharedir`**：要么实现（新功能，超本版"零功能新增"边界），要么从解析与文档中移除（会影响配置兼容性判断）——两项都留到 **2.0.0 决策项**（见 [REMOVALS.md](../2.0.0/REMOVALS.md) §3）。
- **2.0.0 弃用面的任何动作**（`[test].flags` / `ezmk utils cc` / lockfile `sha256` 别名 / `-V` / 旧式 shell 钩子等）：本版**不动**，也不放宽告警。
- **本地残留文件的清理**（根目录 `temp.md`/`sessions.md`/`build_err.txt`/`*.eml`/`build/pkg-arch/…`）：它们**未被跟踪**，不属仓库内容；本版只修 `.gitignore` 规则本身。
- **`test_file_watcher.cpp` 的 7 处环境相关 SKIP**：本机（MSYS2/Windows）不投递文件事件所致，需在 Linux/CI 上判定，不在本版处理。
- **`test_workspace.cpp:301` 的 Catch2 `WARN`**：刻意保留的诊断信息。
- **man/CLI/配置面**：本版不触碰，`check_man_sync.py` 预期保持绿（无需更新页面正文，仅发布 commit 更新 `.TH` 日期）。

### 3.9 已知坑位与对策

| # | 坑 | 对策 |
|---|-----|------|
| 1 | workflow YAML 步骤名含 `: ` 会导致解析失败（1.4.3 实测 0 秒失败） | 新增/改动的 `name:` 一律加引号；改完用 `npx --yes js-yaml` 解析验证 |
| 2 | `vars.` 上下文只对 **repository/organization variable** 生效；未定义时为空串 | 条件写成 `== 'true'`（不是 `!= 'false'`），保证未设置时跳过而非运行 |
| 3 | `install.ps1` 在 `$ErrorActionPreference = "Stop"` 下，任何非终止错误都会中止 | 修 dry-run 时显式保证不触碰文件系统；CI 断言里加"目标目录不存在"检查，防止未来再引入副作用 |
| 4 | 测试告警修法可能引入 C++20 语法（designated initializers） | 全部改法限定 C++17；用 `-Wpedantic` 严格编译验证 |
| 5 | 删除 `test/test_lua.cpp` 的未用函数可能牵动断言数 | 只删无调用点的定义；回归对照 1099/6348，若数字变化需说明原因 |
| 6 | 只读/受限沙箱下 MSYS2 bash 无法启动（`couldn't create signal pipe, Win32 error 5`） | 本地验证用 PowerShell/cmdlet 或非受限环境；`check_docs_sync.sh` 这类 bash 检查以 CI 为准 |
| 7 | `.gitignore` 改动后误把生成物纳入跟踪 | 改完跑 `git status --porcelain --ignored` 复核：生成物仍为 `!!`，`plan.md`/`version.hpp` 不再被忽略 |

## 6 跨版本关注点

- **与 2.0.0 的分工**：本版只做"不需要弃用到期即可收口"的卫生项；所有弃用面（`[test].flags`、`ezmk utils cc` 等）与三项待拍板决策（lockfile 旧别名读取、`[utils.permissions]` 缺省、旧式 shell 钩子、`sharedir`）都归 [`plans/2.0.0/REMOVALS.md`](../2.0.0/REMOVALS.md)。**2.0.0 计划必须把"同步 man / i18n / 测试夹具 / 文档"写成显式交付项**——删 `[test].flags` 与 `ezmk utils cc` 会让 `check_man_sync.py` 与 `check_i18n.py` 立刻变红（这是 1.4.3 埋下的设计意图）。
- **与 1.4.3 的关系**：1.4.3 交付 man 基础设施后，本版**不动 man 正文**；发布 commit 仍按 CONTRIBUTING 的约定更新 4 页 `.TH` 日期（构建期不打时间戳，保持可复现）。
- **回归基线**：**1099 用例 / 6348 断言**（1.4.3 发布态），本版为纯清理补丁，必须零回归；测试告警修法不得改变断言数。
- **i18n**：三向 **406** 键不变（本版不新增/不删除 key）。
- **与发布流程的长期收益**：`macos-x64` 默认跳过后，`gh run watch --exit-status` 才能真正代表 Release 成功，发布自动化不再被假信号干扰。
