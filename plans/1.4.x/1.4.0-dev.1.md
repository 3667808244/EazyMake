# EazyMake 1.4.0-dev.1 — 调试配置生成（VS Code 三件套）

> 1.4.0 第一个开发子版本。总览见 [`1.4.x/README.md`](README.md)。

---

## 1 背景

`ezmk` 生成构建/运行环境（`ezmk build`/`run` 及 `project export cmake`），但**不生成调试器配置**——用户要用 VS Code 调试需手写 `launch.json`/`tasks.json`/`settings.json`，且必须自行拼出 ezmk 的编译参数（include 路径、宏、`-std`、依赖包注入），极易出错。本版提供 `ezmk project export vscode`（或并入 `project export` 的 `--vscode` 形态）一键生成三件套，**per-platform 调试器**（gdb / lldb / cppvsdbg），与 `[compile.profile.*]` 联动。

## 2 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | `ezmk project export vscode`：生成 `.vscode/launch.json` + `tasks.json` + `settings.json`（存在则询问/`--overwrite`） | P0 |
| 2 | **launch.json**：per-platform 调试器（Windows/MSVC → `cppvsdbg`；Linux/GCC → `cppdbg`(gdb)；macOS/Clang → `lldb`）；program 指向 `build/<name>`；`preLaunchTask` 触发构建 | P0 |
| 3 | **tasks.json**：`ezmk build [--profile <name>]` 任务 + 默认组；依赖注入的 include 路径/宏随构建自动生效（不硬编码） | P0 |
| 4 | **settings.json**：clangd/c_cpp 的 include 路径 + 宏（复用 `project cc` 的 `compile_commands.json` 或等效信息） | P0 |
| 5 | profile 联动：`--profile <name>` 时 launch/tasks 指向该 profile 的产物与编译参数 | P1 |
| 6 | 测试：三件套生成 + JSON 合法性（nlohmann 反序列化断言）+ 关键字段（调试器/program/preLaunchTask/include）| P0 |

## 3 详细设计

### 3.1 CLI 形态

- `ezmk project export vscode [--overwrite] [--profile <name>]`（`export` 命令组新增子形态；`--profile` 与 `project cc`/`export cmake` 同语义）
- 缺省输出 `.vscode/`（项目根）；`--overwrite` 覆盖已存在文件，否则询问（对齐 `export cmake` 的覆盖安全惯例）

### 3.2 launch.json（per-platform）

| 平台 | 调试器 type | 说明 |
|------|------------|------|
| Windows + MSVC | `cppvsdbg` | `program`: `build/<name>.exe` |
| Linux + GCC/Clang | `cppdbg` | `miDebuggerPath`: `gdb`/`lldb`（按检测工具链）；`setupCommands` 注入 |
| macOS + Clang | `lldb` | `program`: `build/<name>` |

- `preLaunchTask`: `ezmk-build`（tasks.json 中定义），保证调试前先增量构建（1.3.0-dev.5「总是先构建」语义对齐）
- `cwd`: `${workspaceFolder}`；`externalConsole`: false

### 3.3 tasks.json

```json
{
  "version": "2.0.0",
  "tasks": [{
    "label": "ezmk-build",
    "type": "shell",
    "command": "ezmk build",
    "args": ["--profile", "<name>"],   // 仅 --profile 时
    "group": { "kind": "build", "isDefault": true }
  }]
}
```

- 依赖包的 include/宏**不硬编码**进 tasks（构建侧 ezmk 注入，调试/索引侧由 settings 或 compile_commands 提供）——单一数据源

### 3.4 settings.json

- 优先 `compile_commands.json`（`[compile].compile_commands = true` 或 `project cc` 生成）：`clangd.arguments` 指向它
- 无 compile_commands 时回退：`C_Cpp.default.includePath`（`<proj>/include` + 依赖包 include）+ `C_Cpp.default.defines`（`EZMK=1` 等，复用 `generate_ezmk_macros`）

### 3.5 已知坑位与对策

| # | 坑 | 优先级 | 对策 | 落点 |
|---|-----|--------|------|------|
| 1 | 调试器类型猜错 → 用户困惑 | 高 | per-platform 表 + 工具链检测（`toolchain::detect_toolchain`）；文档注明可手动改 | §3.2 |
| 2 | JSON 转义（项目名/路径含引号反斜杠） | 高 | 统一 JSON 序列化（nlohmann `dump`），禁止手拼字符串 | §3.2-3.4 |
| 3 | `preLaunchTask` 名不匹配 → 调试失败 | 中 | launch/tasks 由同一生成器产出，键名常量对齐；测试断言交叉引用 | §3.2/3.3 |
| 4 | 覆盖已有用户配置 | 高 | 询问 + `--overwrite`；`.vscode/` 已在 .gitignore 常见 | §3.1 |
| 5 | MSVC 调试需 VS 安装（vsdbg） | 中 | 文档注明 cppvsdbg 依赖 VS/VS Code C++ 扩展 | §3.2 |

## 6 跨版本关注点

- **与 dev.2~dev.5 独立**：调试配置主线不依赖语言标准/CMake 互操作，可并行。
- **依赖 `project cc`**：settings 的 compile_commands 优先路径复用其产物（dev.1 不改 `cc` 本身）。
- **`--profile` 联动语义**与 `project cc --profile`/`export cmake --profile` 对齐（复用 apply_profile）。
- **后续窗口**：launch 参数透传（`--`）、多配置（test 目标调试）——1.4.0 后续或 1.5.x 评估。
