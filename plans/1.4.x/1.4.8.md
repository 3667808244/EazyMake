## 3 详细设计

### 3.1 miniz 2.2.0 → 3.1.2（D-01）

**替换范围**：`src/vendor/miniz.c`、`miniz_tdef.c`、`miniz_tinfl.c`、`miniz_zip.c`；`include/vendor/miniz.h`、`miniz_common.h`、`miniz_tdef.h`、`miniz_tinfl.h`、`miniz_zip.h`。上游 2.2.0 与 3.x 都是「拆分文件」布局（`miniz_common.h` / `miniz_tdef.*` / `miniz_tinfl.*` / `miniz_zip.*`），文件集合一致，因此是**同构替换**，不是换布局。`include/vendor/miniz_export.h` 是上游由 CMake `generate_export_header` 生成、本仓手写的静态链接桩（`#define MINIZ_EXPORT` 空），**保留不动**。

**上游来源**：GitHub release [`3.1.2`](https://github.com/richgel999/miniz/releases/tag/3.1.2)（资产 `miniz-3.1.2.zip`）或对应 tag 源文件；**不要**用 amalgamated 单文件。

**目标版本带来的变化**（上游 `ChangeLog.md`）：

| 版本 | 与 EazyMake 相关的条目 |
|---|---|
| 3.1.2 | 修「读 zip 头时中央目录偏移溢出」；修 `tinfl_decompress` 的 `code_len==0` 死循环；给 ZIP 校验/写入/压缩加 fuzz；CMake 4 |
| 3.1.1 | 函数包装改 `inline static`，修告警 |
| 3.1.0 | 支持「zip 不从偏移 0 开始」；去掉 `tinfl_decompress` 中会破坏 `tinfl_decompress_mem_to_heap` 的参数检查；`miniz_tdef.c` 支持**强制 C++ 编译**（本仓正是用 `g++` 编 `.c`，见 `build.sh:84`）；修 MinGW32 Unicode 路径；避免 `windows.h` 与 `std` 的 min/max 冲突；加 fuzz 与 Catch2 测试 |
| 3.0.2 | 修 Windows `mz_utf8z_to_widechar` 缓冲区溢出 |
| 3.0.0 | inflate 内存占用下降（`tinfl_decompressor` 结构变更 = **ABI 断**，本仓静态重编无影响）；结构体加 padding；MinGW32 改用 `_ftelli64`/`_fseeki64` + `wfopen`；修 `MZ_ZIP_GENERAL_PURPOSE_BIT_FLAG_UTF8` 未被设置（**写出的 zip 字节会变**）；新增 `MINIZ_NO_DEFLATE_APIS` / `MINIZ_NO_INFLATE_APIS` |

**本仓用到的 API（兼容面）**：压缩路径 `mz_deflate` / `mz_crc32`（`src/util.cpp:800/812`，tar.gz）；解包 `mz_zip_reader_init_cfile` / `_get_num_files` / `_file_stat` / `_is_file_a_directory` / `_extract_to_callback` / `_end`（`src/util.cpp:1020-1071`）；打包 `mz_zip_writer_init_cfile` / `_add_mem` / `_finalize_archive` / `_end`（`src/util.cpp:880-900`）。均为公共 API，3.x 保留；结构体 `mz_zip_archive_file_stat` 的字段（`m_uncomp_size` / `m_filename`，`src/util.cpp:1037-1040`）在 3.x 保留（新增 padding），**编译期即可暴露字段改名**。

**行为差异与风险**：

1. **zip 产物字节变化**：3.0.0 起会设 UTF-8 general purpose flag。受影响的是「按字节/hash 比对 zip」的断言（`test/test_integration_report.cpp:384`、`test/test_util.cpp:1063`）；`.sha256` 边车是对产物现算，不受影响。
2. **畸形归档处理更严格**：`test/test_util.cpp:833` 的「invalid zip throws」应继续通过；上游新增的 fuzz 目标可作为语料来源。
3. **`mz_version()` 字符串变化**：10.2.0 → 11.3.2；首方代码未调用，但 `docs/*/technical.md:17` 写死了旧值（D-05）。
4. **许可/版权**：确认上游 `LICENSE` 与文件头版权声明未变化；本仓 `docs/*/technical.md` 的「第三方代码保持原样」承诺不变。

**回归验证**：`bash build.sh`、`bash build.sh test-all`；zip 端到端（`project pack --format zip` → `pkg install <zip>` → 消费侧构建）；tar.gz 端到端；含非 ASCII 条目名/路径的 zip 解包（`fopen_utf8` 路径）；恶意条目名/超大条目（既有 1 GiB 上限用例）。

### 3.2 Lua 5.4.7 → 5.4.9（D-02）

**替换范围**：`src/vendor/lua/*.c`（**32** 个，不含解释器入口 `lua.c` / 编译器入口 `luac.c`——本仓用 `src/ezmk_lua_main.cpp`）+ `include/vendor/lua/*.h`（**27** 个，含生成头 `ljumptab.h` / `lopnames.h`）。上游来源：`https://www.lua.org/ftp/lua-5.4.9.tar.gz`。

**为什么停在 5.4.9 而不是 5.5**：官网明确「There will be no further releases of Lua 5.4」，5.4.9 是 5.4 终版；5.5 有破坏性变更（for 循环变量只读、全局变量需声明、`luaL_makeseed` 等）且 5.5.2 仍在开发，`build.sh:95` 的 `-DLUA_COMPAT_5_3` 语义在 5.5 下也不同——升级 5.5 归 2.0 评估，本版只吃 5.4 补丁。

**必须迁移的本地改动**：`src/vendor/lua/linit.c:47` —— 从 `loadedlibs[]` 移除了 `io` 与 `os` 库（安全沙箱，注释原文「io and os removed for security — use ezmk.file_* and ezmk.run() instead」）。全仓 vendor 目录只有这一处本地改动（`grep EZMK src/vendor include/vendor` 仅命中此处），替换后**必须重新施加**，否则沙箱被打开。

**修了什么**（[lua.org/bugs.html](https://www.lua.org/bugs.html)）：

- 5.4.7 中存在、5.4.8 修掉的 4 个：`Wrong code generation for indices with comparisons`（代码生成正确性）、`Wrong limit for local variables in 16-bit systems`、`Missing error status in panic function`、`Wrong error message when using fields of string "_ENV"`。
- 5.4.8 中存在、5.4.9 修掉的 2 个：`New metatable in an all-weak table can fool the GC`（GC 正确性）、`Lua raises an error when given the option '--' without a script`。
- Debian 安全跟踪对 5.4.7 **无未修 CVE**（forky/sid 已到 5.4.9）→ 本项是正确性/健壮性升级，不是应急安全修复。

**回归验证**：`bash build.sh`、`bash build.sh test-all`；`ezmk-lua` 独立运行时冒烟（`build/ezmk-lua`）；Lua 钩子 / `ezmk utils` 用例；沙箱用例（`io` / `os` 不可达）；`LUA_COMPAT_5_3` 相关兼容路径。

### 3.3 Catch2 3.8.0 → 3.16.0（D-03）

**现状**：`include/vendor/catch2.hpp` + `src/vendor/catch2_impl.cpp` 是 Catch2 v3.8.0 的 **amalgamation**（横幅 2025-01-06 生成），`src/vendor/catch2_impl.cpp:16` 用 `#include "catch2.hpp"`，并在 `:4773/4780` 通过 `#if !defined(CATCH_AMALGAMATED_CUSTOM_MAIN)` 提供 `main()`。

**升级方式**：从 release [`v3.16.0`](https://github.com/catchorg/Catch2/releases/tag/v3.16.0) 取资产 `catch_amalgamated.hpp` / `catch_amalgamated.cpp`，分别落到 `include/vendor/catch2.hpp` / `src/vendor/catch2_impl.cpp`，保持 `#include "catch2.hpp"` 与 amalgamated `main()` 不变。

**影响面**：

1. 本仓测试套件（`build.sh:93` 的 `TEST_SRC` 显式包含 `src/vendor/catch2_impl.cpp`）。
2. `ezmk test` 的 Catch2 模式**解析控制台摘要行**：`src/build.cpp:2292-2352` 匹配 `test cases: M | X passed | Y failed` 与 `All tests passed (A assertions in M test cases)`。升级后必须跑全量测试确认这两条仍匹配；若 Catch2 改了摘要格式，解析会退化为「只看退出码」，属必须修复项。
3. 用户项目的 `include/vendor/catch2.hpp` 分支（`src/build.cpp:2173-2177` 走 `CATCH_CONFIG_MAIN`）与本仓 vendored 头无关，本版不改。
4. 断言统计口径：由 Catch2 自身统计，升级后若总数出现变化，需在收口时说明来源；**用例数只增不减**。
5. **默认执行顺序变更（升级中发现）**：Catch2 ≥ 3.16 的 `--order` **默认改为 `rand`**（v3.8 为 `decl`）。本套件多处用例共享进程级 `lua_State`（且 unrestricted 路径会把 `io`/`os` 载入同一状态），随机顺序会使其结果不确定——实测 `[lua]` 在随机顺序下 10 个用例失败、`--order decl` 下全过。对策：`build.sh` 的两个测试调用补 `--order decl`（恢复 3.16 前的行为并保证回归可复现）；用例的**顺序独立性**作为已知债登记（见 §6 延后项）。

**回归验证**：`bash build.sh test-all`；`build/test_ezmk --help` 确认 `--verbosity high`（`build.sh:279`）等旗标仍在；`ezmk test` 端到端（含失败用例的摘要解析）。

### 3.6 明确不做

- **Lua 5.5**（破坏性，归 2.0 评估）、**toml++ / nlohmann-json**（已是最新，无动作）。
- 公共 API / CLI / 配置 / 输出格式的语义变更；任何弃用面的放宽或移除（归 [2.0.x/REMOVALS.md](../2.0.x/REMOVALS.md)）。
- 官方仓库 `ezmk-repo` 的 `packages/`（catch2 3.6.0、lua 5.4.7、nlohmann_json 3.11.3 等）版本更新——那是**分发内容**，与 ezmk 自身依赖解耦，另立计划。
- Windows 之外的 vendor 构建方式调整；`build.sh` 结构不做与本版无关的重构。
- **测试用例的顺序独立性重构**（`[lua]` 共享全局 `lua_State` 等）——本版只固定 `--order decl` 恢复确定性，不重写用例；归后续代码质量审计。

## 6 跨版本关注点

- **承接 1.4.7 的依赖盘点**：本版是该盘点的落地；盘点结论同时登记了「已最新」的 nlohmann/json / toml++，避免重复评估。
- **与 2.0.0 解耦**：本版不放宽也不移除任何弃用面；Lua 5.5 与官方仓库包版本更新是 2.0 前后的独立议题。
- **回归基线**：本机立项态 **1133 用例 / 6525 断言 / 9 个 `test_integration_git.cpp` 环境性失败**（`file:///D:/...` 被 MSYS2 git 当 POSIX 路径，与依赖升级无关；详见 `build/upstream/BASELINE-NOTES.md`）；每阶段全量回归后再进下一阶段，判据为**失败集合不扩大**。Catch2 升级带来的统计口径差异须在收口时说明来源。
- **vendor 政策不变**：第三方代码保持原样（唯一例外是既有 Lua `linit.c` 沙箱补丁），`CLAUDE.md` / `docs/*/technical.md` 的「原样 vendored」承诺继续成立。
- **发布门槛**：⛔ ① 清单完成或明确收口 ② 公共 API 无破坏性变更 ③ 全量零回归 ④ 四项附加门槛 ⑤ CI 全绿。
