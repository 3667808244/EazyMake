## 1 背景

### 1.1 现状：源发现全部非递归

核心 helper `util::list_files()`（`src/util.cpp:359-377`）用 `fs::directory_iterator`（`src/util.cpp:363`）——只遍历目录自身。所有源收集路径都走它：

| 用途 | 落点 | 语义 |
|---|---|---|
| 项目源码 | `build::collect_sources()`（`src/build.cpp:142-198`，扫描在 `:161`） | `[compile].src_dirs` 每个目录的**直接**子文件 |
| 测试源码 | `collect_test_sources()`（`src/build.cpp:2106-2123`，扫描在 `:2117`） | `[test].dirs` 同上 |
| 包源码 | `compile_package()`（`src/pkg.cpp:910`，复用 `collect_sources`） | 包 `[compile].src_dirs` 同上 |
| utils 包门控 | `src/pkg.cpp:1395` | 目录是否有源码可编 |
| Lua `ezmk.list_sources()` | `src/lua_api.cpp:530-569`（扫描在 `:545`） | 同 helper，供 `compile_commands` 等使用 |
| workspace 测试探测 | `src/workspace_build.cpp:153` | 成员是否有测试源码 |

结果是 `src/sub/foo.cpp` 不会被编译，除非把 `src/sub` 显式写进 `src_dirs`。

### 1.2 三处不一致，说明「递归」缺的是接线而不是能力

- **`project export cmake` 已经递归**：`--glob` 输出 `file(GLOB_RECURSE ...)`（`src/export.cpp:156`），`--no-glob` 用 `recursive_directory_iterator`（`src/export.cpp:175`）。于是**导出的 CMake 会编译子目录文件，而 `ezmk build` 不会**——同一项目两套构建的文件集合不同，round-trip 不一致。
- **`project pack`（源码包）也递归**：`copy_pack_source_dir()` 递归复制整棵目录树（`src/build.cpp:1800-1823`）——归档里有子目录源文件，消费侧 `ezmk build` 却编不到。
- **计划文档与实现漂移**：`plans/1.1.x/1.1.0-dev.6.md:33` 声称 `[test].dirs`「递归收集目录下所有 `.cpp`」，实现从未递归。用户文档此前也未写明「非递归」（已在本版外先行补齐，见 §4 阶段零）。

### 1.3 现状变通与代价

变通做法是把子目录逐个列进 `src_dirs`。它可行——对象输出路径镜像 `rel(src, proj_root)`（`src/build.cpp:2742-2744`），缓存键同样是相对路径，因此嵌套目录本身不是问题。代价有三：

1. **手工同步**：目录增删必须同步改 `ezmk.toml`，否则静默漏编（只有全空情形才 fatal）。
2. **同名去重是陷阱**：`collect_sources` 按**文件名**去重（`src/build.cpp:163-168`），嵌套后同名文件很常见——`src/a/util.cpp` 与 `src/b/util.cpp` 只有先出现的那个会被编译，另一个打印一条重复告警后跳过。目录越深越容易踩。
3. **配置膨胀**：`project import --from cmake` 把每个源文件所在目录摊平成 `src_dirs`（`src/import.cpp:657-668`），导入一个多层项目可能得到一长串目录。

### 1.4 需求

让「某个源目录下的整棵子树」成为**可选**语义：默认与今天完全一致；启用后 build / test / package / `compile_commands` 看到同一个源集合，并与 export / pack 的既有递归行为自洽。

## 3 详细设计

### 3.1 语法（已拍板：方案 A）

| 方案 | 形态 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）** | 条目尾部标记：`src_dirs = ["src/**", "lib"]` | 每个目录独立控制；不新增布尔键；与 CMake `GLOB_RECURSE`、`.gitignore` 的直觉得一致；可后续扩展（如 `/*` 单层） | 多一个字符串约定，解析期需识别并剥离标记 |
| B | 全局开关：`[compile].recursive_sources = true`（`[test]` 同名键） | 最简单、一眼可见 | 无法 flat / recursive 混用；作用域过大 |
| C | 表数组：`[[compile.src_dir]]` + `path` / `recursive` | 最清晰、可扩展 | 破坏现有 `src_dirs` 字符串数组形态；配置冗长；TOML 双层表易错 |
| D | 默认改为递归 | 无需配置 | 静默改变所有既有项目语义；会把 `.ezmk` / `build` / 临时文件吸进来；破坏「可见即所编」 |

**已拍板（2026-10-13）：采用 A。** 冻结语义：

- 条目以 `/**` 结尾 = 递归该目录**整棵子树**；不以 `/**` 结尾 = 保持现有 flat 语义。
- 同一列表可混用（`src_dirs = ["src/**", "lib"]`），**逐条目**生效。
- `/**` 只是目录级递归开关，**不是 glob**：`src/**/*.cpp` 之类不解析，按字面目录名处理（缺失时沿用 warn）。
- 单层 `/*` **不在本版**（避免与「递归」混淆；如需要另立条目）。
- 同一语法同时适用于 `[compile].src_dirs` 与 `[test].dirs`。
- 方案 B / C / D 不采纳：B / C 作为后续便捷面另行评估，D 的拒绝理由见表。

### 3.2 发现语义（R-02）

- 在 `util` 增加递归实现（形如 `list_files_recursive(dir, exts, skip_dirs)`，或给 `list_files` 加一个默认 flat 的可选参数——**旧签名行为不变**，避免所有调用点回归）。
- **跳过规则**（固定集合，不新增配置）：`.` 前缀目录（含 `.git` / `.ezmk`）、构建输出目录 `build`。理由：`src_dirs = ["."]` 这类配置（`plans/1.4.x/1.4.2.md` F-32 提到过）一旦递归，会把构建产物与内部状态吸进源集合。
- **符号链接**：使用 `recursive_directory_iterator` 的默认行为（**不跟随**目录符号链接），避免自指环；Windows junction 的行为需在实现阶段实测确认并写进文档。
- **确定性**：递归结果统一按路径字符串排序（承接 1.4.6 Q-19 对 `directory_iterator` 无序的收口口径），保证对象顺序、链接顺序、缓存 key 可复现。
- **深度**：不设上限；靠「不跟随符号链接 + 跳过规则」防环。
- **缺失 / 空目录**：沿用现有语义（单目录缺失 warn，全部缺失 fatal `src_dir_missing`；结果为空 fatal `no_source_files`）。

### 3.3 去重与 `main` 检查（R-04）

- **flat 模式保持现状**（按文件名去重 + 重复告警）→ 既有项目零回归。
- **递归模式按项目根相对路径去重**：同一物理文件被两条 `src_dirs` 覆盖时只收一次（必要时按 canonical 归一）。这是递归的意义所在——`src/a/util.cpp` 与 `src/b/util.cpp` 都应参与编译。
- 需要写进兼容性的可观察差异：递归模式下同名文件**都会**被编译，而 flat 模式下只会编第一个。
- `require_main` 的 `main.cpp` / `main.c` 检查不变（按 filename 判断，`src/build.cpp:183-195`）。
- 不变量：某条目的递归标记只影响该条目的子树，不改变其他条目的扫描。

### 3.5 缓存与产物路径（无需迁移）

- 对象落点 `temp_dir / rel(src, proj_root).o`（`src/build.cpp:2742-2744`）与持久缓存 `.ezmk/cache/obj`（`src/build.cpp:650`）已经镜像相对路径，嵌套源天然支持。
- 缓存键含相对路径（`src/cache.cpp`），递归新增的文件首轮是常规 cache miss，**无格式迁移**。
- 若递归改动了既有文件的收集集合（不该发生——默认 flat 不变），需按 1.4.6 的「目录遍历排序」口径复核确定性。

### 3.6 互操作（R-06）

- **export**：`--glob` 目前无条件 `GLOB_RECURSE`；改为 flat 条目用 `GLOB`、递归条目用 `GLOB_RECURSE`，`--no-glob` 按标记决定是否递归遍历。否则导出与 `ezmk build` 的文件集合继续分叉。
- **pack**：`copy_pack_source_dir` 已递归复制，源码包内容不变；消费侧启用递归标记后才能编到子目录。在 pack 文档补一句：*源码包总是递归收录 `src_dirs` 整棵子树，与消费侧是否启用递归无关*。
- **watch**：`ProjectWatch` 对 `src_dirs` 调 `add_directory(..., /*recursive=*/true)`；Windows 走 `ReadDirectoryChangesW` 子树监视（真递归），Linux/macOS 只监视目录自身（`include/ezmk/file_watcher.hpp` 已文档化）。因此 **POSIX 上递归 src_dir 里新增的嵌套文件不会触发重建**，直到「文件监视真递归」另立项。本版必须明确注明，不承诺修复。
- **`compile_commands`**：走 `ezmk.list_sources()`（同一 helper）→ 自动与构建一致。

### 3.7 错误处理与 i18n（R-03）

- 非法 / 不完整标记（如 `"src/**/"`、空条目、`/**` 后还有字符）：**已拍板**按字面目录名处理（沿用「路径原样、缺失 warn」的现有语义）——保持最小惊讶，不新增失败面，也无需新的错误 key。
- 预计新增 0~2 个 i18n 键（例如递归标记的告警）；收口时回填实际键数，`i18n_keys.def` + `locale/en.json` + `locale/zh.json`（+ `zh-TW` 差异键）三向一致。

### 3.8 明确不做

- glob 表达式语言（`**/*.cpp`、排除模式、多段匹配）——只做目录级「递归 / 不递归」。
- 默认改为递归（方案 D）。
- Linux/macOS 文件监视真递归。
- `[workspace] members` 的递归发现（已有 `ezmk workspace scan`）。
- 改变 flat 模式下 `collect_sources` 的既有去重行为。

## 6 跨版本关注点

- **与 1.4.x 既有裁定解耦**：1.4.2 §3.9 / 1.4.7 §3.6 都把「Linux/macOS 文件监视真递归」明确排除，本版沿用该边界（只在文档注明交互影响），真递归另立项。

- **与 2.0.0 解耦**：纯增量，不放宽也不移除任何弃用面（移除清单见 `plans/2.0.x/REMOVALS.md`）。
- **回归基线**：立项时以当次 `bash build.sh test-all` 实测为准（1.4.9 发布态 1137 用例 / 6622 断言 / 4 跳过 / 0 失败仅作参考）；用例 / 断言只增不减，i18n 键数只增不减。
