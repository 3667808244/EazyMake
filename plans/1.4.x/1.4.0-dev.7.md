# EazyMake 1.4.0-dev.7 — workspace scan（现有项目一键采纳）

> 本版本为**用户确认的插队 dev 子版本**：dev.6 已收口 dev 阶段（代码质量审计），经用户决策重新打开 dev 阶段，新增唯一功能项 `ezmk workspace scan`，随后仍归 pre.1 发布前收口。

---

## 1 背景

- workspace（1.3.0）解决了「一个目录下若干独立项目的批量管理」，但**创建 workspace 仍靠手写 `ezmk-workspace.toml`**——对已有目录树（棕地场景：克隆的仓库、CMake 转来的项目、手写的 ezmk 项目）逐个列 `members` 是最大上手障碍。
- `project new`（绿地脚手架）与 `project import --from cmake`（单项目采纳）已覆盖创建/采纳路径；workspace 侧缺少对应的「采纳现有目录树」命令。本版本补上 `ezmk workspace scan`。
- 三个已确认的设计决策：命令名 **`workspace scan`**（非 scan-project）；版本槽位 **1.4.0-dev.7**（提前插队）；已有 `ezmk-workspace.toml` 走**合并更新**（保留既有内容，追加缺失成员）。

## 3 详细设计

### 3.1 命令面

```
ezmk workspace scan [<dir>] [--dry-run] [-y]
```

- `<dir>`：扫描目录，缺省 cwd；必须存在且是目录（否则 `workspace_err_scan_dir` fatal）。
- **定位语义**：`locate_workspace_root(<dir>)` 命中（`<dir>` 自身或向上）→ 以命中的 workspace 根为扫描根（更新该根的文件，覆盖「在成员子目录里执行 scan」的常见流）；未命中 → 以 `<dir>` 为扫描根（新建）。
- `--dry-run`：只预览，不写盘。
- `-y`：跳过合并确认（复用 pkg 的 `confirm()` 模式与 `auto_yes` 键）。
- 简写：`ws` → workspace scan（`kAliases` 加一行，与 wl/wb/wt/wc/ww 简写族一致；已核查无 `ws` 冲突）。
- scan 不接受 `-w`（不是重定向目标）；positionals 至多 1 个（>1 → `cli_too_many_args`）。

### 3.2 扫描语义（workspace.cpp `scan_projects(root)`）

- 递归遍历；**候选成员 = 子目录中含 `ezmk.toml`**；根自身即使有 `ezmk.toml` 也不是成员（容器根）。
- 跳过整个子树：隐藏条目（首字符 `.`，覆盖 `.git` / `.ezmk` / `.vs`）。
- 跳过子树 + 记录原因（`ScanResult.skipped`）：
  - 目录含 `ezmk-workspace.toml`（嵌套 workspace 根——`validate_member` 会判 invalid，直接排除整个子树）；
  - 规范化（`weakly_canonical`）后路径逃出根（符号链接逃逸，复用现有 `canonicalize` + `is_within`）。
- 成员相对路径统一 `/` 分隔（`generic_string()`），**排序输出**保证确定性。
- 成员目录继续下钻（允许嵌套项目：`libs/strutil` 与 `libs/strutil/sub` 可同时是成员）。
- 全部 `error_code` 版本，不可读目录静默跳过。

### 3.3 合并语义（`merge_members(existing, discovered)`）

- 规范化比较：`\` → `/`、去尾部 `/`；去重。
- **保留现有成员顺序**，追加缺失的 discovered（本身已排序）。
- 不做删除（移除成员是手工操作；指向已删目录的成员维持现状 → `workspace list` 显示 invalid，与现状一致）。

### 3.4 写盘（workspace.cpp）

- 新文件：`[workspace]\nmembers = [...]\n`（单行数组，与文档示例一致）。
- 更新：**文本级拼接**——只把 `[workspace]` 节内的 `members` 数组行替换为合并结果（单行数组），其余（`name` / `[workspace.options]` / **注释** / 格式）逐字节保留。选型依据：toml++ v3.4 的 AST **不存储注释**（parser 直接丢弃），formatter 往返会静默丢注释——文本拼接是唯一保留方式；多行数组折叠为单行（可接受）。临时文件 + `util::atomic_rename` 原子落盘。
- 已有文件语法错误 → `read_workspace_members` 在合并前即报错（复用 parse 错误信息），**不覆盖**；无 `[workspace]` 节（退化文件）→ 报错不写。

### 3.5 `run_scan`（workspace_build.cpp）

流程：解析 `<dir>`（缺省 cwd）→ 存在性校验 → 定位扫描根 → `scan_projects` → 分派：

| 场景 | 输出 | 动作 |
|------|------|------|
| 无成员 | `workspace_scan_none` | 退出 0 |
| 新文件 + dry-run | `workspace_scan_would_create` | 不写盘 |
| 新文件 + 写 | `workspace_scan_created` | 写盘 |
| 已有文件、无新增 | `workspace_scan_no_change` | 退出 0 |
| 已有文件 + dry-run | `workspace_scan_would_update` | 不写盘 |
| 已有文件 + 未确认 | `workspace_scan_aborted` | 退出 0 |
| 已有文件 + 确认 | `workspace_scan_updated` | 合并写盘 |

- 跳过项逐条打印 `workspace_scan_skip`（原因 `workspace_scan_skip_nested` / `workspace_scan_skip_escape`）。
- 确认走 `confirm()`（`-y` 跳过，交互 [y/N]）。
