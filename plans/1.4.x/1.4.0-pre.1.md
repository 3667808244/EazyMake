## 3 详细设计

### 3.1 用户触达打磨

1. **顶层别名总表集中核对**：`kAliases` 全表（单/双字母简写：`pb`/`ki`/`wl`/`wb`/`wt`/`wc`/`ww`/`ws` 等）与 `docs/cli.md` 简写表、README 速览、`--help` 输出**三处逐行比对**——确认 dev.5 新增 `ww`、dev.7 新增 `ws` 均已入三处，且无遗漏/冗余。
2. **`--help` 输出复核**：`ezmk --help` / `ezmk workspace --help` / `ezmk project --help` / `ezmk pkg --help` 实际输出与 cli.md 命令表一致（flag、缺省值、`-w` 家族覆盖 build/test/watch/clean、`--member`/`--stop-on-error`/`-j` 语义）。
3. **README 命令速览核对**：`README.md` / `README_ZH.md` 速览节包含 1.4.0 全部新命令（`project export vscode`、`workspace watch`、`workspace scan`），顺序与分组合理。

### 3.2 `CHANGES.md`：API 稳定性承诺扩展 + 1.4.0 聚合条目

- **扩展点清单**（头部「API Stability」节，按 dev 归属）：

| dev | 纳入永久稳定的 API |
|-----|-------------------|
| dev.1 | 命令 `project export vscode`（含 `--overwrite` / `--profile`） |
| dev.2 | 配置 `[pkg] strict_std_check` |
| dev.3 | 行为语义：源码包**编译协商**（包按 `max(包min, 消费者min)` 重编，cap 到工具链能力表与包声明上界） |
| dev.4 | 行为语义：`project import` 保留 CMake `CXX_STANDARD` / `C_STANDARD` → 区间 language（`">=CPP<N>"`） |
| dev.5 | 命令 `watch --run -- <args>` 透传；`workspace watch`（含 `-w` 重定向、`--member`、`--stop-on-error`、`-j`、`--run`、`ww` 简写）；`pack --format tgz` 别名；`pkg install` sha256 边车自动校验（显式 `--sha256`/index 哈希优先） |
| dev.7 | 命令 `workspace scan`（含 `[<dir>]` / `--dry-run` / `-y`、`ws` 简写） |

- **1.4.0 聚合条目**：汇总 dev.1 ~ dev.7 + pre.1（新增 / 行为变更 / 测试 / 已知限制四节，引用各 dev 条目要点；正式发布时按 workflow 3.2 最终更新）。

## 6 跨版本关注点

- **发布门槛**（⛔ 见 [`1.1.0-pre.3.md`](../1.1.x/1.1.0-pre.3.md)）：① 计划清单全部完成或明确收口 ② 公共 API 无破坏性变更 ③ 全量测试零回归（基线 **988 / 5770**，dev.7 后）——门槛未满足即停止，禁止带着未收口项进入正式发布。
- **语言基准**：全项目用户文档以**中文为基准**（docs/zh / README_ZH / tutorial/zh），英文为同步翻译；本计划所有交付遵循「先中文、后英文」。
- **与 dev.1 ~ dev.7 联动**：文档描述的是已实现且回归锁定的行为；核对发现不符时按「实现为准」裁定（实现已过全量回归），文档缺陷直接修文档，实现缺陷才动代码。
- **发布流水线**（winget/Homebrew/pacman）不在 pre.1 范围：需真实 Release 验证的项明确收口到**正式发布阶段**（workflow §3）；若 pre.1 收口后仍有多项未决，追加 pre.2 检查点（机制同 1.2.0）。
- **正式发布依赖本版**：1.4.0 聚合发布（版本置 1.4.0 + tag + Release + 三渠道分发）以 pre.1 全绿收口为前提。
- **与 2.0.0 解耦**：pre.1 不引入任何 deprecation；破坏性变更窗口保持 2.0.0，本版纯增量。
