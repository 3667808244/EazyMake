# EazyMake 1.2.0-dev.12 — 测试配置收口：`[test].default_profile` + `[test].flags` 弃用

> 本计划并入 1.2.0 正式发布版。发布总览见 [`1.2.0.md`](1.2.0.md)。
>
> **dev.3 的延伸**：dev.3 为 `[compile]` 引入 `default_profile`（未传 `--profile` 时回退应用命名 profile），但 `ezmk test` 至今**完全不支持 profile**——CLI 只有 `-f/--framework`、`--filter`、`-V/--verbose`（`src/cli.cpp:344-348`），`run_tests`（`src/build.cpp:1655+`）编译测试用裸 `cfg.compile.*`、链接用裸 `cfg.link.*`。本计划把 profile 机制对称引入测试路径（复用 `[compile.profile.*]` / `[link.profile.*]`，不新建 test profile 表），并顺带收敛 `[test].flags` 与 `[compile].flags` 重叠的配置面（弃用，warn + 继续可用，2.0.0 移除）。

---

## 1 背景

- **`ezmk test` 无 profile 支持**：无法跑 Release / 调试模式的测试，与 `ezmk build --profile` / `[compile].default_profile`（dev.3）不对称。
- **`[test].flags` 与 `[compile].flags` 语义重叠**：测试编译已经带上全部 `[compile]` 标志（`build.cpp:1743-1761`），`[test].flags` 是第二个注入点，仅承担「测试专属标志」，与 profile 机制（flags + macros + msvc_flags 一体的命名配置）重叠。
- 目标：`[test].default_profile` + `ezmk test --profile`，与 build 对称；`[test].flags` 弃用（使用点 warn，2.0.0 移除）。

## 2 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | `[test].default_profile`：`ezmk test` 未传 `--profile` 时回退应用 `[compile.profile.<name>]`（flags/macros/msvc_flags）+ `[link.profile.<name>]`（link flags） | P0 |
| 2 | `ezmk test --profile <name>`：CLI 覆盖 default_profile，与 build 对称（CLI > default_profile > 无） | P0 |
| 3 | profile 解析/合并/未知 profile fatal（含建议）与 build 单一事实源（提取共享 helper，build 路径行为不变） | P0 |

| 5 | 文档（config_file.md / cli.md）+ i18n + 测试（单测 + 集成）；全量测试零回归 | P0 |

## 3 详细设计

### 3.1 配置解析（`src/config.cpp` `parse_test`）

新增 `default_profile` 字段（镜像 dev.3 `[compile].default_profile`，`config.cpp:427-430`）：

```cpp
// 1.2.0-dev.12: default_profile — 未传 --profile 时测试默认应用的 profile
if (auto dp = (*test)["default_profile"].value<std::string>()) {
    cfg.test.default_profile = *dp;
}
```

`[test].flags` 解析不变（仍读入 `cfg.test.flags`）；弃用 warn **不在解析期打**——`parse_config` 对每个依赖包也会调用，避免噪音；改在**使用点**（`run_tests`）打（见 §3.4）。

### 3.2 结构（`include/ezmk/config.hpp`）

```cpp
struct TestConfig {
    std::vector<std::string> dirs = {"test"};
    std::string framework = "catch2";
    std::vector<std::string> flags = {};      // DEPRECATED（1.2.0-dev.12，2.0.0 移除）
    std::string default_profile = "";          // 1.2.0-dev.12
};
```

### 3.3 profile 合并共享 helper（`src/build.cpp`）

现状 build 路径的 profile 合并内联在 `prepare_build_state`（`build.cpp:497-539`）：`--profile` 空 → 回退 `cfg.compile.default_profile` → `merge_compile_profile` 合并 compile profile → 未知 profile fatal（含 closest-match 建议，`build.cpp:508-536`）→ 单独合并 link profile（`build.cpp:538-539`）。

抽取共享 helper，build 与 test 共用：

```cpp
// 1.2.0-dev.12: 解析生效 profile（CLI > default）并合并进 compile/link 配置。
// 未知 profile → ezmk::fatal_error（含 closest-match 建议）。build 与 run_tests
// 共用单一事实源，测试编译/链接与 build 的 profile 语义逐字节一致。
struct AppliedProfile {
    config::CompileSection compile;
    config::LinkSection link;
};
static AppliedProfile apply_profile(const config::EzConfig& cfg,
                                    const std::string& cli_profile,
                                    const std::string& default_profile);
```

- `prepare_build_state` 调用：`apply_profile(cfg, opts.profile, cfg.compile.default_profile)` → 赋值 `st.compile_cfg` / `st.link_cfg`（行为逐字节不变）。
- `run_tests` 调用：`apply_profile(cfg, test_profile, cfg.test.default_profile)` → 测试编译/链接改用结果。

### 3.4 `run_tests` 改造（`src/build.cpp`）

1. 签名追加 `const std::string& test_profile`（`include/ezmk/build.hpp` 同步声明）。
2. 开头：`cfg.test.flags` 非空 → `util::warn(I18nKey::test_flags_deprecated)`（使用点弃用警告，恰好在使用弃用特性时触发）。
3. `base_flags` 构建（1743-1761）从 `cfg.compile.*` 改为 `applied.compile.*`（`ezmk_macros` / `flags` / `macros` / `include_dirs` 用同一套合并后配置）。
4. 链接（1897-1899 catch2 模式；2089-2091 ezmk 模式）从 `cfg.link.*` 改为 `applied.link.*`。
5. `[test].flags` 仍追加（弃用期行为不变）。
