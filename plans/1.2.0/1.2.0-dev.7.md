# EazyMake 1.2.0-dev.7 — 本地包源 + 项目向上查找

> 本计划并入 1.2.0 正式发布版。发布总览见 [`1.2.0.md`](1.2.0.md)。
>
> dev.7 聚合两个相互独立的改进：① 支持从文件夹（源目录）安装包；② `ezmk.toml` 向上查找。二者无依赖，可并行推进。
> （pacman 分发属发布流水线，已拆分为 [`1.2.0-pre.1.md`](1.2.0-pre.1.md)。）

## 1 背景

1. **从文件夹安装包缺口**：`ezmk pkg install` 只接受归档文件（`.zip`/`.tar.gz`）、URL、或已注册仓库的包名。开发/调试本地包时，必须先打包成归档才能安装，无法直接从源目录（`include/` + `src/` + `ezmk.toml`）安装。
2. **项目定位缺口**：`parse_config("ezmk.toml")` 仅在当前工作目录查找。进入项目子目录后运行 `ezmk build`/`ezmk test` 等会因找不到 `ezmk.toml` 而失败，无法像 git 一样"向上查找"。

现状要点：
- `src/pkg.cpp` `install()`（589-…）判断顺序：URL → 本地文件 → 仓库名；`validate_package_dir()`（243）已能校验目录是否为合法包（`ezmk.toml` + `src/` + `include/`，或 `lib/` 预编译、`header_only`）。
- `src/main.cpp` / `src/pkg.cpp` / `src/lockfile.cpp` / `src/cache.cpp` 多处用 `parse_config("ezmk.toml")` 与 `fs::current_path()` 假定 CWD == 项目根。
- `src/config.cpp` `parse_config()`（713）用 `toml_path.parent_path()` 推导项目根——只要传入绝对路径，下游即正确。

## 2 支持从文件夹安装包

> 可以从文件夹安装包，结构与 `docs/zh/pkg.md` 要求的包结构一致。
> 仓库结构的 `packages` 目录下的包也允许使用。

### 2.1 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | `ezmk pkg install <dir>`：参数为已存在目录时，直接从该目录安装（跳过解压），目录结构按 `docs/zh/pkg.md`（`include/` + `src/` + `ezmk.toml`，或预编译/header-only） | P0 |
| 2 | 复用 `validate_package_dir()` 校验目录结构；结构非法 → 清晰报错（复用现有缺 `src/`/`include/`/`ezmk.toml` 的错误路径） | P0 |
| 3 | 目录安装走与归档安装**同一套后处理**：preinstall 钩子 → 依赖解析 → 编译 → 复制 → postinstall 钩子 | P0 |
| 4 | 仓库 `packages/` 目录下的包目录同样可安装（本地 checkout 的 `ezmk-repo/packages/<pkg>/` 解包目录） | P1 |
| 5 | SHA-256 校验对目录安装**不适用**（无归档）——跳过并显式提示；全局安装仍需确认 | P1 |
| 6 | 单测/集成覆盖目录安装 + 非法结构拒绝；全量测试零回归 | P0 |
| 7 | i18n 新 key（en/zh）+ 文档（`pkg.md` 补充目录安装、CHANGES.md） | P1 |

### 2.2 详细设计

**2.2.1 入口判断（`src/pkg.cpp` `install()`，589 起）**

在现有「URL → 本地文件 → 仓库名」判断**之前**加目录分支：

```cpp
fs::path input(pkg_file);
// 新增：目录直接安装（1.2.0-dev.7）
if (fs::is_directory(input)) {
    install_from_directory(input, scope, assume_yes, locked, no_lock);
    return;
}
```

- 判定依据：`fs::is_directory(input)`，与现有「本地文件存在则按文件」逻辑正交——文件走归档分支，目录走新分支，不存在则继续仓库查找。
- 无需新增 flag：`pkg install ./mylib` 当 `./mylib` 是目录时自动识别。

**2.2.2 `install_from_directory()`（新函数）**

- 先 `validate_package_dir(dir)` 校验结构（复用 243 行逻辑，注意它当前对 header-only / precompiled / 普通库的分支已覆盖）。
- 校验通过后，把现有 `install()` 中「解压 + 定位 pkg_root（703-720）+ 钩子 + 依赖 + 编译 + 复制」的后处理抽成可复用段，`pkg_root = dir`（**不复制、不打包**，直接以源目录为安装源）。
- **作用域语义**：目录安装仍支持 `-p/-u/-g` 三作用域，安装路径与归档安装一致（`<scope>/pkg/<name>/`）。
- **SHA-256 跳过**：目录安装无归档，`--sha256` 忽略并输出提示（i18n 新 key）。
- **依赖解析**：目录内 `ezmk.toml` 的 `[depends]` 照常解析；缺失硬依赖走现有「从已注册仓库自动安装」逻辑。

**2.2.3 仓库 `packages/` 目录支持**

- 本地 checkout 的 `ezmk-repo` 中 `packages/` 当前存 `.tar.gz` 归档（归档分支已支持）。若为**解包后的包目录**（`packages/<name>/` 含 `ezmk.toml` + `src/`），目录分支天然覆盖，无需特殊处理——只需文档说明「从文件夹安装可用本地 checkout 仓库里解包的包目录」。

### 2.3 执行步骤

- [ ] **2.1 入口分支**：`install()` 加 `fs::is_directory` 判断，分流到 `install_from_directory`
- [ ] **2.2 后处理抽取**：把解压后处理抽为可复用函数，目录分支复用（`pkg_root = dir`）
- [ ] **2.3 SHA-256/确认**：目录安装跳过 SHA-256 并提示；全局安装确认保留
- [ ] **2.4 i18n**：`install_from_dir` / `sha256_skipped_dir` 等 key（en/zh），`check_i18n.py` 通过
- [ ] **2.5 测试**：单测（目录安装成功、非法结构拒绝）+ 集成（建临时包目录 → `ezmk pkg install <dir>` → `ezmk pkg list` 可见）；全量零回归
- [ ] **2.6 文档**：`docs/en|zh/pkg.md` 补「从文件夹安装」小节 + CHANGES.md

## 3 支持 `ezmk.toml` 的向上查找功能

> 如果当前目录没有 `ezmk.toml`，就向其父目录查找，最多 5 层。

### 3.1 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | 新增 `util::locate_project_root()`：从 CWD 起向上查找含 `ezmk.toml` 的目录，最多 5 层父目录；找到返回该目录，否则回退 CWD（保持现状行为） | P0 |
| 2 | `main.cpp` 各命令（build/run/test/watch/project/cc 等）在解析配置前先定位项目根，用绝对路径 `parse_config(root/"ezmk.toml")`，`proj_root` 统一取定位结果 | P0 |
| 3 | `pkg.cpp`（lockfile/install 目录）、`cache.cpp` 的 `fs::current_path()` 同步改为定位后的项目根 | P0 |
| 4 | 找不到 `ezmk.toml` 时错误信息仍清晰（提示「在 5 层父目录内未找到 ezmk.toml」） | P1 |
| 5 | 单测覆盖：项目根、子目录（1~5 层）、超出 5 层回退、无 `ezmk.toml`；全量测试零回归 | P0 |
| 6 | i18n + 文档（`cli.md`/README 说明向上查找行为、CHANGES.md） | P1 |

### 3.2 详细设计

**3.2.1 `util::locate_project_root()`（`src/util.hpp`/`util.cpp` 新增）**

```cpp
// 从 start 起向上查找含 ezmk.toml 的目录，最多向上 max_up 层父目录。
// 找到 → 返回该目录；未找到 → 返回 nullopt（调用方回退 start）。
std::optional<fs::path> locate_project_root(const fs::path& start, int max_up = 5);
```

- 遍历：`cur = start`；循环 `max_up + 1` 次（含 start 自身），每次检查 `cur/"ezmk.toml"` 存在即返回 `cur`；否则 `cur = cur.parent_path()`；越过 `max_up` 层仍未找到 → `nullopt`。
- **语义**：start（CWD）记为第 0 层，最多检查到第 5 层父目录（共 6 个候选目录）。

**3.2.2 接入点**

- `src/main.cpp`：在命令分发处（或各命令入口）统一 `auto root = util::locate_project_root(fs::current_path()).value_or(fs::current_path());`，之后 `parse_config((root/"ezmk.toml").string())`，`proj_root = root`。覆盖 `generate_compile_db_entry`（45）、watch（285-340）、以及 40/149/156/182/194/210/233/244 等 `parse_config("ezmk.toml")` 调用。
- `src/pkg.cpp`：`install()`/`lockfile` 用 `fs::current_path()` 处（427、596、1040、1084）改用定位根；`pkg_install_dir(Project)`（80）的 `.ezmk/pkg` 路径也随根。
- `src/lockfile.cpp` / `src/cache.cpp`：`lockfile_path`/`cache dir` 的 `fs::current_path()` 传入定位根。
- **回退保证**：找不到 `ezmk.toml` 时行为与现状一致（不新增报错面），仅在找到时才改变 `proj_root`。

**3.2.3 设计决策**

| 决策 | 说明 |
|------|------|
| 最多 5 层 | 常量 `PROJECT_ROOT_MAX_UP = 5`，防误扫到用户 home / 系统根 |
| 回退 CWD | 未找到时保持现状，不破坏「无配置场景」（如 `ezmk project new` 无需查找） |
| 单一入口 | `locate_project_root()` 收敛查找逻辑，避免各命令重复实现 |
| 不改公共 API | 纯内部定位，不新增 flag / 配置字段 |

### 3.3 执行步骤

- [ ] **3.1 工具函数**：`util::locate_project_root()` + 单测（0/1/5/6 层、无 toml）
- [ ] **3.2 main.cpp 接入**：各命令统一定位项目根，`parse_config` 改绝对路径
- [ ] **3.3 pkg/cache/lockfile 接入**：`fs::current_path()` → 定位根

## 5 跨版本关注点

- **与 1.2.0 主线**：dev.7 两块均纯增量，不触碰 dev.1~dev.6 的命令构造/导出/导入逻辑；与 dev.5/dev.6 相互独立，可并行。

- **分发渠道**：pacman 分发已拆至 [`1.2.0-pre.1.md`](1.2.0-pre.1.md)（发布流水线阶段），与 dev.7 无代码依赖。
