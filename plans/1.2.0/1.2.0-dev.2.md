# EazyMake 1.2.0-dev.2 — CMakeLists.txt 导出

> 本计划并入 1.2.0 正式发布版。发布总览见 [`1.2.0.md`](1.2.0.md)。

---

## 1 背景

`ezmk.toml` 是 EazyMake 项目的唯一配置源。但大量 IDE（CLion / VS Code 扩展）、工具链、CI 与第三方库（以 `CMakeLists.txt` + `find_package` 生态）以 CMake 为事实标准。目前 EazyMake 项目**无法导出**到 CMake，用户想用 CMake 生态构建/索引 EazyMake 项目只能手写 `CMakeLists.txt`，既重复又易与 `ezmk.toml` 漂移。

本计划新增 `ezmk project export cmake`：从当前项目的 `ezmk.toml` **一键生成** `CMakeLists.txt`。定位：

- **单向生成**：`ezmk.toml` 是事实源，导出的 `CMakeLists.txt` 是一次性快照，明确"重新生成、勿手改"。
- **互操作**：让同一项目既可用 `ezmk build`，也可被 CMake 生态构建/索引。
- **命名可扩展**：`project export <target>` 作为子命令，未来可扩展 `project export make` / `project export meson`。

## 3 详细设计

### 3.1 命令面

```
ezmk project export cmake                     # 输出 <proj_root>/CMakeLists.txt
ezmk project export cmake -o build/CMakeLists.txt   # 自定义输出路径
ezmk project export cmake --overwrite         # 覆盖已存在的 CMakeLists.txt
ezmk project export cmake --profile debug     # 应用 build profile 的标志/宏
ezmk project export cmake --resolve           # 依赖导出具体安装路径（非便携）
ezmk project export cmake --no-glob           # 源文件用显式列表而非 GLOB
ezmk project export make | meson              # 未来扩展
```

| 项 | 值 |
|---|---|
| 命令枚举 | `Command::ProjectExport`（`export` 为 `project` 子命令，首个 target `cmake`） |
| 命令形式 | `ezmk project export <target>` |
| flags | `-o/--output <path>`、`--overwrite`、`--profile <name>`、`--resolve`、`--glob`/`--no-glob` |

> **命名理由**：命令挂在 `project` 命名空间下，与 `ezmk project cc` 一致；`export` 作为 `project` 的子命令，用 `<target>` 参数区分导出格式，为未来 `make`/`meson` 预留扩展。不新增顶层别名/简写，保持与用户指定的命名一致。

**行为约束**：
- 无 `ezmk.toml` → 复用项目定位逻辑报错。
- `--glob`（默认）：`file(GLOB_RECURSE ... CONFIGURE_DEPENDS)`，镜像 ezmk 运行时按目录收集源文件的语义（新增文件不需重新导出）；`--no-glob` 输出显式文件列表（确定性、可审阅）。
- `--overwrite` 未给出且目标已存在 → 拒绝并提示（exit 1），打印现有文件摘要帮助用户判断。
- `[hooks]`（`pre_build`/`post_build`/`on_failure`）：**不映射**——钩子是 EazyMake 沙箱 Lua（`ezmk.*` API），CMake 无等价运行时。导出时生成注释块列出配置的钩子并说明「EazyMake 特有、不导出」；配置了钩子则输出 `message(WARNING)` 提示 CMake 构建不会执行钩子（产物不经钩子后处理）。与 `[utils]` 类型「跳过 + `message(WARNING)`」同模式。

### 3.2 项目级映射

```cmake
cmake_minimum_required(VERSION 3.16)
# Generated by `ezmk project export cmake` from ezmk.toml — do not hand-edit; regenerate.
project(<name> VERSION <version> LANGUAGES <C|CXX>)
```

| `ezmk.toml` | CMake |
|---|---|
| `[project].name` | `project(<name> ...)` |
| `[project].version` | `VERSION <ver>` |
| `[project].language`（`C++17`/`C11`/…） | `LANGUAGES CXX/C`；`-std=` 另行映射到 `CXX_STANDARD` |
| `[project].type = "executable"` | `add_executable(<name> <srcs>)` |
| `[project].type = "static"` | `add_library(<name> STATIC <srcs>)` |
| `[project].type = "shared"` | `add_library(<name> SHARED <srcs>)` |
| `[project].type = "utils"` | 跳过 + `message(WARNING)`（utils 是包格式，无 C++ target） |
| `[project].header_only = true` | `add_library(<name> INTERFACE)` |
| `[project].precompiled = true` | `add_library(<name> IMPORTED)` 链接预编译归档（见 §3.6） |

### 3.3 编译映射

源文件收集（`--glob` 默认）：

```cmake
file(GLOB_RECURSE <name>_SOURCES CONFIGURE_DEPENDS
    ${CMAKE_CURRENT_SOURCE_DIR}/src/*.cpp
    ...)
```

按 `project.language` 选择扩展名（C++: `*.cpp *.cc *.cxx *.c++`；C: `*.c`）。支持多 `src_dirs`，逐目录生成 glob 行。`--no-glob` 用 `target_sources(<name> PRIVATE <显式列表>)`。

include / 宏 / 标准 / 选项：

```cmake
target_include_directories(<name> PRIVATE ${CMAKE_CURRENT_SOURCE_DIR}/include ...)
target_compile_definitions(<name> PRIVATE EZMK=1 EZMK_VERSION="..." <[compile].macros>)
set_target_properties(<name> PROPERTIES CXX_STANDARD <N> CXX_STANDARD_REQUIRED ON)
set_target_properties(<name> PROPERTIES CXX_EXTENSIONS OFF)   # GNU 前缀 → ON
target_compile_options(<name> PRIVATE <剩余 flags>)
target_compile_options(<name> PRIVATE $<$<COMPILE_LANG_AND_ID:CXX,MSVC>:<msvc_flags>>)
```

**标志拆分规则**（把 `[compile].flags` 按语义归类，避免 CMake 重复管理）：

| 标志类别 | 映射 |
|---|---|
| `-std=<ver>` / `-std=gnu++<ver>` | `CXX_STANDARD` / `CXX_EXTENSIONS` |
| `-I<dir>` | `target_include_directories` |
| `-D<mac>` | `target_compile_definitions` |
| 其余（`-Wall`、`-O2`、`-g`…） | `target_compile_options` |
| `msvc_flags` | genex 包裹的 `target_compile_options` |

**宏**：`[compile].macros` + `ezmk_macros`（`EZMK`/`EZMK_VERSION`/`EZMK_PROJECT_NAME`/…）与 `ezmk build` 注入**完全一致**（复用 `generate_ezmk_macros()`），保证 CMake 与 ezmk 构建下的条件编译行为一致。

**stdlib**：`project.stdlib` → best-effort genex：

```cmake
target_compile_options(<name> PRIVATE $<$<COMPILE_LANG_AND_ID:CXX,Clang>:-stdlib=libc++>)
```

**include 路径处理**：`include_dirs` 解析 `@link:` 后，项目内路径用 `${CMAKE_CURRENT_SOURCE_DIR}/` 前缀（相对、可移植），项目外路径（`@link:` 到外部目录）用绝对路径并加注释。

### 3.4 链接映射

```cmake
target_link_directories(<name> PRIVATE <link_dirs 解析 @link:>)
target_link_libraries(<name> PRIVATE pthread ...)          # system_targets 去 -l
target_link_options(<name> PRIVATE <link.flags 去 -L/-l>)
target_link_options(<name> PRIVATE $<$<COMPILE_LANG_AND_ID:CXX,MSVC>:<link.msvc_flags>>)
```

拆分规则：`link_dirs` → `target_link_directories`；`system_targets`（如 `pthread`）→ `target_link_libraries`（去 `-l` 前缀）；`link.flags` 去 `-L`/`-l` 后 → `target_link_options`。

### 3.5 依赖映射（`[depends]`，P1 best-effort）

ezmk 的依赖是从仓库生态安装的静态库（`.a`/`.lib`），多数不提供 CMake config。两种模式：

**默认（便携，best-effort）**：

```cmake
# --- dependency: openssl ---
find_package(OpenSSL QUIET)
if(TARGET OpenSSL::SSL)
    target_link_libraries(<name> PRIVATE OpenSSL::SSL OpenSSL::Crypto)
else()
    message(STATUS "dependency 'openssl': CMake target unknown — add manually")
endif()
```

- 内置**常见包别名映射表**（`包名 → find_package 名称 + target`）：`catch2`→`Catch2`、`openssl`→`OpenSSL`、`libcurl`→`CURL`、`protobuf`→`protobuf`、`eigen`→`Eigen3`、`googletest`→`GTest`、`fmt`→`fmt`、`spdlog`→`spdlog`、`nlohmann_json`→`nlohmann_json::nlohmann_json`、`sqlite3`→`SQLite3`、`zlib`→`ZLIB`、`lua`→`Lua`、`tomlplusplus`→`tomlplusplus` 等。
- 映射表未覆盖 → 生成 `find_package(<Pkg> QUIET)` + `if(TARGET <Pkg>)` 占位 + `message(STATUS)` 提示手动补充。
- `[depends].want` → 同结构但非 REQUIRED，`if(TARGET ...)` 才链接。

**`--resolve`（具体，本机立即可用但不可移植）**：解析已安装依赖（project → user → global 作用域），输出：

```cmake
target_include_directories(<name> PRIVATE <installed>/pkg/openssl/include)
target_link_libraries(<name> PRIVATE <installed>/pkg/openssl/lib/libopenssl.a)
```

> **为什么默认不 `--resolve`**：安装路径（`~/.local` / `%LOCALAPPDATA%`）不可移植，提交进 git 会在别的机器失效。默认走便携 `find_package`，需要"立刻能构建"时用 `--resolve`。

### 3.6 预编译 / 头文件包

- `header_only = true`：`add_library(<name> INTERFACE)` + `target_include_directories(<name> INTERFACE <include>)`。
- `precompiled = true`：`add_library(<name> IMPORTED)`，`IMPORTED_LOCATION` 指向 `lib/lib<name>.a`（或 `--resolve` 到安装路径）；`INTERFACE_INCLUDE_DIRECTORIES` 指向 `include/`。

### 3.7 进阶映射（P2，可选/延后）

| `ezmk.toml` | CMake | 状态 |
|---|---|---|
| `[compile.profile.<name>]` | 默认导出 base；`--profile` 应用指定 profile 内联；可选 genex `$<$<CONFIG:Debug>:...>` 对照 `[compile.profile.debug]` | P2 |
| `[test]`（ezmk 内置框架） | `enable_testing()` + 每个测试源 `add_executable` + `add_test`（镜像 `ezmk test` 逐文件独立可执行语义） | P2 |

| `deterministic` | best-effort：GCC `-ffile-prefix-map` / MSVC `/Brepro` + 注释说明局限 | P2 |

## 6 跨版本关注点

- **单向快照语义**：导出不可逆（不读回 `CMakeLists.txt` 同步 `ezmk.toml`），文档必须讲清。若未来需要反向同步，另立版本。
- **`@link:` 一致性**：导出路径解析须与 `config.cpp::resolve_link_path()` 完全一致（复用同一函数），避免导出与实际构建目录不一致。
- **宏一致性**：`ezmk_macros` 值（如 `EZMK_VERSION`）须与构建注入一致，防止 CMake 下条件编译行为漂移。
- **`project export` 扩展**：`Command::ProjectExport` 预留 `export <target>` 子命令分发（`cmake` 首个），未来 `make`/`meson` 复用同一骨架与 i18n 前缀。
