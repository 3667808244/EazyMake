# EazyMake 1.2.0-dev.6 — 各源文件构建耗时统计

> 本计划并入 1.2.0 正式发布版。发布总览见 [`1.2.0.md`](1.2.0.md)。

---

## 1 背景

`ezmk build` 已显示总耗时（0.9.6+，`build_elapsed_time`，并行模式），但用户无法知道**哪个源文件最慢**。排查编译瓶颈只能靠猜或外置计时。本计划为构建补上 **per-file 编译耗时明细**：按耗时降序列出本次实际编译的源文件，让"慢在哪一步"一目了然——纯诊断增强，**零配置、不改变构建语义**，符合"易用优先、功能从简"的设计理念。

现状要点（`src/build.cpp`）：
- `compile_phase()`（803-971）并行分支（872-912）每个任务调用 `cache::compile_one_source()`，返回值含 `rel_src` / `cache_hit`——计时挂点现成。
- 完成汇总块（952-968）已输出总耗时与缓存统计，明细在此基础上扩展。

## 3 详细设计

### 3.1 计时（`src/build.cpp` `compile_phase()` 并行分支，872-912）

- 并行任务 lambda（886-901）内 wrap `cache::compile_one_source()`：任务开始 `steady_clock::now()`，结束取差值。
- `cache::SingleCompileResult` 已有 `rel_src` / `cache_hit`；**不改 cache.hpp**——耗时在 build.cpp 本地收集（`std::vector<TimeEntry>`，`rel_src` + elapsed_ms，与 `single_results` 按序对应）。
- **只计入 cache_miss（实际编译）** 的文件；cache_hit 文件耗时 ≈ 0，跳过——避免把缓存命中误报为"编译快"。
- **串行路径边界**：`compile_sources()`（911）为黑盒，不产出 per-file 计时；单线程小项目仅显示总耗时。

### 3.2 输出（`compile_phase()` 完成汇总块 952-968 扩展）

- 总耗时（`build_elapsed_time`）输出**不变**。
- 新增明细，两种触发：
  - `-v/--verbose`：完整排序明细（非缓存文件，耗时降序）。
  - 默认：总耗时 > `BUILD_TIME_SLOW_THRESHOLD`（常量 5s）→ 最慢 `BUILD_TIME_TOP_N`（常量 10）+ 汇总行。
- 明细格式（示例）：

  ```
  slowest compile units (8 compiled, 4.2s):
      2.1s  src/render/core.cpp
      1.3s  src/parser/lexer.cpp
      0.8s  src/main.cpp
  ```

- 与既有 `-v` 逐文件进度（`[i/N] rel_src`）不冲突——明细是汇总后的诊断表，非逐条进度。

### 3.3 设计决策

| 决策 | 说明 |
|------|------|
| 不新增 flag / 配置字段 | 复用 `-v` + 命名常量，零配置面，符合"易用优先" |
| 阈值 5s / top-10 为常量 | `BUILD_TIME_SLOW_THRESHOLD` / `BUILD_TIME_TOP_N`，不做成配置字段 |
| 只统计非缓存文件 | 明细反映**实际编译**成本 |
| 串行路径不细化 | 避免侵入 cache 模块重构，改动最小 |
| 计时在 build.cpp | 不改 `cache.hpp` / `SingleCompileResult` |

## 6 跨版本关注点

- **与既有构建输出协同**：总耗时（`build_elapsed_time`，0.9.6+）与逐文件进度（`[i/N]`）保留；明细是其上的诊断汇总。
- **哲学边界**：零配置诊断，与 dev.3（默认模板零配置工程化）同一取向；**不做成完整 profiling 子系统**（火焰图/交互 UI 属 CMake 或专用工具范畴）。
- **与 dev.1/dev.2 无关**：纯 build 输出层改动，不触碰 `project cc` / `export cmake` 的命令构造。
- **回归基线**：全量测试零回归（当前 546 用例 / 2617 断言，含集成 556 / 2666）。
