# EazyMake 1.2.0-dev.4 — CMake 项目导入（实验性）

> 本计划并入 1.2.0 正式发布版，作为 **1.2.0 的高级实验性功能**。发布总览见 [`1.2.0.md`](1.2.0.md)。

---

## 1 背景

目前使用 CMake 的项目无法导入 EazyMake，可能影响 CMake 用户的转化。`ezmk project export cmake`（dev.2）提供了 EazyMake → CMake 的单向导出；本计划补齐反向通道：**CMake → EazyMake** 的 `ezmk project import` 命令，让标准 CMake 项目无缝转化为 EazyMake 项目。

定位：
- **实验性**：转换是 best-effort，非标准写法明确拒绝并指引手动迁移。
- **单向快照**：转换后 `ezmk.toml` 成为唯一事实源（与 export 互补，不保证可逆往返）。
- 面向「最最标准」的 CMake 项目，覆盖大多数小型/单 target 项目。

## 3 详细设计

### 3.1 命令（`ezmk project import`）

```
ezmk project import --from cmake    # 导入当前目录的 CMakeLists.txt → ezmk.toml
ezmk project import                  # --from 省略，默认 cmake
ezmk project import --from CMAKE     # 大小写不敏感
ezmk project import --overwrite      # 已存在 ezmk.toml 时显式覆盖
```

| 项 | 值 |
|---|---|
| 命令枚举 | `Command::ProjectImport` |
| `--from <format>` | 导入的项目类型；目前**仅支持 `cmake`**（解析时大小写不敏感）；省略时默认 `cmake`，为未来其他格式预留 |
| `--overwrite` | 项目根已存在 `ezmk.toml` 时默认**拒绝**（避免覆盖手写配置），显式传此 flag 才覆盖 |
| 实验性提示 | 转换成功后输出提示：`ezmk project import --from cmake` 为实验性功能，请手动校对库链接与平台宏 |

**前置条件**：项目根必须存在 `CMakeLists.txt`；缺失则报错退出。无 `ezmk.toml` 时生成新文件。

### 3.2 导入范围：核心目标

支持将**最标准的 CMake 项目**无缝转化为 EazyMake 项目。支持解析的 CMake 命令：

| CMake 命令 | 映射到 `ezmk.toml` |
|---|---|
| `project(name VERSION x.y.z LANGUAGES CXX/C)` | `[project]` `name` / `version` / `language` |
| `add_executable(t ...)` | `[project]` `type = "executable"`，`name = t` |
| `add_library(t STATIC/SHARED ...)` | `type = "static"` / `"shared"` |
| `target_sources(t PRIVATE <src...>)` | 源文件归入 `[compile].src_dirs`（源文件所在目录） |
| `target_include_directories(t PRIVATE <dir...>)` | `[compile].include_dirs` |
| `target_compile_definitions(t PRIVATE <NAME=VAL...>)` | `[compile].macros` |
| `target_compile_options(t PRIVATE <flag...>)` | `[compile].flags` |
| `target_link_libraries(t PRIVATE <lib...>)` | `[link].system_targets` + `[depends]`（见 §3.3） |

**多 target 项目**：仅导入第一个/主 target，其余输出 warning 并在生成的 `ezmk.toml` 注释说明（单 target 项目映射最干净，多 target 建议分项目）。

**解析器**：轻量 CMake 函数调用解析器——识别 `命令名(参数...)` 结构，正确处理双引号字符串、括号嵌套、`#` 注释、`[[...]]` 长字符串；对**不支持**的命令按 §3.4 策略处理。不引入第三方 CMake 解析库。

**变量展开（`${VAR}`）策略**（1.2.0-dev.4 设计补充）：

CMake 的 `target_*` 命令普遍用 `${VAR}` 引用源文件/定义/目录（如 `target_sources(t ${SRCS})`），解析器若不做任何变量求值，§3.2 核心映射在真实项目上会大面积落空。但完整求值（作用域、`CACHE`、条件、递归、`$ENV{}`）超出轻量解析器的范围。因此采取**有限单层展开 + 不可解析处 best-effort** 的分级策略：

1. **有限变量表**：仅捕获同时满足以下条件的 `set(<name> <常量>...)`，记入内部变量表：
   - value 全为常量字符串 / 字符串列表，不含 `${}`、`$<...>`、`$ENV{}`
   - `set` 出现在文件**顶层、条件块之外**（条件块内的 `set` 不入表——分支未定，避免错配）
   - 变量此后被**任何**命令修改（再次 `set` 覆盖、`list(APPEND ...)`、`string(...)`）→ 该变量从表中剔除并标记「不可解析」
2. **展开规则**：仅在映射命令（§3.2 表内 8 个命令）的参数上做**单层、非递归**展开 `${VAR}`；展开结果仍含 `${}` 或 `$<...>` → 该参数视为不可解析。
3. **不可解析参数的统一处置**（避免逐命令拍脑袋）：
   - 出现在映射命令**关键参数**（如 `target_sources` 的源文件、`target_compile_definitions` 的值）→ 命令**其余参数照常映射**，该参数留 `# TODO: 未解析的参数 <原文>` 注释；若整条命令因此无法产生有意义的配置 → warning + 跳过该命令 + TODO 注释（best-effort，**不中止**）
   - `$ENV{}` → best-effort：warning + 跳过该参数 + TODO 注释（不中止）
   - 生成器表达式 `$<...>` → 维持 §3.4 **明确拒绝**（事务性中止）
4. **明确不做什么**（防止解析器失控）：
   - 不实现变量作用域（`function()`/`macro()` 内局部变量）、`CACHE` 变量、`if` 条件求值下的变量
   - 不展开 `$ENV{}`、不做 `${VAR}` 嵌套递归求值
   - 不解析 `list()`/`string()`/`file()` 等命令——它们的副作用只用于「剔除变量」，不做输出

> 优先级与 §3.4 一致：`${VAR}` 属**声明式写法**，只是暂无法求值 → 归 best-effort 跳过；生成器表达式属**非声明式** → 明确拒绝。`find_package` 的版本参数不在此列，走 §3.3.1 的 `@` 版本语法。

### 3.3 导入范围：best-effort（尽可能处理）

这些情况**不能崩溃**，而是合理地执行可能失败的操作：

1. **依赖处理（`find_package`）**：
   - 不要试图解析 `FindXXX.cmake`。
   - **策略**：在生成的 `ezmk.toml` 的 `[depends]` 中，**自动填入**转换时识别到的包名并**注释掉**，旁边加一条 i18n 提示：

     ```toml
     [depends]
     # TODO: 原 CMake 引用了 Boost，请手动执行 `ezmk pkg install boost` 后取消注释
     # lib = ["boost@1.82"]
     ```

   - **包名映射**：`find_package(Boost ...)` 的 CamelCase 名 → ezmk 仓库小写包名（`boost`）；内置常见包别名表（`Boost`→`boost`、`OpenSSL`→`openssl`、`CURL`→`libcurl`…），与 dev.2 导出命令**共享同一张别名表**（见 §6）。版本约束按 ezmk `@` 语法（`boost@1.82`）。
   - `target_link_libraries` 中无法识别的库名 → 写入 `[link].system_targets`（去 `-l` 前缀），并注释提示。

2. **条件编译**：
   - 识别常见平台条件（`MSVC`、`WIN32`、`UNIX`、`APPLE`、`CMAKE_SYSTEM_NAME` 等），按**当前平台**展开所取分支。
   - 无法求值的条件（如自定义变量、`$ENV{}`）→ warning + 跳过该条件块，并在生成文件注释 `# TODO: 未求值的条件块 <原文>`，供用户手动补充。
   - 绝不崩溃；每次跳过都留下可追溯的注释。

### 3.4 导入范围：明确拒绝

碰到以下**非声明式**写法，**直接中止转换**（事务性——不产出半成品 `ezmk.toml`），提示用户手动迁移：

- **自定义命令**：`add_custom_command`、`add_custom_target`（比如构建前自动生成某些 `.h` 文件）。
- **生成器表达式**：`$<TARGET_FILE:`、`$<JOIN:` 等。
- **函数/宏定义**：CMake 里自定义的 `macro()` 和 `function()`。
- **外部依赖查找**：`pkg_check_modules`、`execute_process`。

> **报错文案**（i18n）：`检测到 {不支持的内容}，EazyMake 导入器暂不支持非标准构建步骤，请参考迁移文档手动添加 Lua 脚本`
>
> 迁移文档见 §7（`docs/en|zh/migrate-from-cmake.md`），指引手动迁移：用 Lua 构建钩子（`[hooks]`）复刻自定义步骤。

### 3.5 生成物（`ezmk.toml`）与头部注释

在生成的 `ezmk.toml` 头部加上注释：

```toml
# ============================================
# 此文件由 `ezmk project import --from cmake` 自动生成 (v1.2.0)
# 基于: CMakeLists.txt
# 转换时间: {iso8601时间戳}
# 该命令为实验性功能，请手动校对库链接和平台宏定义
# ============================================

[project]
name = "..."
...
```

- 转换后 `ezmk.toml` 为唯一事实源；再次修改请直接编辑 `ezmk.toml`，不要回改 `CMakeLists.txt`。
- 时间戳复用构建缓存同款 ISO 8601 工具。

## 6 跨版本关注点

- **与 dev.2（`export cmake`）互补**：export 是 EazyMake → CMake 单向快照；import 是 CMake → EazyMake 单向转换。**不保证可逆往返**（export 产出"重新生成、勿手改"快照；import 拒绝非标准写法）。
- **共享包名别名表**：dev.2 导出（CMake target ← ezmk 包）与 dev.4 导入（find_package 名 → ezmk 包）共用同一张常见包别名映射表，避免两处漂移。建议抽取到公共头文件（如 `src/pkg_alias.hpp`）。
- **实验性定位**：`--from cmake` 在稳定前可调整语义；若需要破坏性调整，集中在 2.0.0 窗口。
- **与 1.1.1 的 `compile_commands` 联动**：导入后项目开箱即可用 `ezmk project cc`（dev.1）/ `compile_commands` 自动生成（1.1.1）与 dev.3 的模板 Profile，构成完整「从 CMake 迁入」体验。
- **回归基线**：当前全量测试 546 用例 / 2617 断言（含集成 556 / 2666），新增命令不得引入回归。
