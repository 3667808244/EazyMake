# EazyMake 1.2.0 — 工具链互操作与开箱工程化

> **正式发布计划**。聚合 `1.2.0-dev.1`（`ezmk project cc` 命令）、`1.2.0-dev.2`（CMakeLists.txt 导出）、`1.2.0-dev.3`（默认模板内建 Debug/Release Profile）、`1.2.0-dev.4`（CMake 项目导入，实验性）、`1.2.0-dev.5`（catch2 v3 测试主程序兼容）、`1.2.0-dev.6`（各源文件构建耗时统计）、`1.2.0-dev.7`（从文件夹安装包 + ezmk.toml 向上查找）、`1.2.0-dev.8`（CMake 导出钩子运行时）、`1.2.0-dev.9`（包构建配置收敛）、`1.2.0-dev.10`（平台标识符扩展：工具链/ABI）、`1.2.0-dev.11`（代码质量审查与改进）、`1.2.0-pre.1`（pacman 分发）、`1.2.0-pre.2`（README 整理与高级特性触达）。dev.1 的**核心重构**（`build_compile_args()`/`compile_db`/拦截）已由前置补丁 **[1.1.1](../1.1.x/1.1.1.md)**（拦截 `ezmk utils cc`）先行交付。

## 1 背景

1.1.0 正式版发布后，`ezmk` 的核心构建体验已稳定。但"开发工具互操作"缺口仍未闭合：

1. **`compile_commands.json` 仍是外置工具**。由 `ezmk-official-utils` 包中的 Lua 工具（`ezmk utils cc`）生成，存在两类问题：
   - **命令 drift**：Lua 工具自行重拼编译命令，与 `ezmk build` 真实命令系统性偏离（缺 `@link:`/依赖包 include/宏/`-stdlib`/`-fPIC`/profile/MSVC 翻译等）。
   - **外置依赖**：需先安装 `ezmk-official-utils` 包才能使用。
   - 命令构造重构、对 `ezmk utils cc` 的**拦截**（改由内置 C++ 生成器服务）、以及 `[compile].compile_commands` **构建后自动生成**均在 **1.1.1** 落地（`build_compile_args()` + `compile_db` 模块）。1.2.0 补齐最后一步：新增**正式命令** `ezmk project cc`（零外部包依赖），并弃用 `ezmk utils cc`。

2. **无法导出到 CMake 生态**。`ezmk.toml` 是唯一配置源，但大量 IDE / 工具链 / CI 生态以 `CMakeLists.txt` 为准。缺少从 EazyMake 项目**一键生成 CMakeLists.txt** 的通道。

3. **默认模板缺少工程化配置**。`ezmk project new` 生成的 `ezmk.toml` 没有内建 Debug/Release Profile，用户需自行手写。

本版本目标：新增 `ezmk project cc` 命令（内化完成）、新增 `ezmk project export cmake` 互操作命令、让默认模板**开箱自带 Debug/Release Profile**。均为**纯增量**（唯一行为变更：新项目默认模板去 `-O2`、优化归 profile），不触碰 1.1.0 起的 API 稳定性承诺。

## 3 详细设计

### 3.0 compile_commands 内化（`ezmk project cc` 命令）

> 命令构造**单一事实源**基础（`build_compile_args()` / `join_shell_args()`）、`compile_db` 模块、以及对 `ezmk utils cc` 的 C++ 拦截，均由 **1.1.1** 交付（[`plans/1.1.x/1.1.1.md`](../1.1.x/1.1.1.md)）。本版本的 `ezmk project cc` 命令交付见 **[`1.2.0-dev.1.md`](1.2.0-dev.1.md)**，要点：

- **命令**：`ezmk project cc`（`Command::ProjectCc`），flags `-o/--output <path>`（默认 `<proj_root>/compile_commands.json`）、`--profile <name>`。
- **输出**：沿用 1.1.1 `compile_db`（`arguments` 数组、相对项目根、排序、原子写），生成器核心零改动。
- **弃用 `ezmk utils cc`**：拦截迁移为新命令后，`ezmk utils cc` 输出弃用提示（`use ezmk project cc instead`），工具保留可用，2.0.0 移除。
- **自动生成已在 1.1.1**：`[compile].compile_commands = true` → `ezmk build` 后自动生成（见 [`../1.1.x/1.1.1.md`](../1.1.x/1.1.1.md) §3.4），本版不重复。

### 3.2 命令面

| 功能 | 命令形式 | 关键 flag |
|------|----------|-----------|
| compile_commands 内化 | `ezmk project cc` | `-o/--output <path>`、`--profile <name>` |
| CMake 导出 | `ezmk project export cmake` | `-o/--output <path>`、`--overwrite`、`--profile <name>`、`--resolve` |

> **命名理由**：两个命令均挂在 `project` 命名空间下。`project cc` 简洁且继承 `ezmk utils cc` 的既有习惯，避免顶层 `ezmk cc` 与 C 编译器 `cc` 歧义；`project export <target>` 用 `<target>` 区分导出格式，为未来 `make`/`meson` 预留扩展点。不新增顶层别名/简写。

### 3.3 发布门槛

沿用 1.1.0-pre.3 确立的门槛（`plans/1.1.x/1.1.0-pre.3.md`「⛔ 发布门槛」）：

- **没有完成实现，或破坏了兼容性的版本，不得正式发布**
- 发布前必须同时满足：① 计划清单全部完成或明确收口；② 公共 API 无破坏性变更（仅 `2.0.0` 引入）；③ 全量测试零回归（`bash build.sh test` + `test-all`）

1.2.0 为纯增量 minor：新增命令与配置字段，**不破坏** 1.1.0 稳定 API。`ezmk utils cc` 工具保留可用（弃用提示），其移除属 2.0.0 破坏性窗口。前置 **1.1.1** 需先发布（`build_compile_args()`/`compile_db`/拦截）。

## 6 跨版本关注点

- **1.1.1 → 1.2.0 承接**：1.1.1 的拦截在 1.2.0 迁移为 `ezmk project cc` 命令（`Command::ProjectCc`），`ezmk utils cc` 转弃用提示；共享 `build_compile_args()` + `compile_db` 基础。
- **2.0.0 破坏性窗口**：`ezmk utils cc` 工具的移除，以及任何在 1.2.0 标记弃用的接口，均在 2.0.0 执行；1.2.0 只加不删。
- **命令构造单一事实源**：`build_compile_args()` 收敛后，任何新增编译标志自动进入 compile_commands.json，**从结构上消除 drift 风险**。
- **与 `@link:` / 包生态的关系**：compile-db 复用构建路径的 `@link:` 解析与依赖包 include 收集；CMake 导出对 `@link:` 走相对路径（项目内）或绝对路径（项目外），对包依赖走 best-effort 映射。
- **文档一致性**：`project cc` 与 `project export cmake` 进入 `docs/en|zh/cli.md` 命令表与 README 命令速览；`docs/en|zh/utils.md` 标注 `cc` 工具内化并弃用。
- **C++ ABI 维度（dev.10）**：预编译包平台标识符加入工具链/ABI 维度，修正"os-arch 即够"的旧假设；`repo` 的 `os_arch_toolchain` 三元组（族级）与 `lib/` 文件级 ABI 匹配暂不合并，版本化归 2.0.0 窗口。
- **dev.10 → pre.2 联动**：pre.2 的 README 高级特性表、教程 14、package_authoring ABI 警告均引用 dev.10 的命名/匹配规则，命名事实源在 dev.10/package_authoring。
- **回归基线**：当前全量测试基线 546 用例 / 2617 断言（含集成 556 / 2666）。重构与新增命令均不得引入回归。
