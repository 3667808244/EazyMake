## 1 背景

1. 需要为项目引入链接机制（`.ezmk/links.json`），方便跨目录共享源文件，并提供便捷的管理工具
2. `ezmk-cc` 当前作为内置工具随 ezmk 分发，但作为"默认 util 包"的一部分更合理，体系一致
3. 在 Linux 和 Windows 上默认项目在 watch 模式下报错：`filesystem error: cannot make absolute path: Invalid argument []`

## 3 解决 watch 模式下默认项目报错

### 3.1 问题

在 Linux 和 Windows 上对默认项目（`ezmk project new` 创建的新项目）运行 `ezmk project watch` 时：

```
[ezmk error] filesystem error: cannot make absolute path: Invalid argument []
```

### 3.2 根因分析

`FileWatcher` 初始化时调用 `fs::absolute()` 将 watch 目录转为绝对路径。根据错误信息 `Invalid argument []`，空字符串被传入了 `fs::absolute()`。

可能原因：
1. 默认项目的 `src_dirs` / `include_dirs` 使用相对路径（如 `src`），但在某些代码路径中路径拼接出错，产生了空字符串
2. `ezmk.toml` 中未显式声明 `src_dirs` 时，默认值 `["src"]` 的解析路径可能在某些平台/场景下解析为空
3. Watch 模式下独有的路径构建逻辑与 build 模式不一致

### 3.3 修复计划

1. **定位**：在 `file_watcher.cpp` 的 watch 目录收集逻辑中加入空路径断言/日志，复现并定位空字符串来源
2. **修复**：确保所有传入 `fs::absolute()` 的路径非空；在路径拼接处添加 `fs::path` 有效性检查
3. **加固**：在 `FileWatcher::add_directory()` 入口处防御性检查，空路径直接跳过 + warning
4. **测试**：创建默认项目 → `ezmk project watch` → 确认不再报错

### 3.4 涉及文件

| 文件 | 变更 |
|------|------|
| `src/file_watcher.cpp` | 空路径防御 + 根因修复 |
| `src/project.cpp` / `src/build.cpp` | 检查 watch 路径收集逻辑 |
| `test/test_file_watcher.cpp` | 新增：空路径传入不崩溃 |

## 4 `.ezmk/links.json` 链接机制

### 4.1 数据结构

`.ezmk/links.json` 位于项目根目录，记录所有链接映射：

```json
{
  "shared_files": "../common/src",
  "external_lib": "../../libs/mylib"
}
```

- Key: 链接名称（字母/数字/下划线/连字符，不允许 `..` 和 `/`）
- Value: 目标路径（相对路径，相对于项目根目录解析；**不支持绝对路径**以保持项目可移植性）

### 4.2 路径解析语义

```
@link:shared_files              → ../common/src
@link:shared_files/include      → ../common/src/include
@link:shared_files/src/util     → ../common/src/src/util
```

规则：
1. 遇到 `@link:<name>` 前缀 → 查找 `.ezmk/links.json` 中对应条目
2. 条目不存在 → 报错 "link '{name}' not found in .ezmk/links.json"
3. 如果 `@link:<name>` 后无子路径 → 直接替换为目标路径
4. 如果 `@link:<name>/sub/path` → 目标路径 + `/sub/path`
5. **循环链接**：link A 的目标路径中引用了 `@link:B`，B 又引用 `@link:A` → 解析时检测并报错
6. **链接链**：允许 A→B→C 链式解析（深度限制 10 层，超过报错）

### 4.3 应用场景

`ezmk.toml` 中以下配置项支持 `@link:` 语法：

```toml
[compile]
src_dirs = ["src", "@link:shared_files/src"]
include_dirs = ["include", "@link:shared_files/include", "@link:external_lib/include"]

[link]
link_dirs = ["@link:external_lib/build"]
```

**解析时机**：`config.cpp` 在解析 `ezmk.toml` 时自动展开 `@link:` 引用（在所有其他路径处理之前）。

### 4.4 涉及文件

| 文件 | 变更 |
|------|------|
| `include/ezmk/config.hpp` | `resolve_link_path()` 声明 |
| `src/config.cpp` | `resolve_link_path()` 实现 + 循环检测 + 深度限制 + TOML 解析中自动展开 |
| `src/util.cpp` | 辅助：`parse_link_syntax()` 解析 `@link:<name>/...` 格式 |

## 5 编写 `link` 工具

附属于 `ezmk-official-utils` 包，Lua 脚本 `utils/link.lua`。

### 5.1 CLI

```
ezmk utils link add    <name> <path>     # 添加链接
ezmk utils link remove <name>            # 删除链接
ezmk utils link list                     # 列出所有链接（名称 → 路径）
ezmk utils link show   <name>            # 查看单个链接详情
```

### 5.2 行为

- `add`：检查 name 合法性（字母/数字/下划线/连字符），path 必须存在（目录或文件），写入 `.ezmk/links.json`
- `remove`：删除条目，如果 `.ezmk/links.json` 变空则保留空 `{}`
- `list`：格式化打印所有链接
- `show`：打印目标路径 + 目标是否存在 + 如果是目录则列出内容摘要

### 5.3 Lua 实现要点

```lua
-- 使用 ezmk.file_read() / ezmk.file_write() 读写 .ezmk/links.json
-- 使用 ezmk.json_decode() / ezmk.json_encode() 解析 JSON
-- 使用 ezmk.file_exists() 验证目标路径
-- 路径操作：ezmk.project_root() 获取项目根目录
```

## 6 规范化 `ezmk-cc`

### 6.1 当前状态

`ezmk-cc` 作为内置工具，Lua 脚本编译时嵌入 ezmk 内部（`scripts/embed_locale.py` 同类机制），通过 `ezmk utils cc` 调用。

### 6.2 目标状态

1. 将 `cc` 工具脚本移到 `ezmk-official-utils/utils/cc.lua`
2. 从 ezmk 内置中移除 `cc` 的硬编码加载逻辑
3. 用户安装 `ezmk-official-utils` 包后即可使用 `ezmk utils cc`
4. 向后兼容：`ezmk-official-utils` 在安装脚本中预安装（§8），确保新用户不感知变化

### 6.3 迁移步骤

1. 将现有 cc 脚本内容写入 `ezmk-official-utils/utils/cc.lua`
2. 从 `src/lua_api.cpp` 的 `find_utils_script()` 中移除 `cc` 的特殊处理
3. 确保 `ezmk utils cc` 通过标准的 utils 查找链（project → user → global）发现 `cc.lua`
4. 更新 `install.sh` / `install.ps1` 预安装 `ezmk-official-utils`

## 7 生成快速构建包 util：`gen-build-package`

### 7.1 功能

`ezmk utils gen-build-package [--output <dir>] [--name <name>]`

为当前项目生成一个自包含的构建包（`.tar.gz`），包含：
- 项目所有源文件（`src_dirs` 下文件）
- 头文件（`include_dirs` 下文件）
- `ezmk.toml`
- 一个生成的构建脚本（`build.sh` / `build.ps1`），使用 ezmk 的命令行接口编译

### 7.2 用途

方便在没有网络或不方便 `git clone` 的环境下分发项目源码 + 一键构建。

### 7.3 输出

```
myapp-build-1.0.0.tar.gz
├── myapp/
│   ├── ezmk.toml
│   ├── src/...
│   ├── include/...
│   └── build.sh           # 生成的：#!/bin/bash; ezmk project build
```

## 8 在安装脚本中预安装 `ezmk-official-utils` 包

### 8.1 实现

在 `install.sh` 和 `install.ps1` 的安装流程末尾添加：

```bash
# 安装完成后预装官方 utils 包
./build/ezmk repo add ezmk-repo <url>
./build/ezmk pkg install -g ezmk-official-utils -y
```

### 8.2 考虑

- 使用 `-g`（全局作用域）安装，确保所有用户项目可用
- 使用 `-y` 跳过确认
- 预装失败不阻塞安装（网络问题时降级为 warning）
