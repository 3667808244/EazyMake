# EazyMake 1.1.0-dev.6 — 测试系统

---

## 1 背景

目前 EazyMake 没有内置的测试运行支持。用户需要手动编写测试编译命令、手动运行测试可执行文件、自行汇总测试结果——整个流程割裂且容易出错。

期望通过 `ezmk project test`（别名 `ezmk pt`）一键完成：**编译项目 → 编译测试 → 运行测试 → 汇总结果**。

---

## 2 配置支持

### 2.1 `[test]` 配置节

在 `ezmk.toml` 中添加：

```toml
[test]
dirs = ["test", "tests/unit"]   # 默认 ["test"]
framework = "catch2"            # 默认 "catch2"
flags = ["-Wall"]               # 可选：额外测试编译标志
```

所有字段可选，均有默认值。

### 2.2 `test.dirs`

- 类型：`string[]`
- 默认值：`["test"]`
- 说明：测试源文件所在目录，支持多个目录，相对路径（相对于项目根目录）
- 遍历：递归收集目录下所有 `.cpp`（及 `.cxx`/`.cc`）文件

### 2.3 `test.framework`

- 类型：`string`
- 可选值：`catch2` / `ezmk`（大小写不敏感，复用 `normalize_lang()` 泛化）
- 默认值：`catch2`

### 2.4 `test.flags`

- 类型：`string[]`
- 默认值：`[]`
- 说明：额外追加到测试编译的编译标志（不影响主项目编译）
- 典型用途：`-DUNIT_TEST`、`-DNO_MAIN`、`-g -O0`

## 3 CLI 支持

### 3.1 命令

```
ezmk project test [--framework <catch2|ezmk>] [--filter <pattern>] [--verbose]
ezmk pt             # 别名
```

### 3.2 完整流程

```
1. 如果项目未构建 → 编译项目源码（正常 build 流程，生成所有 .o）
2. 收集 test.dirs 下所有测试源文件
3. 编译每个测试源文件（使用项目编译标志 + test.flags，但排除项目 main.cpp/main 入口）
4. 链接测试可执行文件：
   - Catch2: 链接项目 .o + Catch2 框架 + 测试 .o → test_runner.exe
   - ezmk:    每个测试 .cpp 独立链接项目 .o → test_<name>.exe
5. 运行测试可执行文件，收集退出码 + 输出
6. 汇总结果，打印统计
```

### 3.3 选项

| 选项 | 说明 |
|------|------|
| `--framework` / `-f` | 临时覆盖 `test.framework`（不修改 `ezmk.toml`） |
| `--filter` | 过滤测试名称（Catch2: 传递给 `-c` 参数；ezmk: 文件名 glob 匹配） |
| `--verbose` / `-V` | 展示每个测试的详细输出（即使通过） |

## 4 Catch2 支持

当 `test.framework = "catch2"` 时启用。

### 4.1 Catch2 检测策略

按优先级查找 Catch2：

1. **项目依赖**：`ezmk.toml` 的 `[depends]` 中声明了 `catch2` → 使用包管理器版本
2. **单头文件**：`include/vendor/catch2.hpp` 存在（常见于 header-only 引入）
3. **系统包**：全局/用户作用域已安装的 `catch2` 包
4. **报错**：未找到 → 提示 `ezmk pkg install catch2` 或将 `catch2.hpp` 放入 `include/vendor/`

### 4.2 Catch2 入口生成

Catch2 v3 提供 `CATCH_CONFIG_MAIN` 宏来生成 `main()`。

**检测用户自定义 main**：
- 扫描测试源文件，如果已包含 `#define CATCH_CONFIG_MAIN` 或定义了 `main()` → 使用用户入口
- 否则 → 自动生成一个 `test_main.cpp`（仅含 `#define CATCH_CONFIG_MAIN` + `#include <catch2/catch2.hpp>`），与测试文件一起编译链接

生成的 `test_main.cpp`（放 `.ezmk/cache/test_main.cpp`）：
```cpp
#define CATCH_CONFIG_MAIN
#include <catch2/catch2.hpp>
```

### 4.3 编译与链接

```
g++ -std=c++17
    <项目编译标志>
    <test.flags>
    -I include/ -I <catch2路径>
    -c test/test_foo.cpp -o .ezmk/cache/obj/test_foo.o
    ...
    -c .ezmk/cache/test_main.cpp -o .ezmk/cache/obj/test_main.o

g++ <所有项目.o(排除main.o)> <所有测试.o> test_main.o -o build/test_runner
```

注意：链接时排除项目自身的 `main.cpp` 对应的 `.o`（避免 `main` 冲突）。

### 4.4 结果解析

运行 `./build/test_runner -s -r xml`：
- 成功（退出码 0）→ 解析 XML 获取测试数量、通过/失败详情
- 失败（退出码 ≠ 0）→ 解析 XML + 打印失败用例的详细信息（节名、文件名、行号）

输出格式：
```
[ezmk] Running tests (Catch2)...
  framework: Catch2 v3.x.x
  cases: 42 | passed: 40 | failed: 2
  [FAIL] test_config.cpp:15 — "config should parse stdlib"
    assertion: config.stdlib == "libcxx"
    expected: libcxx  actual: libstdcxx
  [FAIL] test_build.cpp:88 — "build should link correctly"
    ...
[ezmk] 42 tests: 40 passed, 2 failed
```

## 5 EazyMake 内部简单测试框架支持

当 `test.framework = "ezmk"` 时启用。

### 5.1 测试模型

**设计理念**：零依赖、零 boilerplate。每个 `.cpp` 文件是一个独立的测试单元，只需 `return 0` 表示通过。

```
test/
├── test_basic.cpp      → test_basic.exe → exit 0 = PASS
├── test_config.cpp     → test_config.exe → exit 0 = PASS
└── test_edge.cpp       → test_edge.exe   → exit 1 = FAIL
```

### 5.2 编译与运行

每个测试文件：
1. **独立编译**：使用项目编译标志 + `test.flags`，编译为独立可执行文件
2. **独立运行**：每个可执行文件以子进程运行，捕获 stdout/stderr + 退出码
3. **超时处理**：每个测试 30 秒超时，超时标记为 FAIL

```
g++ -std=c++17
    <项目编译标志>
    <test.flags>
    <项目 .o（排除 main.o）>
    test/test_basic.cpp
    -o build/test_basic.exe
```

### 5.3 内置轻量断言宏（可选增强）

为方便用户编写测试，ezmk 内置框架提供最小化的断言头文件 `include/ezmk/test_assert.h`：

```cpp
// 最简宏（用户可选使用）
#define EZMK_ASSERT(cond)        if (!(cond)) { fprintf(stderr, "ASSERT FAIL: %s:%d\n", __FILE__, __LINE__); return 1; }
#define EZMK_ASSERT_EQ(a, b)     if ((a) != (b)) { fprintf(stderr, "ASSERT FAIL: %s:%d: %s != %s\n", __FILE__, __LINE__, #a, #b); return 1; }
```

用户可选用此头文件，也可以用任何其他方式（包括裸 `assert()`、手写逻辑）。

### 5.4 结果输出

```
[ezmk] Running tests (ezmk)...
  [PASS] test_basic.cpp        (0.12s)
  [PASS] test_config.cpp       (0.08s)
  [FAIL] test_edge.cpp         (0.23s)
    stdout: starting edge test...
    stderr: ASSERT FAIL: test_edge.cpp:42: result != expected
  [PASS] test_util.cpp         (0.05s)
[ezmk] 4 tests: 3 passed, 1 failed (in 0.48s)
```

## 6 实现要点

### 6.1 数据流

```
ezmk project test
    ↓
cli.cpp: parse --framework / --filter / --verbose
    ↓
config.cpp: 读取 [test] 配置节 (dirs, framework, flags)
    ↓
build.cpp: compile_test_targets()
    ├─ Catch2: 收集测试 .cpp → 编译 → 检测 main → 链接 test_runner
    └─ ezmk:   收集测试 .cpp → 逐个编译 → 逐个链接
    ↓
util.cpp: run_command() 运行测试可执行文件
    ↓
build.cpp: parse_test_results() 汇总输出
```

### 6.2 涉及文件

| 文件 | 变更 |
|------|------|
| `include/ezmk/config.hpp` | `Config` + `TestConfig` 结构体 |
| `src/config.cpp` | 解析 `[test]` 配置节 |
| `src/cli.cpp` | `project test` + `pt` 别名 + `--framework`/`--filter`/`--verbose` |
| `include/ezmk/build.hpp` | `compile_test_targets()` / `run_tests()` 声明 |
| `src/build.cpp` | 测试编译管线：`compile_test_targets()` + `run_tests()` |
| `include/ezmk/test_assert.h` | **新建**：轻量断言宏（ezmk 内置框架） |
| `test/test_config.cpp` | 新增：`[test]` 配置解析测试 |
| `test/test_build.cpp` | 新增：测试编译管线测试 |

## 8 兼容性

| 变更 | 影响 | 处理 |
|------|------|------|
| 新增 `[test]` 配置节 | 旧项目无此节 | 全部字段有默认值，`ezmk pt` 可正常运行 |
| `project test` 命令 | 不影响现有命令 | 全新子命令 |
| 自动排除 `main.o` | 用户项目有自定义 `main` | 按约定：项目编译的 `main.o` 被排除，测试入口由框架提供 |
| Catch2 自动检测 | 用户使用非标准 Catch2 路径 | 可用 `compile.flags` + `test.flags` 手动指定 include 路径 |
