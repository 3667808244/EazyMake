# EazyMake 1.1.0-dev.4 — 编译器与语言配置增强

---

## 1 背景

1. 使用 `clang++` 的 Linux 用户无法通过语义化的配置项选择使用的标准库
2. 语言识别过于严格（大小写敏感、`C++` vs `CXX` vs `CPP` 等变体）
3. 使用编译器拓展（GNU extensions、Clang extensions 等）不易，需要手动修改 `compile.flags`

---

## 2 `project.stdlib` 支持

### 2.1 配置项

在 `ezmk.toml` 的 `[project]` 节中添加 `stdlib` 字段：

```toml
[project]
name = "myapp"
type = "executable"
version = "0.1.0"
language = "C++17"
stdlib = "libstdc++"    # 可选，默认 libstdc++
```

可选值（大小写不敏感，内部泛化处理与 `lang` 共用 §3.1 的 `normalize_lang()`）：

| 用户输入 | 标准化结果 | 对应标准库 | 编译器标志 |
|----------|-----------|-----------|-----------|
| `libstdc++` / `glibcxx` / `gnu` | `LIBSTDCXX` | GNU libstdc++ | GCC: (默认), Clang: `-stdlib=libstdc++` |
| `libc++` / `llvm` | `LIBCXX` | LLVM libc++ | GCC: `-stdlib=libc++` (需安装), Clang: `-stdlib=libc++` |

默认值：`libstdc++`（未设置时行为不变）。

**验证**：如果传入不被识别的值，报错并列出可用值。

### 2.2 标准宏 `EZMK_STDLIB`

编译时自动注入 `-DEZMK_STDLIB=<值>`：

| stdlib 值 | `EZMK_STDLIB` 宏值 |
|-----------|---------------------|
| `libstdc++` (默认) | `"libstdcxx"` |
| `libc++` | `"libcxx"` |

> 宏值中的 `++` 替换为 `xx`，避免在某些构建工具链中 `+` 字符被误解析。用户代码中使用 `"libstdcxx"` / `"libcxx"` 进行条件编译，与 `ezmk.toml` 中的 `stdlib` 值对应关系如上表。

用户代码可据此条件编译：

```cpp
#ifdef EZMK_STDLIB
  #if EZMK_STDLIB == "libcxx"
    #include <ciso646>  // libc++ 特需
  #endif
#endif
```

宏同样添加到 `EZMK_STDLIB` 的标准宏列表中（与 `EZMK_LANG` 并列）。

### 2.3 `-stdlib=` 注入逻辑

在 `toolchain.cpp` 的编译标志生成中：

```
if (stdlib == "libc++"):
    if compiler is GCC:   add "-stdlib=libc++" (warning: GCC libc++ 支持有限)
    if compiler is Clang: add "-stdlib=libc++"
    // MSVC 不支持 -stdlib flag，仅使用 STL
```

## 3 `project.lang` 拓展

### 3.1 字符串泛化函数 `normalize_lang()`

在 `config.cpp` 中实现统一的泛化函数，`project.lang` 和 `project.stdlib` 共用：

```
std::string normalize_lang(const std::string& input) {
    1. to_upper(input)
    2. replace "C++" → "CPP"
    3. replace "CXX" → "CPP"
    4. trim whitespace
    5. return result
}
```

处理示例：

| 用户输入 | 泛化结果 |
|----------|----------|
| `c++17` | `CPP17` |
| `C++17` | `CPP17` |
| `cxx17` | `CPP17` |
| `CXX17`  | `CPP17` |
| `cpp17` | `CPP17` |
| `c11`   | `C11` |
| `c17`   | `C17` |
| `C++2B` | `CPP2B` |
| `c++20` | `CPP20` |

> `EZMK_LANG` 标准宏也复用此泛化结果，保证宏值与用户输入格式无关。

**边界情况**：
- 空字符串 → 报错 "language not specified"
- 无法识别的值（如 `Rust`）→ 报错并列出支持的格式
- 仅 `C` / `CPP` 不带版本号 → 默认版本（C11 / C++17）

### 3.2 编译器拓展支持

用户可以在 `project.lang` 中显式声明是否需要编译器拓展：

```toml
[project]
language = "GNUCPP17"   # 显式要求 GNU 拓展
```

或者在 `compile.flags` 中声明（保持现有兼容性）。

**泛化中的拓展检测**（`normalize_lang()` 后置）：

| 编译器 | 拓展前缀 | `-std=` 标志 | 警告 |
|--------|---------|-------------|------|
| GCC/g++ | `GNUCPP` → `gnu++` | `-std=gnu++17` | `warn: using GNU extensions (non-ISO C++), use 'language = "CPP17"' for standard C++` |
| GCC/g++ | `CPP`（无 GNU） | `-std=c++17` | 无 |
| Clang/clang++ | `GNUCPP` → `gnu++` | `-std=gnu++17` | 同上警告 |
| Clang/clang++ | `CPP`（无 GNU） | `-std=c++17` | 无 |
| MSVC/cl.exe | 忽略（MSVC 自带拓展） | `/std:c++17` | 无（MSVC 默认含拓展，无分离标志） |

**实现位置**：`toolchain.cpp` 中的 `get_language_flag()` / `get_compile_flags()`。泛化后的结果查找对应 `-std=` / `/std:` 标志。

**GNU C 语言同理**：`GNU11` → `-std=gnu11`，`GNU17` → `-std=gnu17`。

## 4 实现要点

### 4.1 数据流

```
ezmk.toml [project].lang / [project].stdlib
    ↓
config.cpp: Config::parse()
    ↓
normalize_lang() / normalize_stdlib()  (泛化)
    ↓
toolchain.cpp: build_compile_flags()
    ↓
-std=c++17 -DEZMK_LANG="cpp17" -DEZMK_STDLIB="libstdcxx" [-stdlib=libc++]
```

### 4.2 涉及文件

| 文件 | 变更 |
|------|------|
| `include/ezmk/config.hpp` | `Config` 结构体添加 `stdlib` 字段 |
| `src/config.cpp` | 解析 `project.stdlib` + 实现 `normalize_lang()` |
| `src/toolchain.cpp` | `get_language_flag()` 重构：拓展检测 + `-stdlib=` 注入 |
| `src/build.cpp` | `EZMK_STDLIB` 宏注入到编译标志 |
| `test/test_config.cpp` | 新增：`stdlib` 解析 + `normalize_lang()` 边界测试 |
| `test/test_toolchain.cpp` | 新增：拓展标志生成 + `-stdlib=` 注入测试 |

## 6 兼容性

| 变更 | 影响 | 处理 |
|------|------|------|
| 新增 `project.stdlib` | 旧项目无此字段 | 默认 `libstdc++`，行为不变 |
| `project.lang` 泛化 | 旧项目写 `C++17` / `cxx17` 等 | 泛化后等价于 `CPP17`，标志不变 |
| 编译器拓展自动检测 + 警告 | 旧项目写 `GNUCPP17` | 行为不变，首次编译给出 non-ISO 警告（可用 `--quiet` 抑制） |
| `-stdlib=` 注入 | 旧项目未用 clang 或未设 stdlib | 不注入额外 flag |
