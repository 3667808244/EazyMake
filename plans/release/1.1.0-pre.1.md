# EazyMake 1.1.0-pre.1 — 改善用户触达

---

## 1 背景

当前 `1.1.0-dev.6` 已将所有核心功能实现完毕。在合入 `1.1.0` 正式版之前，需要改善用户首次接触 EazyMake 的体验：

1. **命令冗长**：所有命令都是 `ezmk project <action>` 形式，新用户记住压力大
2. **`--help` 信息密度低**：分组不直观，日常命令和高级功能混在一起
3. **README 信息过载**：技术栈、依赖表等开发者细节占位过多，普通用户一目不了然
4. **安装方式单一**：仅有 `curl | bash` 一种方式，缺少包管理器支持
5. **API 稳定性未承诺**：用户担心未来破坏性变更

---

## 2 顶层命令别名（P0）

### 2.1 目标

在 `ezmk` 的 CLI 解析入口添加以下顶层别名，让用户可以省略 `project` 前缀：

| 别名 | 展开为 |
|------|--------|
| `build` | `project build` |
| `run` | `project run` |
| `clean` | `project clean` |
| `watch` | `project watch` |
| `install` | `project install` |
| `test` | `project test` |
| `pack` | `project pack` |

这些别名在源码中作为**顶层命令**注册（与 `project`/`pkg`/`repo`/`utils`/`help`/`version` 同级），在命令行 token 化后、分组解析前展开，展开后的形式与原 `project <action>` 完全一致。

### 2.2 实现要点

**在 `cli.cpp` 的 `parse()` 函数中**：在现有的 `kAliases` 两字母简写展开之后、分组路由（`group == "project"` 等）之前，增加一层"顶层别名展开"：

```cpp
// 1.1.0-pre.1: top-level aliases — build/run/clean/watch/install/test/pack
static const std::map<std::string_view, std::pair<const char*, const char*>>
    kTopAliases = {
        {"build",   {"project", "build"}},
        {"run",     {"project", "run"}},
        {"clean",   {"project", "clean"}},
        {"watch",   {"project", "watch"}},
        {"install", {"project", "install"}},
        {"test",    {"project", "test"}},
        {"pack",    {"project", "pack"}},
    };
```

展开逻辑与 `kAliases` 完全一致，复用已有的 token vector 修改 → `argv_buf` 重建流程。

### 2.3 帮助文本更新

- `--help` 输出中，**§2 的别名放在最前面**，原 `ezmk project xxx` 用法保留但退居其次
- 中文帮助 (`locale/zh.json`) 同步更新
- `CLAUDE.md` quick reference 更新

### 2.4 兼容性

纯增量——`ezmk project build` 和 `ezmk build` 两种写法同时生效，不破坏现有脚本和肌肉记忆。

## 3 `--help` 输出重组（P1）

### 3.1 目标

将 `--help` 输出按用户使用频率重新分组：

```
Usage:

  日常构建命令:
    ezmk build                         Incremental build (compile + link)
        完整: ezmk project build
    ezmk run                           Build and run
        完整: ezmk project run
    ezmk clean                         Clean cache and temp files
        完整: ezmk project clean
    ezmk watch                         Watch sources and rebuild on change
        完整: ezmk project watch
    ezmk install                       Install build artifacts to prefix
        完整: ezmk project install
    ezmk test                          Build and run project tests
        完整: ezmk project test

  项目初始化:
    ezmk project new <name>            Create a new project
    ezmk project pack                  Create distributable package

  包管理与仓库（高级功能）:
    ezmk pkg install <pkg>             Install a package
    ezmk pkg remove <pkg>              Remove a package
    ezmk pkg search <pkg>              Search for a package
    ezmk pkg info <pkg>                Show package info
    ezmk pkg list                      List installed packages
    ezmk pkg update [<pkg>]            Update installed package(s)
    ezmk repo add <url>                Register a package repository
    ezmk repo remove <name>            Remove a registered repository
    ezmk repo update [<name>]          Update repository indices
    ezmk repo list                     List registered repositories
    ezmk repo info <name>              Show repository details

  其他:
    ezmk utils <name>                  Run a Lua-based utility tool
    ezmk help                          Show this help
    ezmk version                       Show version information
```

### 3.2 实现要点

**`print_usage()` 重写**：

1. 不再用 `cli_usage_project` / `cli_usage_pkg` 等分组标题（这些 i18n key 保留但不再在 help 中使用）
2. 新增 i18n key：
   - `help_section_daily` — "日常构建命令" / "Daily build commands"
   - `help_section_init` — "项目初始化" / "Project init"
   - `help_section_advanced` — "包管理与仓库" / "Packages & repos"
   - `help_section_other` — "其他" / "Other"
   - `help_section_options` — "常用选项" / "Common options"
3. 日常命令每种占两行 — 首行顶层别名，次行缩进标注完整 `project` 形式；单/双字母简写（`pb`/`pr`/…）不显示
4. 最简单/双字母简写（`pb`/`pr`/…）**不显示在 `--help` 文本中**，也不在 zsh 补全中使用；仅在文档中保留（可选查阅）

### 3.3 i18n 更新

`locale/en.json` 和 `locale/zh.json` 中新增上述 5 个 section key；原有的 `cli_usage_*` 系列 key 保留不删（代码中不再引用，但保留向后兼容）。

### 3.4 zsh 补全

`res/ezmk.zsh` 需要同步更新：
- 添加 §2 的顶层别名补全
- 不添加单/双字母简写（`pb`/`pr`/…）

## 6 包管理器分发（P2）

### 6.1 GitHub Actions CI

创建 `.github/workflows/release.yml`，在 Release 创建时自动构建以下平台的二进制包：

| 平台 | 产物 |
|------|------|
| `windows-x64` | `ezmk-windows-x64.zip` |
| `linux-x64` | `ezmk-linux-x64.tar.gz` |
| `macos-x64` | `ezmk-macos-x64.tar.gz` |
| `macos-arm64` | `ezmk-macos-arm64.tar.gz` |

每个 Workflow job 调用 `bash build.sh` 编译 → 打包 → 上传到 Release Assets。

### 6.2 Homebrew（macOS / Linux）

创建 Homebrew formula（`homebrew-eazymake/ezmk.rb`），指向 GitHub Release 的预编译包：

```ruby
class Ezmk < Formula
  desc "A simple C/C++ build tool"
  homepage "https://github.com/3667808244/EazyMake"
  url "https://github.com/3667808244/EazyMake/releases/download/v1.1.0/ezmk-macos-arm64.tar.gz"
  sha256 "..."

  def install
    bin.install "ezmk"
  end
end
```

### 6.3 winget（Windows）

创建 winget manifest（`manifests/e/ezmk/1.1.0.yaml`），提交到 [microsoft/winget-pkgs](https://github.com/microsoft/winget-pkgs)：

```yaml
PackageIdentifier: EazyMake.EazyMake
PackageVersion: 1.1.0
InstallerType: zip
Installers:
  - Architecture: x64
    InstallerUrl: https://github.com/3667808244/EazyMake/releases/download/v1.1.0/ezmk-windows-x64.zip
    InstallerSha256: ...
```

### 6.4 安装方式优先级调整

在所有安装文档中，推荐顺序调整为：

1. **包管理器**（首选）：`brew install ezmk` / `winget install EazyMake`
2. **预编译 Release**（备选）：从 GitHub Release 下载解压
3. **`curl \| bash`**（快速尝鲜）：`curl ... | bash`

## 7 API 冻结承诺（P1）

### 7.1 冻结范围

在 `1.1.0` 正式版发布时明确声明以下 API 永久稳定：

| 类别 | 冻结项 |
|------|--------|
| 顶层命令 | `build`, `run`, `clean`, `watch`, `install`, `test`, `pack` |
| 项目命令 | `project new`, `project build`, `project run`, `project clean`, `project watch`, `project install`, `project test`, `project pack` |
| 包管理命令 | `pkg install`, `pkg remove`, `pkg search`, `pkg info`, `pkg list`, `pkg update` |
| 仓库命令 | `repo add`, `repo remove`, `repo update`, `repo list`, `repo info` |
| 配置文件 | `[project]`, `[compile]`, `[link]`, `[depends]`, `[test]`, `[install]` 核心字段 |

### 7.2 兼容承诺

- 破坏性变更仅在 `2.0.0` 引入
- 提前至少一个次版本发出弃用警告（deprecation warning）
- CLI 选项、`ezmk.toml` 字段废弃前需在 `1.x.0` 中保留并打印 warning

### 7.3 写入位置

- **`CHANGES.md`**：顶部添加 `## API Stability` 章节
- **`README.md`**：在"设计理念"段落下添加一行 "Stable public API as of v1.1.0"
- **`README_ZH.md`**：对应中文版本
