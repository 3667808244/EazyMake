## 1 背景

1.5.0-dev.3 的 `[settings].gen_agent_md` 只在 `project new` 时写一个最小 `AGENTS.md`，解决「agent 知道项目怎么构建」的问题。本版要解决的是「agent 拿到可复用技能」：把本仓库 `.claude/skills/ezmk-user-*` 下的 4 个用户项目技能按常见 agent 的目录约定复制到新项目：`ezmk-user-build`、`ezmk-user-config`、`ezmk-user-pkg`、`ezmk-user-test`。

需求有两个约束：

1. **配置类型是 bool 或 string**：既要支持「一键全开」，也要支持只给某个 agent 生成。
2. **不是生成一个自造技能，而是分发已有 skill**：源头是 `.claude/skills/` 中的实际 `SKILL.md`，安装后的 `ezmk` 二进制无法假设源码树存在，因此必须在构建期把技能内容嵌入二进制。

## 3 详细设计

### 3.1 配置项

- 位置：`[settings]`，键名 `gen_agent_skills`（复数）。
- 类型：**bool | string**；默认 `false`。
- 作用域：全局级 / 用户级 `config.toml`；不提供项目级覆盖键（与 `gen_agent_md` 一致）。
- 合并：沿用 global < user 的逐键覆盖；`--config` 替换用户级；`--no-config` 跳过两级。
- 取值语义：

| 值 | 含义 |
|----|------|
| 缺省 / `false` / `""` | 关闭，不生成任何 skill |
| `true` | 等价于 `"all"`，分发到所有受支持 profile |
| `"claude"` / `"claude-code"` | 只写 `.claude/skills/` |
| `"copilot"` / `"github"` | 只写 `.github/skills/` |
| `"agents"` / `"agent"` / `"codex"` / `"gemini"` | 只写 `.agents/skills/` |
| `"all"` | `.claude/skills/` + `.github/skills/` + `.agents/skills/` |
| `"claude,agents"` 等逗号列表 | 按列表去重后分发 |
| 其它字符串 | 加载期 fail-fast，错误信息列出允许值 |

- 解析规则：string 按逗号 / 空白拆分，大小写不敏感，去重；空 token 忽略；全部为空等于关闭；未知 token 报错。
- 存储：`SettingsConfig` 内部归一化为一个字符串（如 `""` / `"claude"` / `"agents"` / `"claude,agents"`），供生成逻辑与测试使用；不把 bool 和 string 原样散落到调用点。
- 类型读取：沿用 `read_initial_commit` 的「bool 或 string」读取模式；非 bool/string（如整数）报 `config field 'settings.gen_agent_skills' ... must be a boolean or a string`。
- 不新增 CLI 开关；如后续需要 `--gen-agent-skills`，另行立项。

### 3.2 常见 agent 目录矩阵

| profile | 项目内目录 | 典型客户端 | 说明 |
|---------|------------|------------|------|
| `claude` | `.claude/skills/<skill>/SKILL.md` | Claude Code、GitHub Copilot | Claude Code 原生目录；Copilot 也直接读取 |
| `copilot` | `.github/skills/<skill>/SKILL.md` | GitHub Copilot（cloud agent / code review / CLI / VS Code） | GitHub 原生目录；Copilot code review 会优先使用 |
| `agents` | `.agents/skills/<skill>/SKILL.md` | Codex CLI、Gemini CLI、GitHub Copilot | 通用 Agent Skills 布局；三方共同支持 |
| `all` | 同时写上述三处 | 多客户端 | 内容相同，目录各自独立 |

- GitHub Copilot 文档明确支持 `.github/skills`、`.claude/skills` 与 `.agents/skills` 三种项目技能目录，因此 `claude` / `copilot` / `agents` / `all` 生成的技能都可被 Copilot 读取；`copilot` profile 额外提供 GitHub 原生 `.github/skills/`，便于 code review 等场景。
- v1 **不写** `.gemini/skills/`：Gemini CLI 可使用通用 `.agents/skills/`，避免同一项目出现两套重复技能；若未来需要 Gemini 原生目录，新增 profile，不改变现有值语义。
- v1 **不写** `.cursor/rules` 等非 `SKILL.md` 私有格式；`.github/skills` 是 Copilot 的 `SKILL.md` 目录，已由 `copilot` profile 支持。
- `true` 选择 `all`，而不是只选 `agents`，因为「全开」最符合 bool 的直觉；用户要精简时用 string 明确指定。

### 3.3 构建期嵌入

新增 `scripts/embed_skills.py`：

- 输入 `.claude/skills/ezmk-user-*/`；只读取 `ezmk-user-build` / `ezmk-user-config` / `ezmk-user-pkg` / `ezmk-user-test` 四个目录下的 `SKILL.md`，忽略其它开发/发布类技能。
- 校验每个 `SKILL.md` 有 YAML frontmatter 的 `name`，且与目录名一致；不一致构建失败，防止目录名与技能名漂移。
- 生成 `src/skill_data.cpp`：一个只读表 `{name, content}`，按目录名排序，内容 byte-for-byte；转义用现有 C++ 原始字符串或长度+字节，避免 NUL/引号问题。
- `build.sh` 在 locale/logo/examples 生成之后增加一步；Python 缺失时生成空表并打印 warning（与现有生成物降级策略一致），但 CI 必须安装 Python 并断言 4 个目标技能非空。
- 生成文件加入 `.gitignore`；测试源码清单加入 `src/skill_data.cpp`。
- v1 只嵌入 `SKILL.md`；未来技能若带 `reference/` 等附加文件，再扩展为「相对路径 → 内容」表，不在本版做。

### 3.4 生成逻辑

在 `create_project()` 完成 `ezmk.toml`、源码骨架、可选 `AGENTS.md` 之后执行：

1. 读取已归一化的 `settings.gen_agent_skills`；空则直接返回。
2. 解析 profile 集合（`claude` / `agents`）。
3. 对每个 profile 的根目录，对每个嵌入技能：
   - 目标：`root / skill.name / "SKILL.md"`；
   - 若目标已存在 → 跳过（新项目正常不会存在；防御未来复用/夹具）；
   - 否则 `create_directories(parent)` + 写文件；写入失败 `util::fatal`，不留下成功假象。
4. 生成内容与源文件完全一致，不添加项目名/时间戳/绝对路径；不同项目、不同平台的输出字节一致。
5. 汇总：`util::debug` 记录 “generated N skills for <profiles>”；不改变 stdout 的命令输出格式，避免脚本解析漂移。

- 与 `gen_agent_md` 正交：两者独立；`AGENTS.md` 是否存在不影响技能复制。
- 不生成 `CLAUDE.md` 或 `.claude/settings.json`；只写技能树。
- 若源技能内容包含平台路径/仓库专属说明，按原样分发；本版不重写技能正文。

### 3.5 文档与 i18n

- `docs/zh/user_config.md` / `docs/en/user_config.md`：`[settings]` 表新增行，类型 “bool / string”，默认 false，列 profile 取值与两个目标目录。
- `docs/zh/global_config.md` / `docs/en/global_config.md`：在「其余 settings 键」说明中补一句，不重复整表。
- `man/ezmk.toml.5`：新增 `gen_agent_skills` 字段，标明 bool|string 与允许值；放在 `gen_agent_md` 附近。
- `README.md` / `README_ZH.md`：可选补一句两级配置速览中的 project-new 行为；不新增长章节。
- `scripts/check_config_docs.py`：新键必须出现在 user_config + man5，闸门自动覆盖。
- i18n：技能内容不翻译、不进 UI 文案；配置加载期诊断沿用英文策略，预期不新增 `i18n_keys.def` 键。

### 3.7 边界与已知取舍

| 项 | 取舍 |
|----|------|
| 已有项目 | 不自动补发；只作用于 `project new`，避免在用户仓库突然写文件 |
| 技能范围 | v1 只分发 `.claude/skills/ezmk-user-*` 的 4 个用户项目技能；开发/发布类技能不进入新项目 |
| 技能附加文件 | 当前只有 `SKILL.md`；未来引用文件另行扩展嵌入格式 |
| 自定义目标目录 | v1 只接受受支持 profile；不接受任意路径，避免路径穿越/越界写 |
| 其他客户端 | 支持 `.claude/skills`、`.github/skills`、`.agents/skills` 三种 `SKILL.md` 布局；Cursor 等非 `SKILL.md` 私有格式不写 |
| 覆盖策略 | 新项目目标目录不存在；仍跳过已存在文件，不覆盖用户内容 |
| 语言 | 技能正文原样（英文为主），不翻译；避免 agent 指令漂移 |
| 安全 | 只读嵌入源技能；不执行 shell；写入限制在新项目根内；失败 fatal |
