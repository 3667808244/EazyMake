## 1 背景

EazyMake 当前的「用户可调默认值」几乎全部**硬编码在代码里**，分散在多处：

- **路径**：全局包目录 = `util::get_exe_dir()/pkg`（`src/pkg.cpp:163`），用户包目录 = `%LOCALAPPDATA%/ezmk/pkg` 或 `~/.local/ezmk/pkg`（`:153-160`）；全局仓库目录 = `get_exe_dir()/repo`、用户仓库目录同理（`src/repo.cpp:31-51`）；`project install` 默认前缀 = `%LOCALAPPDATA%/ezmk` / `~/.local`（`src/config.cpp:944-951`）；`ezmk example` 的输出目录由 CLI 位置参数决定（`src/example.cpp:23`）。
- **行为**：语言只认 `EZMK_LANG`（`src/i18n.cpp`）；颜色只认全局 `--color`（`src/cli.cpp:1073-1138`，仅 `auto/always/never`）；`project new` 的 git 初始化 / `.gitignore` / `README.md` 只由 `--disable-git-init`、`--disable-gitignore` 控制（`src/cli.cpp:230-247`、`src/project.cpp:118-135`）；没有日志级别 / 日志目录；没有 `auto_pack` / `gen_agent_md`。
- **后果**：同一台机器上的每个项目都要重复传参或重复写 `ezmk.toml`；CI 无法用一份用户级配置统一语言 / 颜色 / 日志；系统管理员无法为整机设定包 / 仓库 / 日志位置。

草稿提出用「系统级 + 用户级」两份 `config.toml` 承载 `[base_dir]`（路径）与 `[settings]`（行为默认值），并由用户级覆盖系统级。本版把它落成一个**向后兼容、默认零变化**的只读配置层。

## 3 详细设计

### 3.1 目录与环境变量（C-01）

两个环境变量都**只决定配置文件所在目录**，不直接决定包 / 仓库 / 日志路径（后者由 `[base_dir]` 决定）。

| 变量 | 作用 | Linux 默认 | Windows 默认 |
|------|------|-----------|--------------|
| `EZMK_GLOBAL_CONFIG_DIR` | 系统级配置目录（管理员维护，整机生效） | `/etc/ezmk` | `C:\.ezmk\config` |
| `EZMK_USER_CONFIG_DIR` | 用户级配置目录（当前用户） | `$HOME/.config/ezmk` | `$USERPROFILE\.ezmk\config` |

解析规则：

- 环境变量非空 → 原样使用（允许相对路径，相对当前工作目录解析）。
- 环境变量为空 / 未设置 → 上表默认值；Windows 的 `$USERPROFILE` 回退顺序复用 `util::get_home_dir()`（`HOME` → `USERPROFILE` → `HOMEDRIVE+HOMEPATH`）。
- Linux 额外兼容 `$XDG_CONFIG_HOME`：若 `EZMK_USER_CONFIG_DIR` 未设置且 `XDG_CONFIG_HOME` 非空，则用户级默认改为 `$XDG_CONFIG_HOME/ezmk`；最终仍以环境变量显式值为最高优先。
- 目录不存在**不是错误**：视为「没有该级配置」；若目录存在但 `config.toml` 解析失败 → 致命错误（配置错误必须显式暴露）。

### 3.2 文件格式与合并顺序（C-02 / C-03）

文件名固定为 `config.toml`（系统级 / 用户级同构）。顶层只允许两个表：`[base_dir]`、`[settings]`；其余键 / 表一律报错（fail-fast），避免拼写错误静默失效。

合并顺序（低 → 高）：

1. 内置默认值（本文档 §3.5）。
2. 系统级 `$EZMK_GLOBAL_CONFIG_DIR/config.toml`。
3. 用户级 `$EZMK_USER_CONFIG_DIR/config.toml`（`--config` 指定的文件**替代**用户级路径，不叠加）。
4. 项目 `ezmk.toml`（仅项目已有字段；本项目不把 `[settings]` 合并进项目配置）。
5. 环境变量 / CLI（`EZMK_LANG`、`NO_COLOR`、`--lang`、`--color`、`--no-config`、`--config`）。

`[base_dir]` 的合并是**按作用域**而不是整体覆盖：系统级里的 `installed_packages` 只影响 Global 作用域，用户级里的只影响 User 作用域；两者互不覆盖。`examples` / `logs` 是「用户级覆盖系统级」的单值。

### 3.3 `[base_dir]` 语义（C-04）

~~~toml
[base_dir]
installed_packages = "/var/ezmk/pkg"   # 该作用域的包安装根目录
examples           = "/usr/local/share/ezmk/examples"  # ezmk example 的默认输出根
repo_cache         = "/var/cache/ezmk/repo"            # 该作用域的仓库缓存根
logs               = "/var/log/ezmk"                   # 日志目录
~~~

| 键 | 作用域 | 默认（未配置时） | 语义 |
|----|--------|------------------|------|
| `installed_packages` | 按所在文件：系统级→Global，用户级→User | Global: `get_exe_dir()/pkg`；User: `%LOCALAPPDATA%/ezmk/pkg` 或 `~/.local/ezmk/pkg` | 覆盖 `pkg_install_dir(scope)` 的根 |
| `repo_cache` | 同上 | Global: `get_exe_dir()/repo`；User: `%LOCALAPPDATA%/ezmk/repo` 或 `~/.local/ezmk/repo` | 覆盖 `repo_dir(scope)` 的根 |
| `examples` | 用户级覆盖系统级 | 无（保持 CLI 位置参数 / 当前目录） | `ezmk example <name>` 省略输出目录时的基准目录 |
| `logs` | 用户级覆盖系统级 | 无（不写文件日志） | `log_level` 非 `off` 且配置了该目录时，写 `ezmk.log` |

路径规则：

- 绝对路径原样使用；相对路径相对**该 config.toml 所在目录**解析（不是 CWD）。
- 支持 `~` / `~/` / `~\` 展开（复用 `[install].prefix` 的展开规则，`src/config.cpp:953-960`）。
- 含 NUL 或无法规范化的路径 → 配置错误。
- 只覆盖对应作用域，**不允许**用用户级 `installed_packages` 改 Global 作用域（防止提权 / 误配）。
- 目录按需创建（包安装 / 仓库 clone / 日志写入时），加载阶段不做写操作。

### 3.4 `[settings]` 语义（C-05）

~~~toml
[settings]
natural_language = "auto"                 # "auto" 或语言标签（en / zh / zh-TW ...）
initial_commit   = false                  # bool 或 string
log_level        = "info"                 # off|error|warn|info|debug
auto_init_git    = true
gen_gitignore    = true
gen_readme       = true
auto_pack        = false
gen_agent_md     = false
color_mode       = "auto"                 # auto|off|16colors|256colors|truecolor
~~~

| 键 | 类型 | 默认 | 行为 |
|----|------|------|------|
| `natural_language` | string | `"auto"` | `"auto"` = 现有检测（`EZMK_LANG` / 系统区域）；其它值作为语言标签交给 `i18n`，**CLI `--lang` / 环境 `EZMK_LANG` 优先** |
| `initial_commit` | bool 或 string | `false` | `false` = `git init` 后不提交；`true` = 用默认消息提交；字符串 = 用该字符串作提交消息。仅当 `auto_init_git` 为真且 git 可用时生效 |
| `log_level` | string | `"info"` | `off` 关闭文件日志与调试输出；`error/warn/info/debug` 过滤 stderr 与（如配置）文件日志；未知值 → 配置错误 |
| `auto_init_git` | bool | `true` | 等价于「未传 `--disable-git-init`」；CLI `--disable-git-init` 仍可覆盖为 false |
| `gen_gitignore` | bool | `true` | 等价于「未传 `--disable-gitignore`」 |
| `gen_readme` | bool | `true` | `project new` 是否写 `README.md`（新增开关；默认与现状一致） |
| `auto_pack` | bool | `false` | 成功构建 `type = "static"` 后自动执行 `project pack`（失败不影响构建退出码，仅警告）；`--no-auto-pack` 可覆盖（见 C-07） |
| `gen_agent_md` | bool | `false` | `project new` 额外生成 `AGENTS.md`（构建 / 测试 / 目录说明），内容为静态模板 |
| `color_mode` | string | `"auto"` | `auto` = 现有 TTY/`NO_COLOR` 判定；`off` = 永不；`16colors`/`256colors`/`truecolor` = 启用（本版三者输出相同的 16 色 SGR，深度仅记录在运行时配置中供后续版本使用） |

约定：

- 未知 `[settings]` 键 → 配置错误（与 1.4.11 Q4-29 的 fail-fast 一致）。
- 类型不符 → 配置错误，并指出文件 + 键名。
- `[settings]` 不进入项目 `ezmk.toml`；项目级行为仍由既有字段 / CLI 控制。

### 3.6 加载时机与访问器（C-06）

- `main()` 在 `cli::parse()` 之前调用 `config::load_runtime_config(argc, argv)`（或在 `strip_color_option` 同层）：先扫描 `--config` / `--no-config` / `--lang` / `--color`，再读两级 `config.toml`，最后交给原有 CLI 解析。
- 新增公共结构（`include/ezmk/config.hpp`）：

~~~cpp
struct BaseDirConfig {                 // 按作用域
    std::optional<fs::path> installed_packages;
    std::optional<fs::path> repo_cache;
};
struct SettingsConfig {
    std::string natural_language = "auto";
    // initial_commit 用三态表示：未设置 / 关 / 开或消息
    bool has_initial_commit = false;
    bool initial_commit_enabled = false;
    std::string initial_commit_message;
    std::string log_level = "info";
    bool auto_init_git = true;
    bool gen_gitignore = true;
    bool gen_readme = true;
    bool auto_pack = false;
    bool gen_agent_md = false;
    std::string color_mode = "auto";
};
struct RuntimeConfig {
    SettingsConfig settings;           // 已合并（用户级覆盖系统级）
    BaseDirConfig global_dirs;         // 系统级文件的 [base_dir]
    BaseDirConfig user_dirs;           // 用户级文件的 [base_dir]
    fs::path global_config_file;       // 空 = 未加载
    fs::path user_config_file;
    bool loaded = false;
};
const RuntimeConfig& runtime_config();
void load_runtime_config(int argc, const char* const* argv);
~~~

- 访问器供 `pkg::pkg_install_dir` / `repo::repo_dir` / `example::create_example` / `util` 日志 / `project::create_project` / `i18n` 读取；未加载时返回默认值（保证单测直接调用这些函数不需要先 `main`）。
- 加载函数必须**幂等**（多次调用只生效一次），并在测试中提供 `reset_runtime_config_for_test()`（仅测试可见）。

### 3.7 CLI 与优先级（C-07）

新增全局选项（在 `strip_color_option` 同层消费，任何子命令都可用）：

| 选项 | 语义 |
|------|------|
| `--config <file>` | 用指定文件**替代**用户级 `config.toml`；系统级仍加载 |
| `--no-config` | 跳过系统级与用户级配置（CI / 复现构建）；与 `--config` 同时给出 → 报错 |
| `--lang <tag>` | 覆盖 `natural_language` / `EZMK_LANG` |
| `--color=<v>` | 既有 `auto/always/never` 保留；新增 `off`（=never）、`on/16colors/256colors/truecolor`（=always） |
| `--no-auto-pack` | 单次覆盖 `auto_pack`（可选，P2） |

优先级：CLI > 环境 > 用户级 > 系统级 > 内置默认。`--no-config` 时只剩「环境 + 内置默认」。

### 3.8 日志（C-08）

- `log_level` 控制 `util::error/warn/info` 的 stderr 过滤（`error` 始终输出；`off` 仅保留 `fatal`）。
- 若 `[base_dir].logs` 已配置且 `log_level != off`，追加写 `<logs>/ezmk.log`（UTF-8、行缓冲、进程内 mutex；不做轮转，文档注明）。
- 日志写入失败 → 一次性警告后关闭文件日志，不影响命令本身。
- 不改变现有 stderr 文案格式；仅增加级别过滤与可选文件副本。

### 3.9 校验与安全（C-06）

- `config.toml` 解析用项目已依赖的 `toml++`；未知键 / 类型错误 / 非法 `log_level` / 非法 `color_mode` / `--config` 与 `--no-config` 冲突 → 带文件与键名的错误，退出非零。
- 系统级配置由管理员维护，视为可信；用户级配置同用户可信。两者都**不允许**指定 `Project` 作用域路径。
- 路径覆盖只影响对应作用域；加载阶段不创建目录、不写文件。
- 不读取 `config.toml` 之外的任何配置；不引入网络行为。

### 3.10 已知坑位与对策

| # | 坑 | 对策 |
|---|-----|------|
| 1 | 加载时机早于 CLI 解析，但 `--config`/`--no-config` 本身是 CLI 选项 | 在 `cli::parse()` 前做一次轻量预扫描（与 `--color` 现有做法一致），随后正式解析时复用结果 |
| 2 | `pkg_install_dir` / `repo_dir` 被大量单测直接调用 | 访问器在未加载时返回内置默认；提供测试 reset |
| 3 | 相对路径的基准是 CWD 还是配置文件目录容易写错 | 统一「相对 config.toml 所在目录」，并加单测 |
| 4 | 用户级 `installed_packages` 误覆盖 Global 作用域 → 提权面 | 按作用域绑定，不做跨作用域覆盖 |
| 5 | `auto_pack` 在构建流程中递归调用 pack / 构建 | 只在顶层构建成功后调用一次；pack 失败仅警告，不改变构建退出码；加防重入标志 |
| 6 | `color_mode` 的 256/truecolor 承诺超出当前实现 | 本版只记录偏好，文档明确「当前输出仍为 16 色」 |
| 7 | 日志文件在只读目录 / 无权限 | 一次性警告后降级为仅 stderr |
| 8 | 未知键 fail-fast 可能破坏「先写新配置、后升级 ezmk」 | 与 1.4.11 Q4-29 一致；CHANGES 写明；`--no-config` 可绕过 |

## 4 执行步骤（每阶段一个 commit，阶段间全量回归）

## 5 兼容性

| 变更 | 影响 | 说明 |
|------|------|------|
| 未创建任何 `config.toml` | **零变化** | 所有默认值与 1.4.11 一致 |
| 新增环境变量 | 纯新增 | 不设置时行为不变 |
| `[settings]` 默认值 | 零变化 | 语言 auto / 颜色 auto / git 三开关开 / initial commit 关 / auto_pack 关 / agent_md 关 / log info |
| `[base_dir]` 路径覆盖 | 纯 opt-in | 只在配置后改变对应作用域路径 |
| `--color` 新别名 | 向后兼容 | `auto/always/never` 语义不变；新增 `off/on/16colors/256colors/truecolor` |
| `--config` / `--no-config` / `--lang` | 纯新增 | 不传时行为不变 |
| 未知键 fail-fast | **行为收紧** | 写错键名会报错；`--no-config` 可绕过 |
| `auto_pack` | 纯 opt-in | 默认关；开启后构建成功可能多一次 pack |
| `gen_agent_md` | 纯 opt-in | 默认关；开启后 `project new` 多一个 `AGENTS.md` |
| 日志文件 | 纯 opt-in | 未配置 `logs` 或不设 `log_level` 时不写文件 |
| 公共 API | **无破坏性变更** | 仅新增结构与访问器；既有 `parse_config` 语义不变 |

## 6 跨版本关注点

- **与 1.4.11 的关系**：1.4.11 收口了配置解析的 fail-fast（Q4-29）与退出码；本版直接复用其「已知键类型错误必须报错」的契约，避免两级配置再次出现静默失效。
- **与 2.0.0 解耦**：本版不新增弃用面，也不移除任何既有字段；2.0.0 移除清单见 [2.0.x/REMOVALS.md](../2.0.x/REMOVALS.md)。
- **后续版本**：`ezmk config get/set`、颜色深度引擎（真正 16/256/truecolor 调色板）、日志轮转、平台级默认配置打包（发行版 `/etc/ezmk/config.toml`）均不在本版，作为独立版本评估。
- **稳定性承诺**：`EZMK_GLOBAL_CONFIG_DIR`、`EZMK_USER_CONFIG_DIR`、`config.toml` 的 `[base_dir]`/`[settings]` 键名一经发布即视为公共契约；新增键只能追加，不重命名。
- **回归基线**：立项基线 = 1.4.11 发布态 **1169 用例 / 6788 断言 / 4 跳过 / 0 失败**；每阶段全量回归后再进下一阶段；新增用例只增不减。
