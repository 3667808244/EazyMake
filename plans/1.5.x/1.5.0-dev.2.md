# EazyMake 1.5.0-dev.2 — 路径接入（`[base_dir]`）

> **状态：📋 计划完成（2026-10-24，待实现）** —— 1.5.0 的第 2 个 dev 子版本。系列索引见 [README.md](README.md)。
>
> **依赖**：dev.1（`RuntimeConfig` / 加载器）。**后续**：dev.4 消费 `logs` 目录。
>
> **范围边界**：只把 `[base_dir]` 接到包安装 / 仓库缓存 / example 默认输出；**不接** `[settings]` 行为（dev.3），**不写**日志（dev.4）。未配置时逐字节不变。
>
> **⛔ 门槛**：同 dev.1；新增路径必须有单测，且「未配置 = 旧路径」逐字节相等。

## 1 背景

dev.1 已能读到 `[base_dir]`，但 `pkg_install_dir` / `repo_dir` / `example` 仍用硬编码路径。本版把配置变成实际生效的路径，同时保持「不配置就完全不变」。

## 2 目标

| # | 目标 | 优先级 |
|---|------|--------|
| C-04a | Global / User 作用域的 `installed_packages` 生效 | P0 |

## 3 详细设计

### 3.1 作用域绑定

| 配置来源 | 影响的 scope | 键 |
|----------|--------------|-----|
| 系统级 `config.toml` | `cli::Scope::Global` | `installed_packages` / `repo_cache` |
| 用户级 `config.toml` | `cli::Scope::User` | `installed_packages` / `repo_cache` |
| 用户级覆盖系统级 | 单值 | `examples` / `logs` |

- **禁止**用户级 `installed_packages` 改 Global 作用域（提权面）。
- Project 作用域不受 `[base_dir]` 影响（仍在 `<root>/.ezmk/...`）。

### 3.2 路径解析

- 绝对路径原样；相对路径相对**该 config.toml 所在目录**。
- 支持 `~` / `~/` / `~\`（复用 `[install].prefix` 规则）。
- 含 NUL / 无法规范化 → 配置错误。
- 加载阶段不创建目录。

### 3.3 接入点

- `pkg::pkg_install_dir(scope)`：Global/User 优先读覆盖，否则旧默认。
- `repo::repo_dir(scope)`：同上。
- `example::create_example`：输出目录为空时用 `examples`（仍允许显式目录）。
- `logs`：仅存入 `RuntimeConfig`，供 dev.4。

### 3.4 已知坑位

| # | 坑 | 对策 |
|---|-----|------|
| 1 | 相对路径基准写成 CWD | 统一相对配置文件目录 + 单测 |
| 2 | 旧路径与覆盖路径混合导致缓存错位 | 未配置时走完全相同的旧分支 |
| 3 | `~` 展开只处理 `~/` | 复用既有 `[install].prefix` 展开 |

## 6 跨版本关注点

- dev.4 的日志目录直接读本版解析好的 `logs`；不要在 `util` 里二次解析。
- 若后续新增作用域，必须先在 `BaseDirConfig` 扩展，不要在调用点特判。
