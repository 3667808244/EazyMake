## 1 背景

dev.1 ~ dev.7 已把「用户级 / 全局级 config.toml」完整落地：两级加载与合并、路径与工具定位、project new 默认、日志、构建/测试/监视/打包/包管理运行默认，以及拆分后的项目/用户/全局配置文档；dev.7 全量零回归并完成 dev 收口。

但 1.5.0 交付的是**公共配置契约**，发布前仍有三类未收口：

1. **用户触达缺口**：`ezmk --help` 的 Common options 没有 1.5.0 新增的 `--config` / `--no-config` / `--lang`，`--color` 说明也停留在旧值；README 只有一句文档链接，zsh 补全未覆盖新开关。
2. **契约与实现漂移**：`[settings].default_jobs` 未作用于 workspace；`installed_packages` 未作用于 utils 发现与 lockfile 校验；`[project].build_dir` 类型错误被静默忽略；绝对 `build_dir` 的共享对象目录风险仍未裁定；文档把 `[compile].jobs` / `[test].timeout` 的默认值写成不可写的 -1。
3. **发布级缺陷**：Windows watch 退出 UAF、同 stem 对象碰撞、`src_dirs=["."]` 打包漏源、Lua 协程绕过指令预算、Windows 命令引号、`--locked` 本地目录绕过、包暂存残留、import 注释注入等；另有 dev.6 遗留 R-13 / R-17 / R-12。

本次全量审查覆盖 src/ 25 个手写模块（约 2.7 万行）、公共头、scripts、man、docs、tutorial、skills、CI 与发布资产，共 47 项（P1 4 / P2 23 / P3 20）。pre.1 的职责是**逐项裁定、修复发布级缺陷、补齐文档与闸门**，不是继续堆功能。

## 3 详细设计

### 3.1 用户触达

- **`--help` Common options**：新增三行，分别说明 `--config <file>`（替换用户级、缺失致命）、`--no-config`（跳过两级）、`--lang <tag>`（覆盖 `EZMK_LANG` 与 settings）；`--color` 说明改为完整别名（always/enable/on/16colors/256colors/truecolor、auto/default、never/disable/off）。
- **i18n 键**：新增 `help_flag_config` / `help_flag_no_config` / `help_flag_lang`，更新 `help_flag_color`；同步 locale/en.json、locale/zh.json（zh-TW 继承 zh，不单独加）。
- **README / README_ZH**：Configuration 节增加 8~12 行两级配置速览（路径、优先级、两个环境变量、三个 CLI 开关）；Commands at a glance 增加全局选项一行；不复制完整 schema。
- **zsh 补全**：`res/ezmk.zsh` 增加 `--config`（文件补全）、`--no-config`、`--lang`（en/zh/zh-TW）、`--color`（新值）；顺带核对 workspace / export / import / cc 子命令是否缺失（缺失则补齐，低风险只增）。
- **man**：`man/ezmk.1` 已有全局选项，逐行与帮助文案核对；`check_man_sync.py` 必须继续通过。
- **畸形配置与 help/version**：不改变 fail-fast 设计；在 FAQ 和 user/global config 文档写明「配置损坏时可用 `--no-config` 查看帮助/版本」。若用户另行裁定改为跳过配置，再改代码。

**具体修正（审查证据见 audit）**：

- B-01：文档与代码同步裁定绝对 `[settings].build_dir`；`[project].build_dir` 若允许绝对路径，文档标注共享目录风险。
- B-04：`[watch].debounce_ms = 0` 的真实语义是「回退 `[settings].watch_debounce_ms`」，不是固定 300。
- B-05：`[compile].jobs` / `[test].timeout` 的 -1 是内部哨兵，**不可显式写入**；文档改为「未设置时继承」并给合法示例。
- B-07：`watch_ignore` / `pack_exclude` 是**追加叠加**，项目不能覆盖或清空全局条目；表格与示例改写。
- B-11 / D-10：畸形配置阻断 help/version 的逃生口；无效 `--lang` 的真实行为是「忽略后继续按 `EZMK_LANG` / settings / 系统回退」，不再写「回退英文」。
- D-07：docs/zh/utils.md 删掉「仅匹配第一个 token」旧描述，与同文件 314 行、英文版对齐。
- D-11：修正 ezmk-lua man 的 usage/退出码矛盾；D-12 经 roff 渲染复核为误报（`\e` 就是反斜杠），不改。
- Catch2 超时：`[settings].test_timeout` 默认 30 只对内置 ezmk 框架生效；Catch2 在未显式配置时**不超时**（dev.6 R-03 的决定）；在 user/global/project 文档与 CHANGES 写清。
- 编辑器：`[settings].editor` 的整体引号语义使 `"code -w"` 不可用；列为已知限制，不改行为。

**新增文档闸门**：`scripts/check_config_docs.py`（或扩展 check_man_sync.py）——从 `src/config.cpp` 提取 `is_known_settings_key` / `[watch]/[pack]/[test]/[project]` 键，检查 user_config / global_config / project_config / man 中每个键都有文档条目，且文档中的 `settings.*` 键都存在于 parser；接入 CI。当前 29 个 settings 键已全部出现在 user_config + man5，脚本用于防回归。

### 3.3 i18n

- 基线：`i18n_keys.def` / en.json / zh.json 均 430 键；zh-TW 继承 zh。
- 本版新增 6 键（3 个帮助 + 2 个写入失败 + 1 个 locked 来源）、更新 1 键（`help_flag_color`），预计 **436 键**；三处同步后跑 `check_i18n.py`。
- **加载期诊断英文策略**：配置加载早于 `i18n::init()`（`--lang` / settings.natural_language 本身依赖加载结果），因此 `config.toml` 的解析/校验错误保持英文；在 user_config / global_config 的「注意」节与 CHANGES「已知限制」明确写出，不在 pre.1 引入加载期 i18n 重构。
- `--lang` 未知值：维持「忽略并继续回退」的实现，文档按 D-10 改写；补一条测试锁定优先级（`--lang` > `EZMK_LANG` > settings > 系统）。
- CI：ubuntu job 在 build 前增加 `python3 scripts/check_i18n.py`（当前 CI 未跑该脚本）。
