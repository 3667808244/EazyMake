> **目标**：当用户级与全局级配置都不存在、且没有显式 `--config` / `--no-config` 时，在用户配置目录生成一份**注释模板**，让用户首次运行后能直接看到可配置项；不改变任何默认行为。

## 1 背景

当前无配置运行时，EazyMake 使用内置默认值，用户不知道有 `config.toml`、文件应放在哪里、有哪些键。每次都要查文档再手写，首次体验断裂。

自动生成默认配置可以解决发现问题，但必须避免三个风险：

1. 自动写入用户目录属于副作用，不能覆盖已有文件；
2. 写入默认值会「冻结」当前默认，未来升级不再继承新默认；
3. 写失败不能阻断正常命令。

因此本版只生成**注释模板**，不激活任何键。

## 3 详细设计

### 3.1 触发条件

在 `load_runtime_config()` 完成路径解析、但尚未发布 `g_runtime_config` 时判断：

- 存在全局配置（`default_global_config_dir()/config.toml`）→ 不生成；
- 存在用户配置（显式 `--config` 或 `default_user_config_dir()/config.toml`）→ 不生成；
- `--no-config` → 不生成；
- 显式 `--config <file>` 且文件不存在 → 保持现有致命错误，**不**自动创建，避免拼写错误被掩盖；
- 以上都不满足（真正无配置）→ 生成用户级模板。

只在「需要加载配置」的命令路径上触发；`--help` / `--version` 是否触发按现有 `load_runtime_config` 调用图决定，本版不新增入口。

### 3.2 生成位置

- 用户级：`default_user_config_dir() / "config.toml"`
  - Windows：`%USERPROFILE%\.ezmk\config\config.toml`
  - Linux/macOS：`$XDG_CONFIG_HOME/ezmk/config.toml` 或 `~/.config/ezmk/config.toml`
- 不写全局目录（通常需要管理员权限）。
- 父目录不存在则创建；已存在但不可写 → 告警并继续。
- 权限：POSIX 创建时尽量 `0600`（文件可能含代理/路径），Windows 用默认 ACL。
- 原子写：同目录临时文件 + `rename`；失败清理临时文件。

### 3.3 模板内容

模板为 UTF-8、LF，全部键注释，只有说明和示例：

~~~toml
# EazyMake user configuration
# Auto-generated on first run. Uncomment a key to override a built-in default.
# Docs: https://github.com/3667808244/EazyMake/blob/main/docs/en/user_config.md

[settings]
# natural_language = "auto"
# color_mode = "auto"
# log_level = "info"
# compiler_output = "error"
# linker_output = "error"
# cxx = ""
# cc = ""
# linker = ""
# use_cache = true
# network_timeout = 0
# retries = 0
# proxy = ""
# install_prefix = ""
# default_jobs = 0
# test_timeout = 30
# watch_debounce_ms = 300
# pack_format = "tar.gz"
# auto_install_deps = true
# auto_pack = false

[base_dir]
# installed_packages = "~/.local/ezmk/pkg"
# repo_cache = "~/.local/ezmk/repo"
# examples = "~/.local/ezmk/examples"
# logs = "~/.local/ezmk/logs"
~~~

约束：

- 不写活动键（所有行以 `#` 开头），因此生成前后 `RuntimeConfig` 完全一致。
- 不写机器名、用户名、绝对路径、时间戳；同一版本输出确定。
- 不写代理凭据；`proxy` 仅注释示例。
- 模板随版本演进只追加新键注释，不删除旧行；生成逻辑不读回模板。

### 3.4 诊断与日志

- 生成成功：`info` 一次，提示文件路径与「可编辑后重新运行」；不重复刷屏。
- 已存在：静默跳过。
- 创建目录/写文件失败：`warn`（含路径与错误），命令继续。
- `log_level=off` 时不输出提示，但生成仍可发生；是否生成不受日志级别控制。

### 3.5 与现有配置语义

- 生成后下一次运行会读取这个模板；因为所有键都注释，解析结果仍是内置默认。
- 用户手动取消注释即生效；不引入新的合并层。
- 不改变 `--config` / `--no-config` / `EZMK_*_CONFIG_DIR` 的现有优先级。
- 不改变配置解析错误行为：模板损坏仍按现有 TOML 错误处理。

### 3.6 测试

- `test_config.cpp`（临时 `EZMK_USER_CONFIG_DIR` / `EZMK_GLOBAL_CONFIG_DIR`）：
  - 无配置 → 生成 `config.toml`，内容全部注释，能够被 TOML 解析；
  - 已存在用户配置 → 不覆盖、mtime/内容不变；
  - 全局配置存在 → 不生成用户文件；
  - `--no-config` → 不生成；
  - 显式 `--config missing` → 仍报错、不生成；
  - 只读目录/父目录不可创建 → 命令仍成功（或按现有语义）并有 warning；
  - 生成前/后 `runtime_config().settings` 关键字段一致。
- 集成：CLI 首次运行 → 文件出现；第二次运行 → 内容不变；删除后再次运行 → 重新生成。
- 文档闸门 / 全量 `test-all` / CI。
