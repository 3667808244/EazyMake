# EazyMake 1.5.0-dev.9 — 编译器与连接器输出策略

> **状态：✅ 实现完成（2026-11-07），待 pre.2 发布复核** —— 依赖 dev.8。
>
> **回归**：单元 **1105 / 6277 / 4 跳过 / 0 失败**；全量 `test-all`（`EZMK_TEST_OFFLINE=1`）**1226 / 7058 / 8 跳过 / 0 失败**。
>
> **目标**：新增两个配置项 —— `[settings].compiler_output` 与 `[settings].linker_output` —— 分别控制编译成功、链接成功时诊断的显示方式：总是输出 / 有警告时输出 / 有错误时输出。

## 1 背景

当前 `compile_one_source()` 只在编译失败时把 stderr/stdout 放进 `error_msg`；成功编译的警告被丢弃。`execute_link()` 同样只在链接失败时输出 stderr/stdout；成功链接的警告也被丢弃。用户无法在正常构建中看到 `-Wall` / 链接器警告，也无法选择只看警告或全部诊断。

## 2 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | 新增 `[settings].compiler_output`（string enum，默认 `error`） | P0 |
| 2 | 新增 `[settings].linker_output`（string enum，默认 `error`） | P0 |
| 3 | always / warning / error 三种策略分别覆盖成功编译与成功链接；失败诊断始终显示 | P0 |
| 4 | 并行与串行编译路径都生效；缓存命中不产生编译器输出 | P0 |
| 5 | 支持 GCC/Clang `warning:`、MSVC `warning C` / `warning LNK` 检测 | P0 |
| 6 | 配置/文档/测试/CHANGES/索引 | P0 |

## 3 详细设计

### 3.1 配置语义

两个键共用同一套枚举，但互相独立：

| 值 | 行为 |
|----|------|
| `error`（默认） | 成功阶段不输出诊断；失败时输出完整 stderr/stdout（保持旧行为） |
| `warning` | 成功阶段仅在诊断包含 warning 时输出；失败时始终输出 |
| `always` | 成功阶段输出全部 stderr/stdout；失败时始终输出 |

- `compiler_output` 只控制编译阶段（`compile_one_source` / `compile_sources`）。
- `linker_output` 只控制链接步骤（`execute_link()`，含静态库归档路径）。
- 类型：string；非法值加载期 fail-fast。
- 作用域：全局/用户配置；不新增项目级键（如需项目级，后续单独立项）。
- 与 `log_level` 独立：模式为 `always` 时即使 `log_level=off` 也显示诊断。

### 3.2 编译数据流

- `cache::SingleCompileResult` 增加 `compiler_output`（stderr 后接 stdout）；`Cache::CompileResult` 增加成功编译的 `compiler_outputs`。
- `compile_one_source()` 在成功与失败时都填 `compiler_output`；失败仍走 `error_msg` 的既有路径。
- `compile_sources()`（串行）收集成功输出；`build.cpp` 在串行与并行合并后按 `compiler_output` 策略调用 `util::raw_diagnostics()`。
- 并行路径在 futures 全部 join 后按结果顺序输出，避免多线程交错。

### 3.3 链接数据流

- `execute_link()` 已捕获 `res.out` / `res.err`；成功时按 `linker_output` 决定是否调用 `util::raw_diagnostics()`，失败时保持现有错误输出。
- 输出发生在命令成功之后、`build_success` 之前；不改变退出码、原子重命名或产物。
- 静态库归档也经过 `execute_link()`，因此使用同一策略；这是有意的，因为归档器警告同样属于构建诊断。

### 3.4 warning 检测

- GCC/Clang：诊断包含 `warning:`（大小写不敏感）。
- MSVC：诊断包含 `warning C` 或 `warning LNK`（大小写不敏感）。
- 仅用于 `warning` 模式的显示判断；不改变编译/链接结果或缓存。

### 3.5 输出实现

- 新增 `util::raw_diagnostics()`：原样写 stderr，不加 `[ezmk]` 前缀；保证末尾换行；不受 `log_level` 过滤。
- 编译与链接共用该函数；调用方负责选择模式与 warning 判定。
- 失败路径继续使用现有 `util::error` / `error_msg`，避免重复输出。

### 3.6 测试

- `test_config.cpp`：
  - `compiler_output` / `linker_output` 缺省均为 `error`；
  - always/warning/error 合法；未知值报错；
  - global→user 覆盖互相独立（一个键覆盖不影响另一个）。
- `test_cache.cpp`：GCC/MSVC warning 标记检测；error/空输出不误判。
- 链接辅助测试：构造带 `warning LNK` / `ld: warning:` 的字符串，验证 warning 判定。
- 集成/手工：
  - 带 `#warning` 的源文件分别用三种 `compiler_output` 构建；
  - 构造链接器警告（或使用测试桩）验证三种 `linker_output`；
  - 检查失败时诊断不丢失。
- 闸门：config docs / man / docs / i18n / 全量 test-all / CI。
