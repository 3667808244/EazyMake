# EazyMake 1.5.0-dev.9 — 编译器输出策略

> **状态：📝 待执行（2026-11-07 立项）** —— 依赖 dev.8；本文件只定义计划，尚未修改代码。完成后与 dev.8 一起进入 pre.2。
>
> **目标**：新增 `[settings].compiler_output`，控制成功编译时编译器诊断的显示方式：总是输出 / 有警告时输出 / 有错误时输出。

## 1 背景

当前 `compile_one_source()` 只在编译失败时把 stderr/stdout 放进 `error_msg`；成功编译的警告被丢弃。用户无法在正常构建中看到 `-Wall` 警告，也无法选择只看警告或全部诊断信息。

## 2 目标

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | 新增 `[settings].compiler_output`（string enum，默认 `error`） | P0 |
| 2 | always / warning / error 三种策略覆盖成功编译；失败诊断始终显示 | P0 |
| 3 | 并行与串行编译路径都生效；缓存命中不产生编译器输出 | P0 |
| 4 | 支持 GCC/Clang `warning:` 与 MSVC `warning C` 检测 | P0 |
| 5 | 配置/文档/测试/CHANGES/索引 | P0 |

## 3 详细设计

### 3.1 配置语义

`[settings].compiler_output`：

| 值 | 行为 |
|----|------|
| `error`（默认） | 成功编译不输出诊断；失败时输出完整 stderr/stdout（保持旧行为） |
| `warning` | 成功编译仅在诊断包含 warning 时输出；失败时始终输出 |
| `always` | 成功编译输出全部 stderr/stdout；失败时始终输出 |

- 类型：string；非法值加载期 fail-fast。
- 作用域：全局/用户配置；不新增项目级键（如需项目级，后续单独立项）。
- 不影响链接命令：链接失败已有固定错误输出；本键只管编译阶段。
- 与 `log_level` 独立：`compiler_output=always` 时即使 `log_level=off` 也显示编译器诊断。

### 3.2 数据流

- `cache::SingleCompileResult` 增加 `compiler_output`（stderr 后接 stdout）；`Cache::CompileResult` 增加成功编译的 `compiler_outputs`。
- `compile_one_source()` 在成功与失败时都填 `compiler_output`；失败仍走 `error_msg` 的既有路径。
- `compile_sources()`（串行）收集成功输出；`build.cpp` 在串行与并行合并后按策略调用 `util::compiler_output()`。
- `util::compiler_output()` 原样写 stderr，不加 `[ezmk]` 前缀；保证末尾换行；不受 log_level 过滤。
- 并行路径在 futures 全部 join 后按结果顺序输出，避免多线程交错。

### 3.3 warning 检测

- GCC/Clang：诊断包含 `warning:`（大小写不敏感）。
- MSVC：诊断包含 `warning C`（大小写不敏感）。
- 仅用于 `compiler_output=warning` 的显示判断；不改变编译结果或缓存。

### 3.4 测试

- `test_config.cpp`：默认 error、always/warning 合法、未知值报错、global→user 覆盖。
- `test_cache.cpp`：GCC/MSVC warning 标记检测；error/空输出不误判。
- 集成/手工：带 `#warning` 的源文件分别用三种策略构建，检查 stdout/stderr。
- 闸门：config docs / man / docs / i18n / 全量 test-all / CI。
