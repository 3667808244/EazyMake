## 1 背景

1.5.0-dev.1 ~ dev.9 已覆盖语言/颜色/日志、项目创建、构建并行度、测试、watch、pack、包管理、agent skills 与诊断输出。但仍有一批高频行为只能靠环境变量、CLI 临时参数或直接写死：

- 编译器路径只认 `CXX` / `CC` 环境变量；
- 关闭缓存只有 `--disable-cache`；
- 网络下载/git clone 没有统一超时、重试、代理；
- 安装前缀只能项目级配置，不能设置用户默认。

本版把这些变成 `[settings]` 的 opt-in/默认兼容配置，并明确优先级。

## 3 详细设计

### 3.1 编译器与链接器路径

新增三个 string 键，默认均为空（自动探测）：

| 键 | 作用 | 为空时 |
|----|------|--------|
| `cxx` | C++ 编译器 | 按现有 `CXX` / 自动探测 |
| `cc` | C 编译器 | 按现有 `CC` / 自动探测 |
| `linker` | 链接驱动 | 使用 `cxx`（GCC/Clang 默认行为） |

优先级（从高到低）：

1. 环境变量 `CXX` / `CC`（保持现有逃生口；`linker` 无对应环境变量）
2. `[settings].cxx` / `.cc` / `.linker`
3. 自动探测（现有 `detect_compiler` / 平台工具链）

规则：

- 空串 = 未配置，不是「空路径」；不覆盖环境变量/自动探测。
- 支持绝对路径、`~` / `~/` 展开；相对路径按**项目根**解析（与构建命令的 CWD 语义一致）。
- 含 NUL 的路径加载期拒绝；路径不存在或不可执行在**使用点** fatal，并报出键名与实际路径，不静默回退。
- `linker` 只用于 GCC/Clang 链接驱动；MSVC 仍使用工具链检测到的 `link.exe`（若显式 `linker` 指向 MSVC 驱动，后续版本再支持）。
- `cxx` 变化必须使对象缓存失效：现有 compiler version 只比较文件名，本版把**实际路径 + 版本**纳入缓存签名。
- 不改 `[project]`：工具路径是用户/全局默认，项目不应硬编码本机路径。

### 3.2 缓存开关

新增 `[settings].use_cache`（bool，默认 `true`）：

- `true`：保持现有缓存行为。
- `false`：等价于每次构建传 `--disable-cache` —— 不读缓存、不写缓存、不更新 `record.json`；测试编译缓存同样关闭。
- CLI `--disable-cache` 仍然最高：即使 `use_cache=true` 也关闭本次缓存。
- 不新增 `cache_dir`（本版不做）；缓存目录继续为 `<project>/.ezmk/cache`。

### 3.3 网络策略

新增三个键：

| 键 | 类型/默认 | 语义 |
|----|-----------|------|
| `network_timeout` | int，`0` | 单次网络操作超时秒数；`0` = 不超时（保持现状）；建议范围 0..3600 |
| `retries` | int，`0` | 首次失败后的重试次数；0 = 不重试；范围 0..10 |
| `proxy` | string，空 | HTTP/HTTPS 代理 URL；空 = 继承环境变量/系统设置 |

适用范围：

- `pkg install` 的 HTTP(S) 下载与 git clone/pull；
- `repo update` 的 git pull；
- 不改变本地文件/包安装路径；不代理 Lua 脚本（Lua 无网络 API）。

行为：

- `network_timeout` 传给 `util::run_command` 的 `timeout_sec`；HTTP 下载在 WinHTTP/curl 路径上设置连接/接收超时。
- `retries` 只重试网络/临时失败（超时、连接失败、5xx）；4xx、校验失败、认证失败不重试（避免掩盖配置错误）。
- 重试输出警告（第 N/M 次），但不打印代理凭据；URL 中的 `user:pass@` 在日志中脱敏。
- `proxy` 优先级：环境变量 `HTTPS_PROXY` / `HTTP_PROXY` > `[settings].proxy` > 系统默认。配置的代理注入 git 子进程环境；Windows WinHTTP 下载使用命名代理。
- 代理 URL 仅支持 `http://` / `https://`；非法 scheme 加载期报错。

### 3.4 安装前缀

新增 `[settings].install_prefix`（string，默认空）：

优先级（从高到低）：

1. CLI `ezmk install --prefix <dir>`
2. 项目 `[install].prefix`
3. `[settings].install_prefix`
4. 平台默认（Unix `~/.local`，Windows `%LOCALAPPDATA%\ezmk`）

规则：

- 空串 = 未配置，回落到下一层。
- 支持 `~` / `~/`；相对路径按项目根解析；NUL 拒绝。
- 不改变 `[install].bindir` / `libdir` / `includedir` 的相对结构。

### 3.6 测试

- `test_config.cpp`：默认值；每个键合法/非法类型；范围（timeout/retries）；代理 scheme；global→user 覆盖。
