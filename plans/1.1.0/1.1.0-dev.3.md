# EazyMake 1.1.0-dev.3 — 常见编程 Agent Skills 支持

---

## 1 背景

AI 编程助手（Claude Code、GitHub Copilot、Cursor 等）在参与项目开发时，最有效的集成方式是项目本身提供符合 **Agent Skills 开放标准** 的 skill 文件。这些 skill 文件告诉 agent：

- 如何编译项目
- 如何运行测试
- 项目架构和代码组织
- 特有的开发惯例和注意事项

EazyMake 目前已有 `CLAUDE.md`（Claude Code 的通用指令文件），但它是一个"大而全"的单文件——混合了构建命令、架构说明、i18n 机制、包管理、配置系统等所有信息。这种模式存在以下问题：

1. **无法按需加载**：agent 在修改测试文件时不需要知道包管理细节，但 `CLAUDE.md` 会全量注入
2. **不符合 Agent Skills 开放标准**：其他 agent（Copilot、Cursor）有各自的 skill 格式，`CLAUDE.md` 仅对 Claude Code 有效
3. **难以维护**：随着项目增长，`CLAUDE.md` 越来越长（当前 ~160 行），新开发者难以快速定位所需信息
4. **无法触发式加载**：理想情况下 agent 在进入特定目录（如 `test/`）或操作特定文件类型（如 `.def`）时自动加载对应 skill

**解决方案**：将 `CLAUDE.md` 中的通用项目信息拆分为多个符合 Agent Skills 开放标准的 skill 文件，放在 `.claude/skills/` 目录下。每个 skill 聚焦一个领域，agent 按需加载。

## 3 详细设计

### 3.1 Skill 文件格式（Agent Skills 开放标准）

每个 skill 是一个 Markdown 文件，放在 `.claude/skills/` 目录下。文件名即 skill 名称。

#### 3.1.1 Skill 文件结构

```markdown
---
name: ezmk-build
description: How to compile EazyMake from source — build.sh, manual g++ commands, and platform differences.
trigger:
  - glob: build.sh
  - glob: src/**/*.cpp
  - glob: include/**/*.hpp
---

# EazyMake Build

## Quick build

```bash
bash build.sh
```

This generates locale data (`scripts/embed_locale.py`) + version header (`include/ezmk/logo.gen.h` + `include/ezmk/version.gen.h`), then compiles all sources.

## Manual build

### Windows (MSYS2)
```bash
g++ -std=c++17 src/*.cpp src/vendor/*.c src/vendor/lua/*.c \
    -I include/ -I include/vendor/ -I include/vendor/lua/ \
    -DLUA_COMPAT_5_3 -o build/ezmk -lwinhttp -static
```

### Linux
```bash
g++ -std=c++17 src/*.cpp src/vendor/*.c src/vendor/lua/*.c \
    -I include/ -I include/vendor/ -I include/vendor/lua/ \
    -DLUA_COMPAT_5_3 -o build/ezmk -static
```

## Build output

- Binary: `build/ezmk` (Linux) / `build/ezmk.exe` (Windows)
- Generated headers: `include/ezmk/version.gen.h`, `include/ezmk/logo.gen.h`
- Generated locale data: `include/ezmk/locale_data.gen.h`

## Key flags

| Flag               | Purpose                          |
| ------------------ | -------------------------------- |
| `-DLUA_COMPAT_5_3` | Lua 5.3 API compatibility        |
| `-lwinhttp`        | Windows HTTP (package downloads) |
| `-static`          | Static linking                   |

```

#### 3.1.2 保留 `CLAUDE.md`

`CLAUDE.md` 作为 **入口文件** 保留，但内容精简为项目一句话概述 + skill 索引。agent 先加载 `CLAUDE.md`，再根据当前任务按需加载对应 skill。

### 3.2 Skill 详细设计

#### 3.2.1 Build Skill（`ezmk-build`）

**触发条件**：agent 读取/修改 `build.sh`、`src/**`、`include/**` 时自动加载。

**内容**：
- 编译命令（`bash build.sh` + 手动 g++ 两条路径）
- 构建产物位置（`build/ezmk`、生成的头文件）
- 关键编译 flag 说明（`-DLUA_COMPAT_5_3`、`-lwinhttp`、`-static`）
- 平台差异（Windows MSYS2 vs Linux）
- 常见编译问题（缺少 MSYS2 包、Lua 版本冲突）

#### 3.2.2 Test Skill（`ezmk-test`）

**触发条件**：agent 读取/修改 `test/**`、`build.sh`（test 目标）时自动加载。

**内容**：
- 测试命令（`bash build.sh test` + 手动 g++ 命令）
- Catch2 v3 框架简介（header-only：`include/vendor/catch2.hpp` + `src/vendor/catch2_impl.cpp`）
- 测试文件组织（`test/test_<module>.cpp`）
- 当前测试基线（538 用例 / ~2440 断言）
- 如何新增测试（文件名约定、`TEST_CASE` 宏、fixtures）
- 集成测试说明（`[integration]` tag，7 个场景）

#### 3.2.3 Codebase Skill（`ezmk-codebase`）

**触发条件**：agent 需要理解项目整体架构时（无特定文件触发，由 agent 自行判断或从 `CLAUDE.md` 索引加载）。

**内容**：
- 目录总览：

```
EazyMake/
├── src/            # 核心源码（.cpp）
│   ├── main.cpp    # 入口 + CLI 分发
│   ├── cli.cpp     # 命令行解析（GNU 风格）
│   ├── build.cpp   # 构建编排（编译→链接→缓存）
│   ├── cache.cpp   # 增量编译缓存（哈希 + record.json）
│   ├── config.cpp  # ezmk.toml 解析
│   ├── pkg.cpp     # 包管理（install/update/list）
│   ├── repo.cpp    # 仓库管理（add/update/clone）
│   ├── toolchain.cpp # 编译器检测（GCC/Clang/MSVC）
│   ├── project.cpp # 项目创建/结构
│   ├── i18n.cpp    # 国际化（X-macro 驱动）
│   ├── lua_api.cpp # Lua C++ API（23 函数 + sandbox）
│   ├── file_watcher.cpp # 文件监控（Watch 模式）
│   ├── crypto.cpp  # SHA-256
│   ├── util.cpp    # 工具函数（路径/进程/颜色）
│   ├── version.cpp # 版本号
│   └── vendor/     # 第三方库（miniz, Catch2, Lua 5.4.7）
├── include/ezmk/   # 公共头文件
├── test/           # Catch2 单元测试
├── docs/en/ + zh/  # 用户文档（双语）
├── plans/          # 版本规划
├── locale/         # 翻译源文件（en.json + zh.json）
├── scripts/        # 辅助脚本（embed_locale.py 等）
└── build.sh        # 一键构建脚本
```

- 关键模块职责（每个模块 2-3 句话）
- 数据流：`CLI → config → build → cache → toolchain`
- 关键设计模式：X-macro（i18n）、RAII、atomic write（temp → rename）
- 不修改哪些文件（`src/vendor/**` 是第三方代码）

#### 3.2.4 i18n Skill（`ezmk-i18n`）

**触发条件**：agent 读取/修改 `include/ezmk/i18n_keys.def`、`locale/*.json`、`src/i18n.cpp` 时自动加载。

**内容**：
- X-macro 机制：`i18n_keys.def` → `I18nKey` 枚举 + `key_name()` 映射
- 添加一个新 key 的步骤：
  1. 在 `i18n_keys.def` 加一行 `X(key_name, "key_name")`
  2. 在 `locale/en.json` 加英文翻译
  3. 在 `locale/zh.json` 加中文翻译
  4. 重建（`bash build.sh` 会自动运行 `scripts/embed_locale.py`）
- Debug 构建的 `audit_missing_keys()` 检查
- `key_name()` 函数的作用和位置

#### 3.2.5 Planning Skill（`ezmk-planning`）

**触发条件**：agent 读取/修改 `plans/**`、`plan.md` 时自动加载。

**内容**：
- `plans/` 目录结构：`0.x.x/`（0.1.6~0.2.6 早期开发版本）、`1.0.0/`（0.9.0~1.0.0 发布准备版本）、`1.1.0/`（1.1.0 系列：dev.1~dev.7 / pre.1~pre.3 / 1.1.0）、`README.md`（索引 + 路线图）、`plan.md`（当前执行计划）
- Plan 文档格式约定（版本号标题 → 背景 → 目标 → 详细设计 → 执行步骤 → 兼容性矩阵 → 跨版本关注点）
- 如何新增版本计划
- 如何更新执行状态

#### 3.2.6 Repo Skill（`ezmk-repo`，P2）

**触发条件**：agent 需要在官方仓库添加/更新包时手动加载。

**内容**：
- 官方仓库结构（`index.toml` + `packages/`）
- 包制作流程（编译 → 打包 → SHA-256 → 更新索引）
- `index.toml` 的 `[[packages]]` 条目格式
- 预编译包 vs 源码包的区别

### 3.3 `CLAUDE.md` 精简

当前 `CLAUDE.md`（~160 行）精简为入口文件（~30 行），核心内容迁移到各 skill 中：

```markdown
# CLAUDE.md

EazyMake is a simple C/C++ build tool (CLI named `ezmk`), based on GCC/g++ (MSYS2 on Windows).

## Skills

This project provides the following skills for AI coding agents. Load the relevant skill for your task:

| Skill    | File                              | When to load                         |
| -------- | --------------------------------- | ------------------------------------ |
| Build    | `.claude/skills/ezmk-build.md`    | Building, modifying src/ or build.sh |
| Test     | `.claude/skills/ezmk-test.md`     | Running/writing tests                |
| Codebase | `.claude/skills/ezmk-codebase.md` | Understanding architecture           |
| i18n     | `.claude/skills/ezmk-i18n.md`     | Modifying translations               |
| Planning | `.claude/skills/ezmk-planning.md` | Working on version plans             |
| Repo     | `.claude/skills/ezmk-repo.md`     | Managing packages in official repo   |

## Quick reference

- Build: `bash build.sh`
- Test: `bash build.sh test`
- See `README.md` for user-facing documentation.
```

### 3.4 与其他 Agent 的兼容性

虽然 Skill 文件放在 `.claude/skills/` 目录（Claude Code 原生格式），但其他 agent 也能受益：

| Agent              | 如何利用                                   | 说明                                                  |
| ------------------ | ------------------------------------------ | ----------------------------------------------------- |
| **Claude Code**    | 原生 skill 加载                            | `.claude/skills/*.md` 按需自动加载                    |
| **GitHub Copilot** | 手动引用 `.github/copilot-instructions.md` | 可生成一份精简版指令文件指向 skill 目录（§3.5）       |
| **Cursor**         | `.cursor/rules/`                           | 可用同样的 Markdown 内容作为 rules（含 `globs` 触发） |
| **Continue**       | `.continuerules`                           | 直接在项目级提供                                      |

#### 3.4.1 可选：Copilot 指令文件（精简桥接）

为 Copilot 生成一个简短的 `.github/copilot-instructions.md`，**不重复** skill 内容，仅指向 `CLAUDE.md` + skill 目录：

```markdown
# EazyMake — Copilot Instructions

This is the EazyMake build tool project. See `CLAUDE.md` for project overview and
`.claude/skills/` for domain-specific development guides.

## Build
Run `bash build.sh` to compile.

## Test
Run `bash build.sh test` to run the Catch2 test suite.

## Key directories
- `src/` — Core implementation
- `include/ezmk/` — Public headers
- `test/` — Unit tests (Catch2)
- `docs/` — User documentation (en + zh)
```

## 6 跨版本关注点

- **依赖**: 无硬依赖。skill 文件反映的是当前代码库状态，与版本无关
- **维护**: 当项目架构发生重大变化时（如新增模块、重构），需同步更新对应 skill
- **与 `CLAUDE.md` 的关系**: `CLAUDE.md` 是入口索引，skill 是领域详情。新增 skill 时在 `CLAUDE.md` 的索引表中加一行
- **与 Agent Skills 开放标准的关系**: 当前 skill 格式遵循 Claude Code 的原生格式。如果未来出现跨 agent 的统一标准，skill 内容可直接迁移（Markdown 正文 + YAML frontmatter 是通用格式）

## 7 EazyMake 用户侧 Agent Skills

### 7.1 背景

§2~§6 的 skill 面向 **EazyMake 自身开发者**。本节面向 **EazyMake 的使用者**——即用 EazyMake 管理自己 C/C++ 项目的开发者。这些用户的 AI 编程助手同样需要知道如何在 EazyMake 项目中工作。

### 7.2 目标

编写一套符合 Agent Skills 开放标准的用户侧 skill 文件，随 EazyMake 分发（或通过 `ezmk project new` 模板生成），覆盖：

| #   | Skill                 | 优先级 | 说明                                              |
| --- | --------------------- | ------ | ------------------------------------------------- |
| 1   | **EazyMake 项目编译** | P0     | 教 agent 如何用 `ezmk project build` 编译用户项目 |
| 2   | **EazyMake 项目测试** | P0     | 教 agent 如何用 `ezmk project test` 运行测试      |
| 3   | **EazyMake 项目配置** | P1     | 教 agent 理解 `ezmk.toml` 结构和配置项含义        |
| 4   | **EazyMake 包管理**   | P2     | 教 agent 如何安装/更新第三方包                    |

### 7.3 分发方式

- **方式一**：`ezmk project new` 创建新项目时自动生成 `.claude/skills/ezmk-user-*.md`
- **方式二**：提供 `ezmk utils skill-gen` 工具，在已有项目中生成/更新 skill 文件

### 7.4 与 §2~§6 的关系

- §2~§6 的 skill 是 EazyMake 仓库自用的（描述 EazyMake 自身的构建/测试/架构）
- §7 的 skill 是给 EazyMake 用户的（描述用户项目的通用 EazyMake 工作流）
- 两者格式相同、标准相同，仅受众不同
